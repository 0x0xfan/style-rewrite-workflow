# daily-plan · 今日选题与分派

用户圣矾：做闲鱼虚拟项目的 B 站 UP 主，非技术人员。说大白话、给选项带推荐、一次只问一件事；**选题表用户点头之前一篇都不写**。

本技能由主会话用：主会话只排表、问用户、派 worker、验收、追加共享文件；稿子全部由 worker 按写稿技能写。

## 0. 账号一览（DECISIONS 2026-09-29）

每天每个账号写一篇存稿（账号约 1–2 天发一期，多出的存着）。横版和竖版是不同账号。

| # | 账号 | skin | orientation | lengthTarget | 字数 | 写法技能 | 选题类型 |
|---|---|---|---|---|---|---|---|
| 1 | 黑黄 横版 | black-yellow-v2 | h | 5min | 1300–1600 | daily-write 长稿 | 产品为主 |
| 2 | 荧光绿 横版 | lime-capsule | h | 5min | 1300–1600 | daily-write 长稿 | 产品为主 |
| 3 | 署名墙 横版 | signature-wall | h | 5min | 1300–1600 | daily-write 长稿 | 产品为主 |
| 4 | 对账台 横版 | ledger-desk | h | 5min | 1300–1600 | daily-write 长稿 | 产品为主 |
| 5 | 黑黄 竖版 | black-yellow-v2 | v | 1-2min | 300–600 | short-video | 产品或知识 |
| 6 | 荧光绿 竖版 | lime-capsule | v | 1-2min | 300–600 | short-video | 产品或知识 |
| 7 | 署名墙 竖版 | signature-wall | v | 1-2min | 300–600 | short-video | 产品或知识 |
| 8 | 对账台 竖版 | ledger-desk | v | 1-2min | 300–600 | short-video | 产品或知识 |

真人出镜是用户自己对着镜头录，不出片，不需要画面素材对照（不出 `.素材.md`）。

## 1. 读什么（每次排表都读）

1. `docs/每日/账号选题台账.md` —— 每个账号用过哪些选题；末尾「未分配」是新节奏之前交的稿（不算任何账号用过）；「选题池」一节是四个来源。
2. 用户今天有没有发选题卡 / 点名要写的期号 —— 有就优先排进去。
3. 选题池（台账「选题池」一节）：SRT 各期（`docs/批量出稿-工单模板-20260910.md` 第六节总表）、素材库 `D:\项目仓库\remotion视频制作\public\ips\xianyu-fanshen\assets\*\topic.json`（只读，看 `name`/`slug`/`status`/`keywords`/`shotRequests`）、闲鱼经验库 `docs/闲鱼经验库/总表.md` 和真人语料包「可用」堆（知识题）。
4. NAS `Z:\素材生成库\ai文案\待审文案\` 和 `已用\` 的选题文件夹名 —— 看这个选题以前写过没有（写过不违规，但要告诉写稿 worker 去看旧稿、换开头和讲法）。

## 2. 排「今日选题表」（12 行）

**两条硬规矩（只有这两条）：**
1. **同一账号不重复**：这一行的选题，在台账这个账号那一节里没出现过。
2. **同一天各篇选题不同**：12 行的选题两两不同（同一个品的横版和竖版也不行，当天只能出现一次）。

**排的时候再照顾这几点（不是硬规矩，做不到就在表下说一句）：**
- 横版 4 个账号排产品题（SRT / 素材库 / 选题卡）；竖版、聊天记录、真人出镜可以排知识题。
- 不同账号之间尽量不撞题（DECISIONS：「皮肤与皮肤之间能做到不重复，那是最好的」）：优先挑所有账号都没用过的题，其次挑别的账号用过但本账号没用过的。
- 产品题要有钱数来源：SRT 里用户亲口说过的数，或选题卡上写的数；都没有的题写进表但在「备注」标"缺钱数，要用户补"，或者换题。
- 短视频（竖版四套 + 真人出镜）前两句要有"闲鱼"和一个闲鱼数据（`docs/短视频规格.md`）：排知识题时想好用哪个闲鱼数据（素材库截图 / 以前实搜的截图）；聊天记录讲经验的稿不要求数据（chat-record 第 4 节）。
- 素材库里用户放了图和关键词的品，优先排给横版（素材齐，出片省事）。
- 同一选题今天之前已经写过很多篇的，往后放。

**表的格式（交给用户看的就是这张）：**

| # | 账号 | 选题 | 类型（产品/知识） | 来源（SRT 第 N 期 / 选题卡 / 素材库 slug / 经验库编号） | 该账号用过吗 | 别的账号用过吗 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 黑黄 横版 | …… | 产品 | SRT 第 47 期 | 没用过 | 没有 | |
| … | | | | | | | |
| 12 | 真人出镜 3 | …… | 知识 | 经验库 E123 | 没用过 | 竖版对账台 3 天前用过 | |

- 「该账号用过吗」一列 12 行都必须是"没用过"，有一行不是就重排。
- 自查一遍"12 个选题两两不同"，在表下写一句"已核对：12 个选题各不相同"。
- 表下最多三行说明：今天为什么这么排（比如用户发了两张选题卡已排进 1、2 行）、哪几行缺钱数、哪几行以前写过同题旧稿。

## 3. 交用户确认（唯一的门）

把表发给用户，问一句："今天这 12 篇按这张表写，可以吗？想换哪行直接说。"
- 用户改了哪行，以改的为准，改完再核一遍两条硬规矩。
- 用户点头之前：不派 worker、不去闲鱼搜、不写稿。
- **横版长稿还有 daily-write 自己的核心卡门**：4 篇横版的核心卡在第一批 worker 出完后**一次性一起**交用户确认，不一篇篇问。（要不要把这道门省掉、并进选题表，等用户定；没定之前照 daily-write 走。）

## 4. 分批派 worker（用户点头后）

**每个 worker 的派单里写清：** 日期、账号（skin + orientation，或 selfie + 当天序号 01/02/03）、lengthTarget、字数、选题、来源（期号 / 选题卡原文 / 素材库 slug / 经验库编号）、topicSlug、要读的写稿技能、NAS 上这个选题有没有旧稿、交付文件名（第 5 节）、readSet / writeSet / forbiddenPaths。

**writeSet 怎么划（一天 12 篇选题各不相同，所以按选题天然不交叉）：**
- 每个 worker 只写：`research-runs/每日/<YYYYMMDD>-<选题>/`（或它技能规定的 `scratch/…/` 子目录，带选题名）、NAS `待审文案\<选题>\` 里自己那几个新文件、NAS `资料\<选题>\`、视频项目该选题的 `_inbox\shot-requests.json`（daily-write 4.2 节）。
- **共享文件 worker 一律不写**（并行写会互相覆盖）：`docs/稿件登记.json`（registry add）、`docs/每日/故事登记.md`、`docs/每日/账号选题台账.md`。worker 在报告里交三样：registry add 的完整命令、故事登记要追加的一行、台账要追加的一行；主会话在第 6 节按顺序一条条执行。
- forbiddenPaths：治理文件（CURRENT / DECISIONS / HANDOFF / 反馈台账 / 稿件登记 / 写稿规则 / 校准词表）、别的选题的文件夹、视频仓库除 `_inbox\shot-requests.json` 以外的一切。

**闲鱼实搜和百度采集只能一个一个来**：`topic-scan` / `baidu-demand` 用同一台机器上的采集 Chrome，两个 worker 同时搜会互相抢。派单时写明"要实搜先报给主会话排队"，或者干脆把要实搜的几个选题放进同一批、由一个 worker 依次搜。优先用 SRT 原片截图、素材库和现成截图，少实搜。

**分四批，一批做完验收了再派下一批（不一次派 12 个）：**

| 批 | 内容 | worker 数 | 每个 worker 写几篇 | 说明 |
|---|---|---|---|---|
| 1 | 横版 4 篇：第一段（核心卡） | 2 | 各 2 个选题的核心卡 | daily-write 第一段；出完 4 张卡一起交用户确认 |
| 2 | 横版 4 篇：第二段（查、写、自检、交付） | 2–4 | 各 1–2 篇 | 核心卡确认后再派；一个 worker 同一时间只写一个选题（daily-write "一次只做一个选题"） |
| 3 | 竖版四套皮肤 4 篇 | 2 | 各 2 篇 | short-video；可以和批 2 同时跑（选题不同，writeSet 不交叉），但实搜要排队 |
| 4 | 聊天记录 1 篇 + 真人出镜 3 篇 | 2 | 一个写聊天记录，一个写 3 篇真人出镜 | chat-record / short-video（selfie） |

- 同时在跑的 worker 最多 4 个；额度紧就一批一批串着跑。
- 同一个 worker 不同时拿两个技能的活（比如不让一个 worker 既写长稿又写聊天记录）。
- 某个选题查不到数据、缺钱数：worker 停下回报，主会话问用户换题还是补数（一次问一件事），不让 worker 自己换题——换题要重新核两条硬规矩。
- worker 连着失败两次同一件事就停，写进报告，不重试。

**worker 报告要有五项**：改动文件（NAS 上新建的文件清单）/ 命令与结果（自检结果）/ 产物路径 / commit（写"无"）/ 剩余风险；外加上面说的三样（registry 命令、故事登记行、台账行）。

## 5. 交付命名和 .meta.json（所有写稿技能统一照这个）

正稿都放 `Z:\素材生成库\ai文案\待审文案\<选题>\`（NAS 同一位置：`\\Zqkj_nas\一楼4t\素材生成库\ai文案\待审文案\<选题>\`），资料放 `资料\<选题>\`。

| 账号 | 正稿文件名 | 旁边的 .meta.json |
|---|---|---|
| 皮肤稿（横版/竖版） | `<YYYYMMDD>-<选题>-<skin>-<h\|v>.txt` | `<YYYYMMDD>-<选题>-<skin>-<h\|v>.meta.json` |
| 聊天记录 | `<YYYYMMDD>-<选题>-chat-v.txt` | `<YYYYMMDD>-<选题>-chat-v.meta.json` |
| 真人出镜 | `<YYYYMMDD>-<选题>-selfie-<NN>.txt`（NN = 当天第几篇真人出镜，01/02/03） | `<YYYYMMDD>-<选题>-selfie-<NN>.meta.json` |

- `.meta.json` 和正稿**同名、只换扩展名**（`xxx.txt` 配 `xxx.meta.json`，不是 `xxx.txt.meta.json`）——中控台「今日任务」就是按这个把稿子配到账号卡片上的。
- 皮肤稿的 `.meta.json`（UTF-8，不带 BOM）：
  ```json
  {"skin":"black-yellow-v2","orientation":"h","lengthTarget":"5min","date":"2026-09-29","topicSlug":"jiakao-ziliao","title":"驾考资料"}
  ```
  - `skin` 只能是 `black-yellow-v2` / `lime-capsule` / `signature-wall` / `ledger-desk` / `chat`，拼错了中控台配不上账号、也不报错。
  - `orientation`：横版 `h`，竖版和聊天记录 `v`。`lengthTarget`：横版 `5min`，竖版 `1-2min`。`date`：写稿当天。
  - `topicSlug`：素材库 slug；素材库还没有这个品就**不写这个字段**（不编 slug）。`title` 可选，写选题名。
- 真人出镜的 `.meta.json`：
  ```json
  {"kind":"selfie","orientation":"v","lengthTarget":"1-2min","date":"2026-09-29","title":"新手标题怎么写才搜得到"}
  ```
  不写 `skin`，不写 `topicSlug`。
- 同名 `.素材.md`（`<同一个文件名去掉 .txt>.素材.md`）照旧可以放在正稿旁边（真人出镜不用放）；说明.md、截图、字幕等其他资料放 `资料\<选题>\`。
- 文件名开头不能是下划线；同名文件已存在就在末尾加 `-2`，不覆盖。
- 写 `.meta.json` 用 node（`JSON.stringify` 后 `fs.writeFileSync(…, 'utf8')`），不要手敲，写完用 `node -e "JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'))" <文件>` 验一遍能解析。

## 6. 汇总（每批 worker 回来后，主会话做）

1. **验收**：看 worker 报告五项；抽查每个选题文件夹里正稿、`.meta.json` 都在、两者同名；打开 `.meta.json` 核一遍 skin / orientation / lengthTarget 和账号对得上；数一下字数在范围里（横版 1300–1600，竖版 300–600）。
2. **登记**（按顺序一条条跑，不并行）：
   - `node engine/return/registry.mjs add …`：worker 给的命令。账号信息写在 `--note` 里（registry 没有 skin 字段，不改代码），格式固定：
     ```
     --note "写稿模型 <模型>；<长稿|短稿|聊天记录|真人出镜>；账号 <skin>-<h|v>（真人出镜写 selfie-<NN>）；lengthTarget <5min|1-2min>；<讲法/骨架>；NAS <正稿完整路径>"
     ```
     `--id` 用正稿文件名去掉 `.txt`（如 `20260929-驾考资料-black-yellow-v2-h`、`20260929-标题怎么写-selfie-01`）；`--film` 用 topicSlug（素材库没有就用选题拼音，小写连字符；聊天记录照 chat-record 的 `<拼音>-<两位序号>`）。
   - `docs/每日/故事登记.md` 末尾追加 worker 给的行（长稿必有；短稿、真人出镜、聊天记录用了来之不易故事才有）。
   - `docs/每日/账号选题台账.md`：在对应账号那一节表格末尾追加一行（日期｜选题｜topicSlug｜稿件文件名｜存稿），只追加不改旧行。
3. **回报用户**（大白话，一张表）：账号｜选题｜文件名｜字数｜检查结果｜要用户看的事（缺数、待打码的图、待补截图的搜索词）。最后一句告诉用户去中控台「今日任务」逐套审。

## 你不做的事

- 用户没点头就派 worker 或写稿。
- 自己写稿（主会话只排表、派活、验收、登记）。
- 改台账旧行（只有「存稿 → 已发」由主会话或用户按用户说的改）；改 DECISIONS / HANDOFF / CURRENT（需要记的新决定交主控会话）。
- 动视频仓库（只读；唯一例外是写稿技能里规定的 `_inbox\shot-requests.json`）。
- 为了凑满 12 行编选题或编数：选题池真凑不出来，就少排几行，告诉用户缺几篇、为什么。
