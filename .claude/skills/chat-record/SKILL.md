# chat-record · 聊天记录式短视频文案

画面就是一段手机聊天记录，消息一条条弹出来，**没有旁白、没有配音**，观众全靠读聊天内容看懂。视频项目的程序逐行解析文案，格式错一行整篇报错。

- **格式唯一真身**：视频仓库 `D:\项目仓库\remotion视频制作\scripts\chat\parse.mjs`（解析器）。给写手的说明是视频仓库的 `src\chat\COPY-FORMAT.md`（提示词），语法表是 `src\chat\README.md`。三者冲突以解析器为准。视频仓库**只读**，不改、不往里放文件。
- 内容规矩沿用短视频：`docs/短视频规格.md`（讲闲鱼、讲数据、讲述人是"我"、不写收益数字）。本文件只讲聊天记录这一类多出来的规矩和怎么干；规格和本文件冲突时以规格为准，并在报告里指出。
- **观众是小白**：想做闲鱼、还没开始的人（DECISIONS 2026-09-27：短视频一律对小白讲，不分产品/经验角度）。

## 3. 格式（以 `parse.mjs` 为准）

交付件是**一个 txt，两块**：上面是聊天文案，单独一行 `=====素材清单=====`，下面是素材清单。不要解释、标题、Markdown 符号、代码框。

**第一块 · 聊天文案**
1. 最前面两行声明角色（必须在所有消息前面，正文开始后再出现 `@左/@右` 会整篇报错）：
   ```
   @左 粉丝 avatar=left-fa.png
   @右 圣矾 avatar=right-shengfan.jpg
   ```
   角色名不能有空格、冒号。左边名字只用"学员"或"粉丝"。
2. 之后每行一条消息：`角色名：台词`。冒号用全角"："（解析器半角也认，但统一写全角）。角色名和声明一字不差——写错一个字（圣帆）解析器**不报错**，会默默多出一个左边角色，所以必须跑第 6 节的检查。一条消息只占一行。
3. 特殊消息（方括号半角 `[ ]`，里面空格半角）：
   | 写法 | 效果 |
   |---|---|
   | `角色：[表情 文件名.png]` | 表情包，无气泡 |
   | `角色：[图片 文件名.png]` | 聊天图片/截图 |
   | `[系统 文字]` | 居中灰字，独占一行，不写角色名 |
   | `[拒收] 角色：台词` | 发送失败，程序自动补"消息已发出，但被对方拒收了。" |
   | `角色：[转账 金额]` / `[转账 金额 已接收]` / `[转账 金额 3s后接收]` | 转账卡片，金额只写数字 |
   文件名英文或拼音、不带空格，`.png` / `.jpg`。**标签写错（比如文件名带空格）解析器不报错，会当成普通台词显示出来**，也靠第 6 节检查拦。
   转账在"学员/粉丝问问题"的题材里基本用不到；真要用，金额必须来自选题卡或用户字幕。
4. 想让某条停久一点，行末加 `{hold=秒数}`（如 `{hold=2}`），只能放在行末。一般不加，程序按字数定停留时间；只在反转、关键数字、梗的地方加。
5. 不写注释、场景描写、括号动作（"（叹气）"）、时间戳；动作和情绪改成台词、表情包或 `[系统 …]`。空行会被忽略。

**第二块 · 素材清单**
每行 `文件名：一句话说明`，文案里每个表情、图片都要列，没用到就写一行"无"。闲鱼截图的说明要写清是实搜哪个词、图上能看到哪个数，并注明"截图用实搜原图"。

**最小完整示例**（〔 〕里是占位，写的时候换成真实的；数字一律从 SRT/截图来，这里不给）：
```
@左 粉丝 avatar=left-fa.png
@右 圣矾 avatar=right-shengfan.jpg
粉丝：问一下，闲鱼上那种〔产品〕是怎么做的？
粉丝：[图片 xianyu-search.png]
粉丝：排第一的那条，〔截图上的想要人数〕人想要
圣矾：你猜他手里有没有货 {hold=2}
粉丝：[表情 thinking.png]
粉丝：〔小白会有的猜测〕
圣矾：〔反常识的一句〕
圣矾：〔拆成两三条的解释〕
[系统 〔可选：时间过渡〕]
粉丝：〔追问：难不难 / 钱从哪来 / 我能不能做〕
圣矾：〔我的做法是……〕
圣矾：〔一个坑，一句红线〕
粉丝：〔收尾的梗或恍然大悟〕
圣矾：[表情 doge.png]
=====素材清单=====
xianyu-search.png：闲鱼搜「〔搜索词〕」的实搜结果截图，排第一的链接显示〔数〕人想要（数字要和截图对上，截图用实搜原图）
thinking.png：一个托腮思考的表情包
doge.png：doge 狗头表情包
```
（示例只示范格式，条数不够 25 条；正式稿按第 4 节写足。）

## 4. 角色与写法

**角色**
- 右边永远是圣矾（`right-shengfan.jpg`）；左边默认 `left-fa.png`，用户另指定才换。
- 左边只有两类：**学员**、**普通粉丝**。问的都是闲鱼相关问题——闲鱼经验，或者一个具体产品在闲鱼上怎么做。**绝不是买家**：不写买家问价、砍价、下单、转账成交的剧情，左边也不说"我在闲鱼买过"这类买家身份的话（样稿早一版结尾有"我之前在闲鱼买票"，这类梗要不要留见第 8 节待确认）。
- 左边是小白：问的是"这是什么生意、谁在买、怎么交货、难不难、钱从哪来、我能不能做"这类问题，不预设他已经开店、有货源、在跑项目。
- **第一条消息必须是左边的文字提问**，第一条就带出"闲鱼"。

**讲闲鱼、讲数据（用户 2026-09-27 定）**
- 所有稿：前 3 条消息内出现"闲鱼"。
- **讲产品的稿**（SRT 来的）：前 3 条内还要有至少一个闲鱼数据（想要人数/浏览数/标价）。推荐做法：左边提问带"闲鱼"→ 左边发一张实搜截图 `[图片 …]` → 下一条把截图上的数念出来。数字要和素材清单里那张截图对得上。没有能对上截图的闲鱼数据，这条不写，停下报告。
- **讲经验的稿**（知识库来的）：不用讲数据（用户：「经验性的内容就没必要讲数据了」），开头把问题问出来、带上"闲鱼"就行。

**右边圣矾的回答**
- 要有干货：一条讲透一件事（一个产品怎么成立，或一条闲鱼经验的"怎么做 → 为什么 → 不这么做会怎样"），冒出第二件事就留给下一条。
- 讲述人是"我"：做法和道理用"我的做法是""我一般会"；不写"同行说过""同行说明里写着"，不点同行名字；别人的坑写成"我见过很多人……"，不编"我踩过"。"我"的具体经历只用经历清单或该期 SRT 里有的。
- 风险只点红线（版权、隐私、违法、亏钱、做不下去），集中说一次，不反复免责。
- 不写躺赚、稳赚、月入过万、百分百、暴利；不写收益数字；不放资源引流、不写加微信/私信/评论区扣字（聊天记录里也不留资料钩子）。
- 没有写稿过程话（"截图显示""原稿里""根据你提供的"）、没有具体月份和"暑假"这类时间词。

**聊天口吻**
- 短句，一条最好不超过 30 个字；一句长话拆成几条连着发。
- 靠左边提问推进，不用"首先/其次/第一第二"；圣矾不做总结。
- 25–60 条消息（约 1–2 分钟）；表情包 + 图片合计不超过 6 个。
- 中间有一次反转或意外，结尾有明确收尾（梗、反转、恍然大悟），不用"把这条转给朋友"。
- 数字写汉字（"四十九万"），跟样稿一致；聊天画面上能不能直接写阿拉伯数字，见第 8 节。
- 同一选题多条：不共享故事、例子、自造说法和开头结构（AGENTS.md）。

## 5. 写的顺序

1. 每条先定：素材（SRT 期号 / 语料包条目）→ 左边是学员还是粉丝 → 要讲透的一件事 → 用哪张截图、哪个数 → 反转在哪 → 收尾梗。写 3 条及以上先把这张表给用户看，用户点头再写。
2. 写对话，存 `scratch/聊天记录式/<序号>-<选题>.txt`（UTF-8）。
3. 跑第 6 节自检，最多改两轮；两轮还过不了就停，写进报告交回。

## 6. 自检（每条都跑；输出先写文件再看，别接 `| tail`）

**① 格式 + 角色（机器）**
```bash
node .claude/skills/chat-record/check-chat.mjs scratch/聊天记录式/<序号>-<选题>.txt
```
它把视频仓库的 `parse.mjs` 复制到系统临时目录里跑（视频仓库不动），再查：有没有 `=====素材清单=====`；@左 只有一个、名字是学员/粉丝；@右 是圣矾 + `right-shengfan.jpg`；有没有没声明的角色（写错字）；第一条是不是左边的文字提问；方括号标签有没有写错被当成台词；表情+图片 ≤6；文案用的文件和素材清单一一对上。条数不在 25–60、单条超 30 字、左边头像不是默认、第一条不像问句、用了转账，只出"提醒"。退出码 0 才算过。
同时把所有文字气泡和系统灰字抽成一行一句的 `<序号>-<选题>.台词.txt`，给下面两步用。

**② 合规（必过）**
```bash
npm run check:compliance -- scratch/聊天记录式/<序号>-<选题>.台词.txt
```
必须 PASS（block 0）。**不要直接查原稿**：声明行和文件名会干扰。

**③ 词表 + 写稿规则**
```bash
npm run check:draft -- scratch/聊天记录式/<序号>-<选题>.台词.txt --topic <选题> --topic-type 虚拟
```
2026-09-27 用电影票样稿实跑过：对台词文本能用。忽略 R002–R007、R010、R011（长稿结构规则，跟短视频一样）；R009 一句一行对聊天气泡也成立，照看；其余命中照改；R040 撞的是圣矾本人语料（`K-说-H-圣矾-*`）不算抄。只想单查词表可以跑 `node engine/brief/check-words.mjs <台词.txt> --topic-type 虚拟`。**对原稿直接跑词表会把 avatar、png、hold 全报成"英文字母"，没有意义。**
同题有别的稿时加 `--against` 查连抄（写法照 daily-write 第 8 节）。

**④ 人工对一遍（写进说明.md，每条一行"过 / 不过 + 理由"）**
- 左边是学员/粉丝，问的是闲鱼问题；全篇没有买家剧情、没有左边的买家身份。
- 左边问的是小白会问的；对着 `docs/audience-lock.md`「受众漂移信号」逐条查。
- 前 3 条有"闲鱼"；讲产品的稿前 3 条还要有一个闲鱼数据（经验稿不要求）；每个闲鱼数据都有截图对得上（写出截图来源路径）。
- 每个钱数能在 SRT 原话 / 选题卡里找到（写出出处）；没有编"我/学员"的收入。
- 右边讲干货用"我"，没有"同行说过"。
- 红线词、写稿过程话、月份时间词都没有；风险只说了一次。

## 7. 交付与登记

**交付**（路径见第 0 节）每条一个文件夹或同一批一个文件夹，里面：
- `<序号>-<选题>.txt`：两块齐全的交付件（聊天文案 + 素材清单），就是视频项目要的东西。
- `<序号>-<选题>.素材.md`：素材清单里每个**图片**对到真实文件——截图的本机路径（素材池 manifest 的 path / research-runs 截图 / 原片截图）、尺寸、SHA-256；表情包写"待视频项目找图"。缺图列在「缺图」一节。
- `说明.md`：一张表（序号｜选题｜素材来源｜左边角色｜讲透的一件事｜闲鱼数据及截图｜消息条数｜三道检查结果），表下每条贴第 6 节 ④ 的人工对照，再列"超出原文的推断句"和"待用户确认的事实"。
- 不覆盖、不删除 NAS 上已有的文件。

**登记**（每条一条，只用这条命令，**不许直接改 `docs/稿件登记.json`**）：
```
node engine/return/registry.mjs add --id <YYYYMMDD>-<选题>-聊天A --version v1 --topic <选题> --film <选题拼音，小写连字符>-<两位序号> --draft scratch/聊天记录式/<序号>-<选题>.txt --angle <左边角色+讲透的一件事> --date <YYYY-MM-DD> --note "聊天记录式短视频；素材 SRT 第N期|知识库 <条目>；NAS <交付路径>"
```
同题第二条用 `…-聊天B`。`--film` 用视频项目 `src/chat/films/<id>` 的起名方式（如 `dianyingpiao-01`）。有 SRT 期的事实卡就加 `--factcard research-runs/<期>/事实卡-终版.md`。
对话里用了"来之不易"故事的，按 daily-write 第 10 节往 `docs/每日/故事登记.md` 末尾追加一行（只追加，不改旧行）；没用就不登。

**之后**：员工改好 → 由视频项目把第一块存成 `src/chat/films/<id>/<id>.txt`、跑 `parse.mjs`、按素材清单放图（见 COPY-FORMAT.md「交回来之后」）。那是视频项目的事，本技能不做。
