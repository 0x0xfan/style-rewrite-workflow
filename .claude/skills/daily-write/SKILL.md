# daily-write · 每日写稿（写给 Gemini）

你给圣矾写口播稿。圣矾是 B 站 UP 主，讲怎么在闲鱼上做虚拟项目赚钱。稿子交给他的员工改，员工改完就出片。
**观众是想找副业、从来没在闲鱼卖过东西的人**：不懂闲鱼、就想赚钱，不是已经在闲鱼卖货、来找问题出在哪的卖家。稿子要先让这类人听懂，再讲操作。
**写作角度按稿件类型分（用户 2026-09-27 定）：**
- **产品稿**：讲一个具体产品、具体路子的稿（SRT 入口、选题卡入口基本都是这种）。站在"还没做过闲鱼、想赚钱的小白"角度写，从他现在的生活写起（下班回家、带孩子、上学、怕投钱），不写成已经在开店的人。
- **经验稿**：讲闲鱼通用经验的稿（上架、标题、客服、账号这类，不绑一个具体产品）。可以站在"已经在做闲鱼的人"角度写。
- 是哪一种，写在核心卡的"稿件类型"一行，用户确认。拿不准就按产品稿写。
**你的目标：写出员工不用再改的稿。** 员工改稿几乎只做一件事：把话说全（补主语、补连接词、补"的话/如果/之后/至于/已经……了"）。所以宁可啰嗦一点，也不要短、不要漂亮。
**用户要的是干货**：观众听完要觉得学到了闲鱼上的门道，而不是听了一遍流程说明。

一次只做一个选题：写完、查完、交完这个选题，再做下一个。

**两个入口，只在最前面不同，后面走同一条流程（用户 2026-09-26 定）：**
- **入口一：SRT（优先）。** 调用者说"写第 47 期"→ 读那期视频的字幕，自己填好选题卡（第 1A 节）。SRT 是圣矾自己讲的整期内容，比选题卡全，能走这条就走这条。
- **入口二：选题卡（补充）。** 调用者直接贴选题卡 → 从第 1 节开始。

**整个流程分两段，中间有一道用户确认门：**
- 第一段：（SRT 入口先做第 1A 节）读选题卡 → 出核心卡（第 2 节）→ **停下，把核心卡交给调用者，等用户确认。** SRT 入口把自己填的选题卡和核心卡一起交，一次确认，不另开一道门。
- 第二段（调用者告诉你"核心卡已确认"，并给你确认后的卡）：查闲鱼 → 干货单 → 区分表 → 写稿 → 自检 → 交付 → 登记 → 回报。
- 用户没确认核心卡，不许查、不许写。用户改了卡，以改过的为准。

## 0. 开工前

- 调用者会告诉你：期号（SRT 入口）或选题卡（贴的文本或文件）、每个选题写几篇长稿 N、几篇短稿 M（没说就长 1 短 1）、今天日期。
- 先读 `examples/` 里全部样板（长 4 篇、短 2 篇）。每篇第一行 `#` 开头的是说明，写它好在哪。**学口气，不抄句子、不抄事实**（机器会查八个字以上的重合）。样板的正文都是分点讲，那只是六种讲法里的一种（见第 6 节）。**学它的口气，不学它的开头**：样板的开头都是旧写法，开头一律按 `docs/每日/开头样板.md` 写（第 6 节）。
- 工作目录：`research-runs/每日/<YYYYMMDD>-<选题>/`（本机，不入库）。把选题卡原文存成里面的 `选题卡.txt`（SRT 入口存你填的那张）。

## 1A. 入口一：SRT（调用者给期号时）

**第一步，找字幕和原片：**
```
node engine/brief/srt-find.mjs --episode <期号> --out "research-runs/每日/<YYYYMMDD>-<选题>"
```
- 打印 SRT 路径、mp4 路径、期名、时长，并在工作目录写好 `字幕.txt`（一行一条：`[00:01:23] 原话`）。选题名先用期名，文件夹名不像选题（比如"重""ios"）就按字幕讲的东西起一个。
- 退出码 1（找不到这一期 / 有多个候选 / 没有 SRT）→ 停，把打印的候选原样回报调用者，不猜、不换别的期。
- 退出码 3（mp4 有多个候选）或打印"mp4：没找到"→ 字幕照用，第三步的原片截图跳过，在回报里说一句。打印"名字不同，请核对"的 mp4 也照用，回报里提一句。

**第二步，通读 `字幕.txt` 全文**（不许只看开头、不许按关键词跳着看），填选题卡五行。**每行下面附 SRT 原话和时间戳**，让用户一眼能核对：

```
选题：闲鱼做淘客，把闲鱼当流量入口
  原话：[00:00:05] 淘客新路子 / [00:00:06] 把闲鱼当流量入口做截流
怎么赚钱：……
  原话：[时间] ……
怎么做：……
  原话：……
你自己的经历：……
  原话：……
不能说的：……
  原话：……
```
- **怎么赚钱**：钱数（卖价、进价、佣金、一单多少、收益）只能是 SRT 里圣矾亲口说的，照原话的口径写（他说"大概""最多""一个月流水"就照写，不改成别的说法）。字幕里没说钱数 → 这一行写"SRT 里没说钱数"，交卡时请用户补，补之前不写稿。
- **你自己的经历**：只取 SRT 里圣矾亲口讲的自己的经历（我做过、我试了、我这边）。没有就空着，稿里不写经历。别把他讲的道理当成经历。
- **怎么做**：抄他讲交付和操作步骤的原话，多段就挑讲得最全的几句。
- **不能说的**：从 SRT 里他自己提过的风险、红线、"不要这么做"里摘。没有就空着，交卡时提醒用户补。
- 字幕是语音识别出来的，错别字和断句照原样附，填卡的那句话里写对。拿不准的词在原话后面打"（识别可能有误）"。
- 存成工作目录的 `选题卡.txt`。然后走第 1 节，规矩跟选题卡入口一样。

**第三步，列要从原片截的画面**（有 mp4 才做）：在字幕里找讲到这几类东西的时间点——价格/收益、闲鱼搜索页或商品页、后台/订单页、交付过程（发链接、发文件、操作软件）。每处挑一个时间点，最多十来个，然后跑：
```
node engine/collect/srt-frames.mjs --video "<mp4 路径>" --times <时:分:秒>,<时:分:秒>,… --out "research-runs/每日/<YYYYMMDD>-<选题>/素材/原片"
```
- 产物：每个时间点一张 png，加 `帧清单.md`。打开每张图亲眼看：画面对不上字幕在讲的东西，就前后挪几秒重截，或者不用。
- `帧清单.md` 里标了"可能要打码"的图（聊天记录、订单、手机号、别人的头像昵称之类），**不许直接交给视频项目**，在说明.md 里单独列一节"待人工看的图"，等人看过再用。
- 这一步写稿时就做，不等出片发现缺图再补。命令报错就停在这一步回报，不反复试。

**第四步，查这一期以前写没写过稿：** 看 NAS `\\Zqkj_nas\一楼4t\素材生成库\ai文案\待审文案\<选题>\` 和 `已用\`（原「已审」，用户 2026-09-28 改名）里有没有这个选题的旧稿。有的话新稿要换开头用的法、开头素材和讲法，不和旧稿共享例子、场景和说法（第 5 节区分表里把旧稿也列上）。

## 1. 读选题卡（两个入口都走这里）

卡片五行，各管一件事：

| 行 | 你怎么用 |
|---|---|
| 选题 | 本期卖什么。文件夹名、闲鱼搜索词都从这里来 |
| 怎么赚钱 | **稿里所有钱数（卖价、进价、差价、一单多少）只能用这一行写的数。** 这里没写进价，就说"进价我没核对过，所以一单剩多少这期不给数" |
| 怎么做 | 交付怎么做的原话，原样抄进核心卡。卡上没写的步骤可以按常识补做法，但不许补数，补了的要在讲偏检查里列出来 |
| 你自己的经历 | 有就用，"我"的经历只能来自这一行；**空着就全篇不写经历，也不编"我/学员/朋友赚了多少"**。同一条经历只进一篇。例外只有两样：`docs/每日/IP信任素材库.md` 里的素材（第 6.2 节）和"来之不易"故事（第 6.3 节），按那两节的规矩用 |
| 不能说的 | 一条都不进稿，也抄进核心卡「不能讲偏的方向」。写完逐条对一遍 |

选题或"怎么赚钱"是空的 → 停，回报调用者要补什么，不写。（SRT 入口"怎么赚钱"没数时，核心卡照出，和选题卡一起交，请用户在确认时补上。）

## 2. 核心卡（第一步，用户确认门）

每篇长稿一张核心卡，照 `docs/每日/核心卡模板.txt` 填（模板下面有填好的电影票例子）。十一行：卖什么 / 本期主推 / 交付怎么做（抄原话）/ 虚拟子类 / 稿件类型（产品 / 经验，后面半句写为什么）/ **观众**（产品稿写"不懂闲鱼、想赚钱的人"，经验稿写"已经在做闲鱼的人"）/ **开头**（本篇开头用哪一法 + 用什么结果或数据，见第 6 节）/ 本篇讲法 / 本期要讲透的经验（三四条，写经验库编号）/ 彩蛋（选哪个 + 理由，从 6 节结尾钩子的五个里选一个）/ 不能讲偏的方向。
- **开头要的收益数【X】**：选题卡"怎么赚钱"或字幕里有用户给的收益数，"开头"一行就写它；没有，就选不需要收益数的写法（方法一用截图里的真数据、方法三的悬念不带数），或者交卡时在最前面一句话问用户要数。**绝不自己编数**（`docs/每日/开头样板.md` 第四节）。

- 挑经验编号前先跑一次候选清单（第 4 节的命令），编号只能从候选清单里挑。
- 同一选题写多篇：每篇的"本篇讲法"和"本期要讲透的经验"都不一样。
- 短稿不单独出卡，但不许违背同题核心卡的主推和"不能讲偏的方向"。
- 卡存成工作目录里的 `核心卡-长A.txt`、`核心卡-长B.txt`……

**交卡：** 把所有核心卡原文交给调用者，说清"等用户确认后再写"，然后停下。这一步不查闲鱼、不写稿（SRT 入口第 1A 节第三步的原片截图可以先做）。
- SRT 入口：先贴 `选题卡.txt`（带原话和时间戳），再贴核心卡，一起交、一次确认。"怎么赚钱"没数、"不能说的"空着，在最前面一句话提醒用户补。

## 3. 拿核心卡过一遍素材（用户确认后）

核心卡要先于底稿、先于素材。卡定了以后，**拿它逐句过一遍手里已有的东西**：选题卡「怎么做」的每一句、以前交过的同题稿或员工定稿（如果这期是在它上面改），每句标"留 / 改 / 删"和一句理由，写进 `说明.md`。
教训：电影票那期，员工定稿里自带"去渠道问价"这类手动说法，跟"全自动"的主推正好相反；只查新加的句子，就把它漏过去了。**旧句子一样要过卡。**

### 4.2 其他来源（百度需求佐证 / 货源证据 / 教程演示，用户 2026-09-28 定）

闲鱼实搜只证明"有没有人卖、卖多少"；这一步补三类来源，证明"有没有人在搜"（demand）、"货从哪来"（supply）、"官方怎么教"（tutorial）。素材按 `docs/交接口规范.md` 的七分类交付，这三类分别落在 `demand` / `supply` / `tutorial`。

**百度需求佐证（demand）：**
```
node engine/collect/baidu-demand.mjs --query "<搜索词>" --out "research-runs/每日/<YYYYMMDD>-<选题>/素材/baidu"
```
- 搜索词只用用户确认过的词（跟 4.1 一样，不自己想新词）。
- 遇人机验证：工具硬停，直接跳过，不绕。
- 失败一次就记下跳过，不反复试；说明.md 里写一句"百度未采集，原因"。

**货源证据（supply）：** 这个品的货从哪来——按品判断去哪找，不是每期都一样：
  - 开源项目类（比如 AI 代部署）→ 找它的 GitHub 仓库页。
  - 装了就能用的软件类（比如 C 盘清理、剪映）→ 找软件官网或下载页。
  - 代充/代开类（比如 AI 会员代充）→ 找官方价格页。
  - 挑不准就按这个顺序试：GitHub 仓库页 → 官网/下载页 → 官方价格页 → 资源站公开页。

**教程演示（tutorial）：** 官方教程页、官方帮助文档、工具自带的操作界面页（截图看它怎么教、界面长什么样，不是自己去操作它）。

**这三类的共同规矩：**
- 只看公开页面，截图；不注册、不登录、不下载安装、不点广告、不付费。
- 截图要解码、查尺寸和 SHA-256 才算有效（AGENTS.md），跟闲鱼截图一样。
- **对题核对**：打开截图亲眼确认页面讲的就是这期的品，不是同名不同物；不对题不收。
- 盗版资源站、破解站不截图（碰到就换成官网/GitHub 这类正经来源，或者跳过这类来源）。
- 截图里出现的网址、账号、个人信息，照素材整理的隐私规矩标（不直接上屏）。
- 没有自动采集脚本的来源（GitHub 仓库页、软件官网、官方教程页这类），用浏览器打开截图：Claude 内置浏览器（Browser 工具）或采集专用 Chrome 的 CDP 截图（`goofish-collect.mjs`/`baidu-demand.mjs` 用的那个 profile），两选一，用哪个在说明.md 里写清楚，不用现改自动化脚本。
- 存放：`素材/supply/`、`素材/tutorial/`（跟 `素材/baidu/` 平级）；`数据摘要.md` 里加一节"来源清单"，记这几张图分别对应哪个来源、哪个网址——**网址只记在这份资料文件里，不进口播稿、不上屏文字**。

**这些来源的"数"能不能进稿：** 只有截图里亲眼看到、且和选题卡/核心卡不冲突才能用；官方价格可以用来讲差价逻辑（比如"官方卖多少，我这边卖多少"），GitHub star 数这类可以用来证明"这个项目有人用"，不能当成收益数字。

### 4.3 干货单（写稿前通读经验库）

```
node engine/brief/pick-experience.mjs --subtype <核心卡上的虚拟子类> --out "research-runs/每日/<YYYYMMDD>-<选题>/经验候选.md"
```

这条命令已经替你过滤好了：只留"通用"和"虚拟专用"、并且虚拟子类包含本期子类的条目，🚫 的一条不出，实物专用的你根本看不到。想只看某几个环节，加 `--env 上架,售后`。**候选清单要通读，不要只搜关键词。**

再拿核心卡筛一遍：
- 跟本期主推相反的去掉（全自动选题里，"卖家自己一条条接待"这类不用）。
- **提醒主推做法里要小心的坑，留下。** 例：全自动选题里，"说明里别写秒发、自动发货，会被当成商家"这条要留。
- 经验里的数字（天数、条数、比例、效果）一个都不带进稿。
- ⚠️ 的条目看备注，备注里剥掉的东西不许回到稿里；剥干净意思不成立就不用。
- "换说法"一栏有内容的，进稿时把实物的词换掉（例：售后→退款、纠纷）。
- 把握是"低"的，标签还没经用户确认，能不用就不用。

筛完写进 `说明.md` 的「干货单」一节，一张表：

| 编号 | 经验一句话 | 标记 | 为什么适合这期 | 本题说法（稿里第几行） | 剥掉了什么 / 换了什么说法 |
|---|---|---|---|---|---|

表下再列"看过没选的"几条和原因（跟主推冲突 / 和别的条目重复 / 篇幅放不下）。核心卡上那三四条必须在表里；干货单里别的条目最多当一句带过，不展开。

## 5. 写之前先排区分表（同题多篇时必做，一篇也要填）

写到 `说明.md` 开头：

| 篇 | 稿件类型 | 开头用的法 | 开头用的结果或数据（出处） | 第一句讲什么 | 引用哪几个数（数据摘要里哪一条） | 例子/场景 | 讲法 | 讲透哪几条经验（编号） | 用经历吗 | 信任/共鸣素材（编号） | 来之不易故事（一句话梗概） |
|---|---|---|---|---|---|---|---|---|---|---|---|

同一选题的几篇（包括以前交过的同题稿：先看 NAS `待审文案\<选题>\` 和 `已用\` 里有没有；SRT 入口同一期以前写过的也算）**只共享事实**。开头用的法、开头素材、第一句、例子、场景、讲法、讲透的经验、自己的说法、来之不易故事必须各不相同；同一个事实在两篇里要换说法；同一个信任素材两篇都用的话要换角度讲。
排表前先读 `docs/每日/故事登记.md`，新故事的梗概不能和表里已有的重复或矛盾（第 6.3 节）。
开头用的法是 dbs-hook 三法之一（素材提取 / 补素材 / 留悬念），见 `docs/每日/开头样板.md`。同题三篇以内每篇一个法不重复；超过三篇时法可以重复，但开头素材和结构不许重复。

## 6. 写长稿（每篇 1300–1500 汉字，约 5 分钟）

**顺序（照样板）：**
1. **开头：按 `docs/每日/开头样板.md` 用 dbs-hook 三法设计**（写之前先读完那份样板）。唯一标准：看完开头就清楚这期讲什么生意、钱从哪来；开头突出结果，用数据或结果留人。
   - 产品稿：第一句就点名"闲鱼上的一个赚钱生意 + 能赚多少 / 一个硬数据"，接一句"今天给你拆解拆解 / 今天给你讲清楚"；怎么做的全放正文。角度是"分享给你一个能赚钱、能当副业的东西"，不是揭秘"他"的生意、不是先铺生活场景。
   - 经验稿：站在已经在做闲鱼、遇到问题的人的角度，点出问题 + 结果（怎么解决），同样简单直接。
   - **每篇先列 3 个候选开头（素材提取 / 补素材 / 留悬念各一），写进 `说明.md`**，挑最好的一个进稿，并写一句为什么挑它。用的法要和核心卡"开头"一行一致。
   - 同题多篇用不同的法、不同的素材（第 5 节区分表）。
   - 收益数【X】只用选题卡或字幕里用户给的数；没有就换不需要收益数的写法，**绝不自己编数**（样板第四节）。
   - 开头一般一两句，最多三四句；小白要问的"闲鱼是什么、谁在买、怎么交货、难不难"放到下面第 2 步那两行之后讲，不塞进开头。
2. 固定两行：`我是圣矾。` 下一行 `学闲鱼，找圣矾。`（全篇只出现这一次，前十句内）。之后产品稿用几句大白话给小白补上：这是什么生意、谁在买、怎么交货、难不难（闲鱼的词第一次出现顺口解释）。
3. 框架句：按本篇讲法写，一句话告诉观众这期怎么走（见下表，机器不再查框架句的写法）。
4. `这期视频干货非常多，建议先点赞收藏。`
5. 正文：按核心卡上的讲法走，把核心卡那三四条经验讲透（写法见 6.1）。
6. 结尾五行：一句交底（`前面这些数是我推算的流水，没扣成本。`，全篇只说这一次）→ `算不算违规，上架之前自己去搜一下平台规则。` → 资料钩子两行 → 固定收尾句。
   - 资料钩子固定两行，只有〔〕里的内容每期换：
     `最后圣矾给大家准备了〔彩蛋〕，这些资料圣矾分享给大家。`
     `有需要的同学在评论区扣个〔关键词〕，圣矾看到就发给你。`
     不写"无条件"；关键词写成本期两三个字，不带〔〕符号本身。**〔彩蛋〕这里第一句不写死量词，量词由彩蛋自己带**（一份/一个），照抄口播说法整段替换进去。
   - 彩蛋只能从下面五个里选一个，不许自己编，口播里的说法照抄右边（量词已经带在里面）：

     | 彩蛋 | 口播说法 | 什么选题用 |
     |---|---|---|
     | 1 入门版 | 一份闲鱼虚拟的入门教程 | 新手向、门槛低；实在没有合适的就用它 |
     | 2 自动发货工具 | 一个免费的闲鱼虚拟自动发货工具 | 网盘发资料、卖软件这类能自动发货的 |
     | 3 违规词 | 一份五千五百多个违规词的词库，还有侵权词检测工具 | 有版权或违规风险的，比如戏曲、驾考、影视类，以及讲说明怎么写、避坑的 |
     | 4 爆品表 | 一份每周更新的闲鱼虚拟爆品表 | 讲选品、讲什么好卖的 |
     | 5 官方知识库 | 一份闲鱼官方课堂的知识库 | 讲平台规则、店铺运营的 |

     口播只说名字，不说效果（比如罚款多少、关了软件也能发货）。同题多篇可以轮换彩蛋。
   - 最后一行：`这期视频就到这儿，学闲鱼找圣矾，我们下个视频见。`

**六种讲法（正文不再固定三点，按内容挑，同题各篇不重复）：**

| 讲法 | 什么时候用 | 框架句怎么写（意思，别照抄） | 正文怎么走 |
|---|---|---|---|
| 分点讲 | 要讲的几件事互不相干 | 这期讲两点 / 这期一共四点，……（点数照实） | 两到四点；"先说第一点 / 接下来是第二点 / 最后一点" |
| 跟着一单走 | 流程环环相扣 | 这期就跟着一单走一遍，从……到……（把路线说出来） | 按一单的先后顺序讲，不分点、不编号，每到一个环节讲一条经验 |
| 问答式 | 新手疑问多 | 这期把新手最常问的几个问题挨个说一下 | 每段用一个设问起头（可能你会问，……？），问完自己答，不编号 |
| 先算账再拆 | 钱是最大的卖点 | 这期先把一单的账算清楚，再说这个账是怎么做出来的 | 先算账（数只用卡片的），再一环一环拆开讲 |
| 只讲透一件事 | 只有一个关键动作决定成败 | 这期就讲一件事，…… | 一件事讲深：怎么做、为什么、做错了会怎样、我怎么判断 |
| 先说新手误区再讲正确做法 | 新手常做错 | 这期先说新手最容易做错的地方，再说我是怎么做的 | 先说错的做法，再说对的做法；只说做法差别，不贬同行 |

- 需要给段落编号时一律用"点"（第一点 / 最后一点），不用块、三件事、三条路。
- 操作步骤照旧写"第一步……第二步……"。
- "很多人觉得……恰恰相反"全篇最多一次（误区讲法除外）。
- 点尾或环节尾可以一句"到了这一步，你已经……"。

### 6.1 经验式写法（让观众听得出是干货）

每条经验写成三段：**怎么做 → 为什么 → 不这么做会怎样。** 用一句点题的话把它引出来，让观众知道"这是门道"：这里有个坑 / 很多新手不知道 / 我的做法是 / 这里特别强调一点 / 这里有个重点要注意。

- 讲透三四条，不要撒九条浅的。一条经验至少三四句。
- 经验要从"你刚开始做的时候"这个角度讲：我刚开始做的时候是怎么发现这个坑的、我刚开始也是这么走过来的。不写只有老卖家才懂的话（"老账号权重高""做了几年你就知道"），观众还没开始做，没有"老"和"新"的对比经验。（这条管产品稿；经验稿观众已经在做，可以讲"你店里""你上架的东西"。）
- 口吻是圣矾自己的做法和判断（我的做法是、我一般会、我都是）；**不许编亲历故事**（"我有一次""我之前有个学员"），不许编任何人的收入。经验库条目是同行说的，只借做法和道理，不借故事和数。例外只有两样：信任素材库里现成的事（第 6.2 节，比如 T12 学员反馈，照原话用）和一个"来之不易"故事（第 6.3 节）。除此之外的亲历故事照旧不许编。
- 点题句在同一篇里别重复用同一句，同题各篇也要换（机器查八字重合）。
- 经验直接当事实说，不写"有人是这么干的""做闲鱼的都知道"。

反面（像流程说明，太淡）：
> 买家搜的就是片名加电影票……所以我会一部电影挂一条链接。

正面（经验式）：
> 这里有个很多新手不知道的地方，闲鱼搜索是按你标题里的词去匹配的。
> 你标题写的是低价电影票，买家搜哪吒电影票，是搜不到你的。
> 所以我都是一部电影单独挂一条，片名放在标题最前面。

（两段都只是示范写法，句子不许照抄。）

**必须做：**
- **话说全。** 员工真实改法（改前 → 改后），照这个方向写：
  - 他买的是有人替他配好 → 他想买的是有人替他配好
  - 拍下网盘自动发货 → 买家拍下后网盘自动发货
  - 那家店在闲鱼开了六年 → 那家店已经在闲鱼开了六年了
  - 你只上架三五条，那就只有三五条的流水 → 你只要是上架三五条，那就只会有三五条的流水
  - 链接铺好了，卖出去之后怎么交付，才是…… → 链接铺好了，至于卖出去之后怎么交付，才是……
  - 这个品能卖，是因为…… → 这个品为啥能行呢，是因为……
  - 全店卖出八万三千多件 → 全店加起来一共卖出去八万三千多件
  - 我一开始也这么算 → 我一开始也是这么算的
  - 标尺句：`开单之后如果你的执行力不到位，那么你的退款率会很高。`
- **人话**：直白的名词动词。不需要你负责（不写"你不自己扛"）；不是到你手里的利润（不写"不是你兜里的钱"）；开通、设置成、整理、下载（动词用两个字）。
- **报数带名词**：排最前面那条商品是七百多人想要；这家店全店累计卖出九万九千多件，这是整个店加起来的数，不是这一条链接的。零头取整加"多"；好评率读"百分之九十九"；全用汉字数字。
- **指图说数**：你看搜索页 / 通过图片可以看到 / 我自己去闲鱼搜了一下。
- **推算要说是推算**：想要不是成交，"按三到五成推算"；只说流水或毛利润，不说到手利润。
- 一句一行，句号结尾，一行不超过五十个汉字；长了用逗号断开接着说，**不许为了短砍连接词**。篇幅超了删整句。
- 软件名照原名写（Obsidian 就写 Obsidian）。
- **闲鱼上的词第一次出现要顺口解释一句**：想要（想要 = 有人点了想买）、链接（链接就是你挂的这条商品）、上架（上架就是把东西挂到闲鱼上）、网盘自动发货（买家一拍下，网盘链接自动发过去，不用你手动发）、店铺（店铺就是你在闲鱼开的这个号）。观众没做过闲鱼，听到这些词卡一下就划走了。

**绝对不做：**
- 编：卡片和数据摘要以外的数；卡片以外的"我"的经历；学员、朋友、"某某赚了多少"；经验库里的数字。资料钩子的彩蛋只能从固定五个里选一个，不许自己编资料名。（信任素材库里现成的事和数、一个守边界的"来之不易"故事不算编，见 6.2、6.3。）
- 讲偏：核心卡「不能讲偏的方向」里的任何一条。
- 时间词：九月初、八月底、今年暑假这类月份和时效词一律不写，说"我之前看的时候""你在闲鱼搜"。
- 比喻、造词、起名字（收券三看、三句硬话）、对仗金句、整齐收口、"不是……而是……"这种纠偏句。
- 江湖话和书面词：扛、兜里、妥妥的、命门、盘面；落在、散在、注明、设定、维度、赋能；压缩说法：这一屏、干货密、需求真不真。
- 我们自己的叫法：红条、口子、规则卡、想要数、口径、事实卡、SKU、核心卡、干货单、经验库、编号。
- 空悬念和承诺：最关键的是第几点、一定要看完、漏听了就坏；学完当天就能接单、必卖爆、一定出单。
- 贬同行：差评、退款多、杂货铺什么都卖，都不说；同行只拿来"炫"。误区讲法说的是"新手容易这么做"，不点任何同行。
- 虚拟品不说退货、快递、运费、签收、物流；正文说"退款"不说"售后"（框架句里"售后怎么办"可以）。
- 合规红线：躺赚、稳赚、月入、百分百、暴利、纯利润、零成本、白嫖、包上热门；加微信、私信、扣1、主页链接。
- 过程话：原文里、资料里、截图显示、根据你提供的、选题卡上写着。
- **把用户的话推大**：用户说"我有业务在用 X 思路"时，只能照原话说（"我自己也有业务在用这个思路引流"），不能推成"我也在做这个项目"，也不能给这个业务安收益数。例：第 47 期用户有业务在用淘客的思路做引流，但他不做淘客，写成"我自己有个业务就在用这个思路引流，一个月能给我带来【X】"被否（`docs/每日/开头样板.md` 第六节）。
- 连着三句用"我"开头；免责说两次；每段都用反问收尾。
- 「广告」这类标记（员工自己加）。

完整用词表：`docs/用户校准词表.md`（用户和员工点名改过的词，禁 → 换）；完整规则：`docs/写稿规则.md`。这两份你只读不改，下一步的检查命令会替你逐条对。

### 6.2 植入信任素材（每篇长稿一到两样）

让观众觉得"这个人靠谱""说的就是我"。每篇长稿从下面两份里挑**一到两样**，不多放：
- `docs/每日/IP信任素材库.md`：圣矾本人的事。只用 ✅ 的；⚠️ 的照"怎么用"那一栏的备注用（T11 闲鱼翻身只能提一句，不介绍、不讲怎么加入）；"不能进视频的"N01–N04 一条都不碰（工作室、价值观两句、"我跟别人有什么不同"、社群介绍）。素材里的数照原话说，不往大了改（T08 学员人数用前要问最新数，问不到就不用这条）。
- `docs/每日/共鸣素材.md`：小白通用的心事。用"很多刚开始做的人……""你是不是也……"的口气说，**不说成圣矾本人的经历**；示范句换你自己的话说。

**按稿件类型挑：**
- 产品稿：共鸣素材只从 A 类（G01–G12）、D 类（G40–G51）和 G13、G16、G17、G26、G27、G28 里挑。B、C 类其余的条目（G14、G15、G18–G25、G29–G39）说的是"你店里、你上架的东西、你的买家"，预设观众已经在做，**产品稿不用**。拿不准就问自己：这条是不是在说他已经有店、已经上架、已经有买家？是就不用。
- 经验稿：共鸣素材哪条都能用。

**放在哪：** 开头"我是圣矾 / 学闲鱼，找圣矾"之后顺一句自报家门（T01、T07 这类）/ 正文里讲一条经验时拿来举证（T10 账号基本面、T12 学员反馈、共鸣素材）/ 结尾交底句之前（T03、T04、T05 这类）。放进去不许打乱第 6 节的固定顺序和固定句。

**轮着用：** 同一样素材换角度讲，不重复上一篇的说法；共鸣素材同一条隔几期再用（查 `docs/每日/故事登记.md` 的"素材编号"一列）。T05 口头禅、T12 学员反馈一篇最多一次。

### 6.3 "来源 + 来之不易"段（产品稿必写，一篇一个故事）

用户的意思：这个路子是圣矾花了代价才弄明白的，对观众是免费的。产品稿里写一段，四到六句，讲两件事：
1. **来源**：这个路子我是怎么知道的。优先用字幕里圣矾说过的真实发现过程（比如他习惯去挖同行的店）；字幕里没有就用常见来源（翻同行的店、问人、进群）。
2. **代价**：为了弄明白付出了什么（熬夜翻店、开车找人、请人吃饭、发红包、付费进群……），最后一句落到"现在免费分享给你""今天我直接讲给你"。

**来之不易故事可以创作，但守这四条边界（用户 2026-09-27 定）：**
1. 只讲"我怎么拿到这个信息、付出了什么代价"。
2. 故事里不带具体收入数，"听说他一天能搞不少"这类模糊说法可以；项目能赚多少仍只用 SRT / 选题卡的数。
3. 不点真实人名店名。
4. 每个故事登记（`docs/每日/故事登记.md`，第 10 节），不重复用、不前后矛盾。

另外几条：
- **一篇只用一个来之不易故事。** 同题各篇的故事也不能一样。
- **不能和字幕里的真经历矛盾。** 字幕里说过的真经历（比如"找了当地经销商"）可以接在它后面补过程和代价，不能改它、不能跟它反着说（他说"这块我不专业"，故事里就不能写成他全弄懂了怎么运营）。
- 写之前先读 `docs/每日/故事登记.md`，梗概不能和表里已有的重复或矛盾。
- 这段不教观众站外怎么做，不引导观众花钱（故事是"我替你花了"，不是"你也去花"）。

参照样例：`D:\项目仓库\风格仿写\research-runs\每日\20260926-淘客\故事与场景-试写.md` 的 A1–A5（用户看过说"方向对"）。**学写法，不照抄句子、不照搬情节。**

经验稿不要求写这一段。

### 6.4 小白场景（产品稿可用，一篇最多一个）

产品稿可以放**一个**场景：上班族、宝妈、学生、怕投钱的人……从他现在的生活写起（下班八九点回到家、孩子睡着的空当、生活费不够花），落到"这个路子的门槛低在哪"。四到六句，放在"我是圣矾 / 学闲鱼，找圣矾"之后回答"难不难"那里，或正文讲门槛的地方，不放进开头。
- 不说"轻松赚钱"，说"门槛低 / 一部手机就能做 / 上手简单"。
- 场景里不预设他有店、有货、已经在上架；要学的东西说成"往后要学的"。
- "站外"对小白说成"在闲鱼外面"（比如"后面的成交在闲鱼外面完成"），只点一句，不教怎么加人。
- 同题各篇的场景不一样。
参照样例：同一个试写文件的 B1–B5，学写法不照抄。

**故事和场景写出来先过小白检查，再放进稿里：** 先把来之不易故事和场景各自单写在 `说明.md`，每段下面一行"小白检查：通过 / 不通过 + 理由"（写法照试写文件），不通过的改到通过再进稿。检查问的是：没做过闲鱼的人听得懂吗？有没有预设他已经在卖？闲鱼的词第一次出现解释了吗？

**篇幅：** 故事、场景、素材都算在 1300–1500 字里，超了删正文里别的整句，不砍连接词。

## 7. 写短稿（每篇 280–340 汉字，60–90 秒）

照 `docs/短视频规格.md`，要点：
- **观众同样是小白**：不懂闲鱼、想赚钱的人，短稿也不能预设观众已经在卖东西。
- **前两句里必须有"闲鱼"和一个闲鱼上的数**（想要人数/浏览/标价，来自数据摘要）。第一句就是钩子，讲观众想要的（少走弯路、省心、搞钱）或"我"的态度，项目名压到句尾或第二句揭晓。
- 讲述人永远是"我"（做了很多年闲鱼的圣矾）：我的做法是、我一般会。不写"同行说过"。
- 一条只讲一件事，最好就是干货单里的一条经验，照 6.1 的三段写；不预告（今天聊聊、我讲三点）；中间不用首先/其次/第一第二；结尾不总结，从这几种里挑：抛问题让人评论 / 一个今天就能做的具体动作 / 说完就停（最后一句是具体的事）。
- **不放收益数字**（一单赚多少、月入都不写；单价、想要人数可以写），不放资料钩子，没有"我是圣矾"和收尾句。
- 同一选题的短稿和长稿开头也不能一样，讲的经验也别和长稿重复。

**讲偏检查（长稿、短稿都做，写进说明.md）：**

2. 「不能讲偏的方向」逐条写"有 / 没有"，有的写在第几行。
3. **原片或选题卡没说、稿里却出现的做法，全部列出来**（第几行、这个做法从哪来：经验库编号 / 同行截图 / 你的推断）。推断出来的标"待用户确认"。
4. 经验编号核对：稿里用到的每条经验编号，都去本期的 `经验候选.md` 里找得到（找得到就说明标签对得上本期子类）；找不到的，那几句删掉或换一条。
5. **小白检查（只对产品稿做）**：逐段问"一个还没开始做的人听得懂吗"，一段一段写"懂 / 不懂"，"不懂"的写理由和第几行。参照 `docs/audience-lock.md`「受众漂移信号」那一节列的信号（拿两个卖家对比、预设你已经在跑、预设你已经有货源、没先回答"这生意到底成不成立"就进操作细节、用行业黑话不解释）逐条对一遍，撞上的算"不懂"。**来之不易故事、小白场景、共鸣素材那几句也要逐段过**，不只查正文。经验稿不做这一项。
6. **角度对不对**：核心卡写的稿件类型，和稿子实际站的角度一致吗？产品稿里有没有"你店里""你上架的""你的买家"这类预设已在做的话；经验稿有没有反过来花大段解释闲鱼是什么。
7. **来之不易故事**（产品长稿）：全篇只有一个吗？逐条写四条边界"守了 / 没守"：①只讲怎么拿到信息和代价 ②故事里没有具体收入数 ③没点真实人名店名 ④已对过 `docs/每日/故事登记.md`，梗概不重复、不矛盾。再写一句：和字幕里的真经历矛盾吗？
8. **开头**（长稿）：`说明.md` 里有 3 个候选开头（三法各一）和挑中的理由吗？挑中的开头看完能说出这期讲什么生意、钱从哪来吗？开头里的收益数来自选题卡或字幕吗（没有就写"没用收益数"）？同题各篇的法和开头素材不重复吗？
9. **素材用了几样**（长稿）：列出用到的信任素材和共鸣素材编号，一共一到两样；没碰 N01–N04；⚠️ 的照备注用了；产品稿没用 B、C 类预设已在做的那几条（见 6.2）；场景最多一个。
- 有"偏了""不懂""没守""矛盾"的段落就改稿，改完重做这张表。
