# daily-write · 每日写稿（写给 Gemini）

你给圣矾写口播稿。圣矾是 B 站 UP 主，讲怎么在闲鱼上做虚拟项目赚钱。稿子交给他的员工改，员工改完就出片。
**你的目标：写出员工不用再改的稿。** 员工改稿几乎只做一件事：把话说全（补主语、补连接词、补"的话/如果/之后/至于/已经……了"）。所以宁可啰嗦一点，也不要短、不要漂亮。

一次只做一个选题：写完、查完、交完这个选题，再做下一个。

---

## 0. 开工前

- 调用者会告诉你：选题卡（贴的文本或文件）、每个选题写几篇长稿 N、几篇短稿 M（没说就长 1 短 1）、今天日期。
- 先读 `examples/` 里全部样板（长 4 篇、短 2 篇）。每篇第一行 `#` 开头的是说明，写它好在哪。**学口气和结构，不抄句子、不抄事实**（机器会查八个字以上的重合）。
- 工作目录：`research-runs/每日/<YYYYMMDD>-<选题>/`（本机，不入库）。把选题卡原文存成里面的 `选题卡.txt`。

## 1. 读选题卡

卡片五行，各管一件事：

| 行 | 你怎么用 |
|---|---|
| 选题 | 本期卖什么。文件夹名、闲鱼搜索词都从这里来 |
| 怎么赚钱 | **稿里所有钱数（卖价、进价、差价、一单多少）只能用这一行写的数。** 这里没写进价，就说"进价我没核对过，所以一单剩多少这期不给数" |
| 怎么做 | 三点正文的骨头（找货 → 上架 → 交付/退款）。卡上没写的步骤可以按常识补做法，但不许补数 |
| 你自己的经历 | 有就用，"我"的经历只能来自这一行；**空着就全篇不写经历，也不编"我/学员/朋友赚了多少"**。同一条经历只进一篇 |
| 不能说的 | 一条都不进稿。写完逐条对一遍 |

选题或"怎么赚钱"是空的 → 停，回报调用者要补什么，不写。

## 2. 查闲鱼（必须真搜）

```
node engine/collect/topic-scan.mjs --keyword "<搜索词>" --out "research-runs/每日/<YYYYMMDD>-<选题>/素材"
```

产物：`素材/scan.json`、`素材/shots/*.png`、`素材/数据摘要.md`。
- **稿里每一个闲鱼上的数（想要人数、浏览、标价、店铺累计卖出、开店年数、好评率）只能从 `数据摘要.md` 里取，并且要打开对应截图亲眼看到这个数。** 对不上的数不用。
- 命令报错、没截图、数据摘要里没有数 → 换一个更具体的搜索词再试一次；还不行就停，回报"查不到"，**不许编数、不许用你记得的数**。
- 卡片上的价和闲鱼上搜到的价对不上时：自己的卖价/进价按卡片说，同行的价按截图说，在 `说明.md` 里写一句。

## 3. 写之前先排区分表（同题多篇时必做，一篇也要填）

写到 `说明.md` 开头：

| 篇 | 开头角度 | 第一句讲什么 | 引用哪几个数（数据摘要里哪一条） | 例子/场景 | 三点里重点讲哪点 | 用经历吗 |
|---|---|---|---|---|---|---|

同一选题的几篇（包括以前交过的同题稿：先看 NAS `待审文案\*-<选题>\` 和 `已审\` 里有没有）**只共享事实**。开头角度、第一句、例子、场景、自己的说法、侧重点必须各不相同；同一个事实在两篇里要换说法。
开头角度从这些里挑，每篇一个，不重复：数据冷开 / 算账冷开 / 报数+反转 / 断言+推演 / 提问→极简回答→展开 / 一条消息引出道理 / 亲历见闻引出（要卡上有经历）/ 一个画面+反转 / 反常识揭晓 / 开门见山预告 / 命令你现在做一个动作。定义见 `engine/corpus-pack/opening-types.json`。

## 4. 写长稿（每篇 1300–1500 汉字，约 5 分钟）

**顺序（照样板）：**
1. 开头五到九句：第一句按开头角度起（不许是"今天给大家分享一个"）；**前三句内说清卖什么、赚谁的钱、一单多少**（数来自卡片）。
2. 固定两行：`我是圣矾。` 下一行 `学闲鱼，找圣矾。`（全篇只出现这一次）。
3. 框架句：`这期视频讲三点，……` / `这期一共三点，……`（用"点"，不用块、三件事、三条路）。
4. `这期视频干货非常多，建议先点赞收藏。`
5. 正文三点。每点前一两句说为什么要讲它（原理句，或"可能你会说……"替观众问，或"很多人觉得……恰恰相反"——这个全篇最多一次），再"先说第一点 / 接下来是第二点 / 最后一点"。点里面平铺直叙，操作就写"第一步……第二步……"；五到十句最多插一句贴士（这里特别强调一点 / 这里有个重点要注意 / 这里给大家一个小建议）；点尾可以一句"到了这一步，你已经……"。
6. 结尾五行：一句交底（`前面这些数是我推算的流水，没扣成本。`，全篇只说这一次）→ `算不算违规，上架之前自己去搜一下平台规则。` → 资料钩子两行 → 固定收尾句。
   - 资料钩子只用真有的资料：`最后圣矾给大家整理了一份彩蛋资料，这些资料圣矾无条件分享给大家。` 或"一份闲鱼官方课堂的知识库，还带五千五百个违规词"。然后 `有需要的同学在评论区扣个〔两三个字的关键词〕，圣矾看到就发给你。` 不许自己编"整理了一份某某模板/清单"。
   - 最后一行：`这期视频就到这儿，学闲鱼找圣矾，我们下个视频见。`

**必须做：**
- **话说全。** 员工真实改法（改前 → 改后），照这个方向写：
  - 他买的是有人替他配好 → 他想买的是有人替他配好
  - 拍下网盘自动发货 → 买家拍下后网盘自动发货
  - 那家店在闲鱼开了六年 → 那家店已经在闲鱼开了六年了
  - 你只上架三五条，那就只有三五条的流水 → 你只要是上架三五条，那就只会有三五条的流水
  - 链接铺好了，卖出去之后怎么交付，才是…… → 链接铺好了，至于卖出去之后怎么交付，才是……
  - 这个品能卖，是因为…… → 这个品为啥能行呢，是因为……
  - 全店卖出八万三千多件 → 全店加起来一共卖出去八万三千多件
  - 我一开始也这么算 → 我一开始也是这么算的
  - 标尺句：`开单之后如果你的执行力不到位，那么你的退款率会很高。`
- **人话**：直白的名词动词。不需要你负责（不写"你不自己扛"）；不是到你手里的利润（不写"不是你兜里的钱"）；开通、设置成、整理、下载（动词用两个字）。
- **报数带名词**：排最前面那条商品是七百多人想要；这家店全店累计卖出九万九千多件，这是整个店加起来的数，不是这一条链接的。零头取整加"多"；好评率读"百分之九十九"；全用汉字数字。
- **指图说数**：你看搜索页 / 通过图片可以看到 / 我自己去闲鱼搜了一下。
- **推算要说是推算**：想要不是成交，"按三到五成推算"；只说流水或毛利润，不说到手利润。
- 一句一行，句号结尾，一行不超过五十个汉字；长了用逗号断开接着说，**不许为了短砍连接词**。篇幅超了删整句。
- 软件名照原名写（Obsidian 就写 Obsidian）。

**绝对不做：**
- 编：卡片和数据摘要以外的数；卡片以外的"我"的经历；学员、朋友、"某某赚了多少"；自己编的资料名。
- 时间词：九月初、八月底、今年暑假这类月份和时效词一律不写，说"我之前看的时候""你在闲鱼搜"。
- 比喻、造词、起名字（收券三看、三句硬话）、对仗金句、整齐收口、"不是……而是……"这种纠偏句。
- 江湖话和书面词：扛、兜里、妥妥的、命门、盘面；落在、散在、注明、设定、维度、赋能；压缩说法：这一屏、干货密、需求真不真。
- 我们自己的叫法：红条、口子、规则卡、想要数、口径、事实卡、SKU。
- 空悬念和承诺：最关键的是第几点、一定要看完、漏听了就坏；学完当天就能接单、必卖爆、一定出单。
- 引经验的固定开头：有人是这么干的、做闲鱼的都知道、做闲鱼的还有一个说法。经验直接当事实说。
- 贬同行：差评、退款多、杂货铺什么都卖，都不说；同行只拿来"炫"。
- 虚拟品不说退货、快递、运费、签收、物流；正文说"退款"不说"售后"（框架句里"售后怎么办"可以）。
- 合规红线：躺赚、稳赚、月入、百分百、暴利、纯利润、零成本、白嫖、包上热门；加微信、私信、扣1、主页链接。
- 过程话：原文里、资料里、截图显示、根据你提供的、选题卡上写着。
- 连着三句用"我"开头；免责说两次；每段都用反问收尾。
- 「广告」这类标记（员工自己加）。

完整用词表：`docs/用户校准词表.md`（用户和员工点名改过的词，禁 → 换）；完整规则：`docs/写稿规则.md`。这两份你只读不改，下一步的检查命令会替你逐条对。

## 5. 写短稿（每篇 280–340 汉字，60–90 秒）

照 `docs/短视频规格.md`，要点：
- **前两句里必须有"闲鱼"和一个闲鱼上的数**（想要人数/浏览/标价，来自数据摘要）。第一句就是钩子，讲观众想要的（少走弯路、省心、搞钱）或"我"的态度，项目名压到句尾或第二句揭晓。
- 讲述人永远是"我"（做了很多年闲鱼的圣矾）：我的做法是、我一般会。不写"同行说过"。
- 一条只讲一件事；不预告（今天聊聊、我讲三点）；中间不用首先/其次/第一第二；结尾不总结，从这几种里挑：抛问题让人评论 / 一个今天就能做的具体动作 / 说完就停（最后一句是具体的事）。
- **不放收益数字**（一单赚多少、月入都不写；单价、想要人数可以写），不放资料钩子，没有"我是圣矾"和收尾句。
- 同一选题的短稿和长稿开头也不能一样。

## 6. 自检（每篇都跑；输出先写进文件再看，别接 `| tail`）

长稿：
```
npm run check:draft -- <稿> --topic <选题> --topic-type 虚拟 --against "//Zqkj_nas/一楼4t/素材生成库/ai文案/已审" <同题其他篇和以前交过的同题稿>
```
- 看表里级别是「退回」且结果是「命中」的行，逐条改到零。「提示」的不用改，抄进说明.md。
- 撞的是固定句（我是圣矾 / 学闲鱼，找圣矾 / 催赞句 / 交底句 / 合规句 / "最后圣矾给大家整理了" / 收尾句）不用改。
- 标「人工」的行你自己对：R013/R014 = 卡片「不能说的」一条没进稿、卡片没有的数一个没进稿；R020 零头取整；R025/R026 话说全、人话；R039 没编人和钱；R044 同题各篇不共享例子和说法；R050 没比喻没造词。
- 英文字母命中（R018）如果是软件名，保留，说明.md 里写一句。

短稿：
```
npm run check:compliance -- <稿>
npm run check:draft -- <稿> --topic <选题> --topic-type 虚拟 --against "//Zqkj_nas/一楼4t/素材生成库/ai文案/已审" <同题其他篇>
```
- check:compliance 必须 PASS。check:draft 里 R002–R007、R010、R011 是长稿规矩，短稿忽略（所以短稿的退出码会是 1，看表不看退出码），其余退回级照改。

最后照 `docs/审稿清单.md`（一页）自己从头读一遍稿。最多改两轮；两轮还有退回级就停，把剩下的命中写进说明.md 交回，不要硬凑。

## 7. 交付

NAS：`\\Zqkj_nas\一楼4t\素材生成库\ai文案\待审文案\<YYYYMMDD>-<选题>\`，里面放：
- 稿子，每篇一个 txt，UTF-8，只有口播正文，一句一行，不带标题和说明：
  - 长稿 `<YYYYMMDD>-<选题>-长A-<开头角度>.txt`、`…-长B-…`
  - 短稿 `<YYYYMMDD>-<选题>-短A-<开头角度>.txt`
  - 文件名里的开头角度去掉符号（提问极简回答展开、断言推演）。文件夹已存在就接着往后排字母，不覆盖任何已有文件。
- `素材\`：整个复制 topic-scan 的产物（scan.json、shots、数据摘要.md）。
- `说明.md`：区分表 + 每篇一段：字数和句数；引用的每个数 → 稿里原句 → 数据摘要哪一行 → 哪张截图；用了卡片哪条经历；检查结果（退回几条、改了几处、留下的提示）；你拿不准的句子（最多三句）。

本机工作目录里的稿子不要再动，它是登记用的原件。

## 8. 登记（每篇一条）

```
node engine/return/registry.mjs add --id <YYYYMMDD>-<选题>-长A --version v1 --topic <选题> --film <选题拼音，小写连字符> --draft research-runs/每日/<YYYYMMDD>-<选题>/<文件名>.txt --factcard research-runs/每日/<YYYYMMDD>-<选题>/选题卡.txt --assets research-runs/每日/<YYYYMMDD>-<选题>/素材 --angle <开头角度> --date <YYYY-MM-DD> --note "写稿模型 gemini；长稿|短稿；NAS <交付路径>"
```
短稿 id 用 `…-短A`。员工改回来的稿就是靠这张表认出来的（按内容比对），所以每篇都要登，`--draft` 指本机原件。

## 9. 回报（给调用者）

每个选题：交付路径、每篇字数、检查结果、查不到或停下的原因、说明.md 里"拿不准的句子"。不贴全文。

## 你不做的事

- 不 git commit、不 git push、不推 GitHub。
- 不改 `docs/写稿规则.json`、`docs/用户校准词表.json`，也不改 `docs/` 下其他规则文件和 `engine/` 下的代码；觉得哪条规矩不对，写进说明.md 的"建议"一节，由用户定。
- 不动视频仓库 `D:\项目仓库\remotion视频制作`，不做配音、分镜、出片。
- 不覆盖、不删除 NAS 上已有的任何文件；只往当天新建的选题文件夹里写。
- 查不到数据、卡片缺关键内容、同一个问题连着失败两次：停下回报，不编、不反复重试。
