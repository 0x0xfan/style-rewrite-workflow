# short-video · 短视频口播稿

规则唯一真身：`docs/短视频规格.md`（v1，2026-09-24 用户定）。本文件只讲**怎么干**；规格和本文件冲突时以规格为准，并在报告里指出冲突。
**观众是小白**：不懂闲鱼、想赚钱的人，不是已经在闲鱼卖货的人，写的时候不预设观众已经在跑这个项目。

## 0. 开工前问清（没说的才问，一次问完）

1. 哪一类：**SRT 改写**（讲产品）还是**知识分享**（讲知识点）。
2. 写哪些、写几条：用户点名选题，或者让你挑（挑的话先把候选列给用户点头）。
3. 放哪：先写在 `scratch/短视频-<YYYYMMDD>/`；验收后交付到 NAS `Z:\素材生成库\ai文案\待审文案\<选题>\`（用户 2026-09-28 改：不再分 `短\` 子目录，文件夹名不带期号/日期前缀，跟长稿共用同一层），文件名 `<期号>-<选题>-<MMDD>-<骨架>.txt` + 同名 `.素材.md`（唯一允许跟正稿放一起的资料），不覆盖已有文件；`说明.md`、批次说明放资料区 NAS `Z:\素材生成库\ai文案\资料\<选题>\`（中控台不扫这里），批次说明文件名不带前导下划线（如 `<MMDD>-<批次>-说明.md`）。

风格固定：圣矾本人口吻、钱十七线，不用再问"用谁的风格"。

## 1. 先读（每次都读，按顺序）

1. `docs/短视频规格.md` —— 全部规矩，逐条遵守。
2. `examples/` 下 6 条用户认可的样稿（A1–A3 是 SRT 类，B1–B3 是知识类）。**学结构和口气，不抄句子、不抄事实**。
3. `docs/用户校准词表.md` —— 用户/员工点名改过的词，命中就改。
4. `docs/写稿规则.md` —— 只看用词、话说全、人话类规则；长稿结构规则（R002–R007、R010、R011）短视频不适用。
5. `docs/圣矾真实经历清单.md` —— "我"的经历只能从这里或该期 SRT 里取。

## 2. 取材

**SRT 类**
- SRT 根目录 `//Zqkj_nas/一楼4t/办公/B站方面/缩放-剪辑导出/`；每期 SRT 相对路径、选题、`research-runs` 目录见 `docs/批量出稿-工单模板-20260910.md` 第六节总表。
- 必须读那期 SRT 原文；SRT 里没有闲鱼想要/浏览/标价数据时，必须去 `research-runs/<期>/事实卡-终版.md` 找闲鱼实采数据。事实以 SRT 为准。
- SRT 里用户亲口说的单价、设置值、"想要"人数可以写；月入、赚了多少这类收益数字短视频里不写。
- **选数字时先查有没有截图**：视频项目素材池 `D:/项目仓库/remotion视频制作/ips/xianyu-fanshen/assets/manifest.json`，`images[]` 里 `path` 含 `assets/<filmId>/` 的就是这一期的图，`description` 写了图上有什么数。同一件事有几个数可选时，优先用素材池里有截图能对上的数。filmId 查工单模板第六节总表。

**知识类**
- 入口 `docs/真人语料包/总表.md`，只用"可用"堆（不用内部 / 重复 / 招生晒收入）；原文在 `D:\项目仓库\闲鱼知识库\cleaned\`，写之前必须读原文。
- 选实操型知识（上架、搜索、链接维护、避坑）；不选只在某次平台新规下才成立的、要当期数据才成立的、和用户自己教的做法冲突的（比如叫人别用自动发货）。
- 文章里的数字、平台结论没核实就不写数，只讲做法和道理。
- 按适用标签过滤：用闲鱼经验库的条目时只从 `node engine/brief/pick-experience.mjs --subtype <本期虚拟子类>` 的候选清单里挑（实物专用、🚫 都已剔除）；语料包条目「品类」是实物专用的不用。

**先查素材库**：这个品在视频项目素材库有 `topic.json` 或用户上传的图（`source=manual`），先用用户的图和关键词，规矩照 daily-write 第 4 节素材顺序第 2 条；用户说过"二次整理"的，补来的图也在那里（`.claude/skills/material-organize/SKILL.md`）。

**要去闲鱼实搜（topic-scan）时**，搜索词怎么定、搜完怎么对题核对，按 `.claude/skills/daily-write/SKILL.md` 第 4 节两条规矩来，不再重复。

**要用百度需求佐证 / 货源证据 / 教程演示时**，按 `.claude/skills/daily-write/SKILL.md` 第 4.2 节的规矩来（只搜公开页面截图、对题核对、网址不上屏）；缺百度/谷歌需求截图时同样按那一节写 `<slug>/_inbox/shot-requests.json` 发请求，不自己硬搜，也读该选题 `topic.json` 的 `shotRequests[]`（`status:"done"` 的图优先用）。

## 3. 排组合表（写之前）

每条定：素材 → 骨架（A1/A2/A3 或 B1/B2/B3，按素材挑合适的）→ 开头结构（规格开头菜单 1–7）→ 结尾（结尾菜单 1–5）。

- 同一开头 10 条内 ≤2 次；相邻两条开头、结尾都不同；骨架轮到。
- 开头 2 资历+唯一、3 向往+卖点连发、4 门槛+承诺 要用"我"的经历，先在经历清单/SRT 找到依据再排；找不到就换结构。
- 写 5 条及以上时，先把组合表给用户看，用户点头再写（用户说"直接写"就不停）。

## 4. 写（每条都对一遍）

- 280–340 字（汉字），一句一行，一条只讲一件事。
- **讲闲鱼、讲数据**：前两句里必须出现"闲鱼"和至少一个闲鱼数据（想要人数/浏览数/标价），来自 SRT 或 `research-runs/<期>/事实卡-终版.md` 的闲鱼实采；都没有就停下报告，不写这条。
- **第一句就是钩子**：讲观众想要的（搞钱、少走弯路、省心）或"我"的态度，项目名/知识点压到句尾揭晓；产品细节放在开头之后。
- **讲述人是"我"**：做法和道理用"我的做法是""我一般会"；不写"同行 X 说过""我看同行的做法"，不点同行名字；别人的踩坑故事写成"我见过很多人……"，不编"我踩过"。
- 不预告（"今天聊聊""我讲三点"）；中间不用"首先/其次/接下来/第一第二"；结尾不总结。
- 结尾不写"把这条转给他"类转发句；不用"不是……而是……""从来不是……只是……"这类句壳（开头、结尾都不用）。
- 直接承诺换软：不写"回来感谢我/大搞一笔/搞到米/99%/躺赚/稳赚"；不带月份、"暑假"这类时间词；不放资源引流。
- 话说全：保留"之后/的话/如果/同时"这类连接词和主语；不用比喻、黑话、我们内部术语（红条/口子/规则卡等）。
- 观众稿里不出现过程话（"原文里""SRT 里""资料里""根据你提供的"）。
- "其实/说白了/关键是/你想想"一批里每个 ≤1 次。
- 软件名照用户平时念法写（Obsidian 就写 Obsidian）。

必须 PASS（block 0）。

```bash
npm run check:draft -- <稿> --topic <选题> --topic-type 虚拟
```
- 忽略 R002–R007、R010、R011（长稿结构规则），其余命中照改。
- R040 连抄如果撞的是圣矾本人语料（`K-说-H-圣矾-*`），不算抄，保留原话。
- R018 英文字母撞的是软件名，保留，报告里注明。

最多改两轮；两轮还过不了就停，写进报告交回。

## 5b. dbs 审稿（每条都做，机器检查过了再做）

1. 按 `.claude/skills/dbs-hook/SKILL.md` 诊断开头（只做 Phase 2–3 诊断 + Phase 4 的方法一"素材提取"、方法三"悬念制造"，**不做方法二"素材增补"**，备选开头 ≤5 条）。重点看：开头钩的问题是不是正文主体在回答的问题。
2. 按 `.claude/skills/dbs-script-flow/SKILL.md` 查衔接和口播（纯口播，只出报告不做标记式改稿）。
3. 按规格筛建议：编数据/经历、晒收益、大佬背书、转发理由、加总结句或金句收尾、"不是……而是……"——一律不采纳。
4. 采纳的建议改进稿子，改完重跑第 5 步的 check:compliance。
5. 审稿要点写进 `说明.md`（每条：开头诊断一句话、采纳了什么、否掉了什么）。
6. **留证据**：把 dbs 的原始输出原样贴进 `说明.md` 的「dbs 原始诊断」一节——dbs-hook 的「当前开头诊断」六项表（独立性/Hook/悬念/可信度/口播友好/匹配度）和备选开头表，dbs-script-flow 的「段落结构」表和「问题清单」（带原句引用）。**没贴原始诊断就算这一步没做。**
7. "否掉了什么"只能写 dbs 实际提出过的建议（能在原始诊断里找到），不许照本节第 3 条的清单凑数；dbs 提出但你没改的问题，要写明原因（比如与规格冲突、SRT 没依据）。

## 5c. 素材对照（给视频项目用，每条都做）

视频项目只出**竖屏 9:16**短视频（用户 2026-09-24 定），做分镜时要知道每句配哪张图。每条稿另出一份 `<序号>-<选题>-<骨架>.素材.md`：

```markdown
# <选题> 短视频素材对照
filmId: <filmId>
稿件: <序号>-<选题>-<骨架>.txt
画幅: 竖屏 9:16

| 句 | 原句 | 画面素材（manifest 里的 path） | 为什么用这张 |
|---|---|---|---|
| 1 | …… | ips/xianyu-fanshen/assets/<filmId>/screenshots/xx.png | 图上能看到"xxx人想要" |
| 2 | …… | （无，口播过渡） | |

## 缺图
- 第 N 句"……"：稿里的数/画面素材池里找不到对应截图
```

- 稿子里每一个闲鱼数据（想要/浏览/标价）都必须配上能看到这个数的截图；找不到就列进「缺图」，并在报告里写明。不许配一张数字对不上的图。
- 只引用 manifest 里已有的 path，不新建、不改名、不动视频仓库。
- 竖屏手机截图宽度 <1000px 的，在"为什么用这张"里注明"不得放大"。

- 每条一个 txt：`<期号>-<选题>-<MMDD>-<骨架>.txt`，纯口播正文，一句一行，UTF-8。
- 每条一个同名 `.素材.md`（见 5c）——唯一允许跟正稿放一起的资料。
- 文件名开头不能是下划线。

资料 → NAS `资料\<选题>\`（中控台不扫这里）：
- `说明.md`：一张表，列：序号｜选题｜素材路径｜骨架｜开头结构｜开头依据（经历清单编号或 SRT 原话）｜结尾｜字数｜check 结果；表下每条列出"超出原文的推断句"和"待用户确认的事实"。
