规则唯一真身：
- **v2.0 事实驱动版（优先，已完成 S0 升级的选题）**：`docs/短视频规格-v2.md`（2026-10-15 用户定，全案分镜 JSON + 视听错位 + 4 大红线 + 5 幕结构，支持 1~3 分钟 300~850 汉字随机梯次）。

## 2.0 v2.0 事实驱动型工作流 (S0 升级选题专用)

### 1. 读取与组装事实上下文
运行或读取上下文构建器：
```bash
node engine/draft/build-v2-context.mjs --topic <slug>
```
严格解析三份核心文件：
- `deconstruct.json`：确定商业交付模型（6 大模型），查看 2~3 个 `angleCandidates`（候选切入点菜单）。
- `facts.json`：获取真实数据白名单（`baiduTrend`, `shopScale`, `subNiches`, `autoDelivery`）、对应的归一化 ROI 坐标及 `sensoryTranslation`（生活化体感金句）。
- `sourcing.json`：获取以买代采指南与拿货履约逻辑。

### 2. 贯彻四大不可违背的写作红线
1. **红线 1 (点菜制准则)**：必须且只能在 `deconstruct.json.angleCandidates` 中选择 1 个候选角度！严禁脱离素材库私自臆造角度。
2. **红线 2 (零幻觉白名单准则 / D-040)**：口播中出现的任何数字（搜索量、销量、好评率、客单价）必须 100% 取自 `facts.json`。**严禁张冠李戴**：店铺历史总销量绝不能说成是单款销量！
3. **红线 3 (视听错位法则)**：耳朵听反常识冲突、生活化痛点（优先使用 `sensoryTranslation`）；眼睛看高清原图与 Remotion 聚光灯/红框对准真实数字！拒绝嘴里念数字、画面也只打数字。
4. **红线 4 (画面素材三级铁律 / D-041)**：每一幕必须绑定切实存在的截图路径 `visualAsset`，涉及数据严禁用纯文字大字卡占位！

### 3. 按 5 幕黄金叙事结构创作 (30~60s)
- **S01 黄金 3 秒钩子 (`HOOK_BREAK_BIAS`)**：采用选中角度的 `hookLine`，打破重资产偏见，抛出反常识利益点。
- **S02 大盘刚需确权 (`MARKET_VALIDATION`)**：用百度大盘体感转译金句暴击，证明绝非自嗨。
- **S03 商业实力与细分长尾 (`COMMERCIAL_PROOF_AND_NICHES`)**：亮出真实店铺累计销量，揭秘闲鱼搜索下拉长尾蓝海。
- **S04 极速履约与以买代采 (`SOURCING_AND_AUTO_DELIVERY`)**：揭秘以买代采去广告，挂自动发货机器人秒发。
- **S05 破局行动号召 (`CALL_TO_ACTION`)**：总结轻资产无库存本质，给出新手第一步，点赞收藏，收尾「学闲鱼，找圣矾。」。

### 4. 机器自检与双轨导出
输出 `<slug>-script.json` 后，运行专用校验门禁并导出口播正文与素材对照：
```bash
npm run check:script-v2 -- <slug>-script.json --topic <slug> --export-txt <YYYYMMDD>-<选题>-<skin>-v.txt --export-material <YYYYMMDD>-<选题>-<skin>-v.素材.md
```
必须 PASS（0 error）。校验通过后生成同名 `.meta.json` 并交付至 NAS。

## 4. 写（每条都对一遍）

- 300–600 字（汉字），约 1–2 分钟（用户 2026-09-29 定，原 280–340 字作废），一句一行。
- **先钉理解**（见规格「动笔前先把理解钉死」）：每条先写"这条讲什么生意"（照抄选题核心「卖什么」+类型），前两句说的生意必须跟它一致；产品题站在"他还没做，我介绍一门生意"的立场，不用"大部分新手都卡在……""多数人怎么做"这类默认对方在做的写法（这类开头只给知识题、真人出镜口播）。写完自检两问，答案写进说明.md：①开头的生意 = 那一句吗？②有没有一句默认观众已经在做？③**前后矛盾**：前面说的钱怎么赚、价怎么定、货怎么来，后面有没有自己推翻（用户 2026-10-02 指剪映 pixel-arcade-v：「你前面讲了卖低价是要靠网盘拉新赚钱，后面又说做高价，前后矛盾。短视频文案你也改改吧」）？三问任一不过就改。
- **一条讲完一个最小闭环**（用户 2026-10-02 定，见规格「总规矩」）：产品题必须交代 ①什么生意、钱从哪来 ②谁买、为什么 ③货/工具从哪来、怎么交付 ④一个关键做法（重点）⑤新手第一步；知识题交代 ①什么问题、谁碰到 ②为什么 ③怎么做（重点）④做对/做错的结果 ⑤新手第一步。写完逐条对一遍，缺一样就补，交付说明里每条标出这五样各在第几句。不许只讲一个细节就收。五样里哪样的事实在 SRT / 选题核心 / 资料里都找不到（常见是"货从哪来"），不编，在说明.md 和报告里列为"缺的事实"，交主会话问用户补一句原话。
- **讲闲鱼、讲数据**：前两句里必须出现"闲鱼"和至少一个闲鱼数据（想要人数/浏览数/标价），来自 SRT 或 `research-runs/<期>/事实卡-终版.md` 的闲鱼实采；都没有就停下报告，不写这条。
- **结尾三步**（用户 2026-10-02 定，见规格「结尾三步」）：新手第一步之后 → 收拢一句 → 自我包装（只说自己是做闲鱼的；不说自己做过本题项目、不报自己号的单量）→ 最后一行「学闲鱼，找圣矾。」。不放彩蛋、不扣关键词。
- **第一句就是钩子**：讲观众想要的（搞钱、少走弯路、省心）或"我"的态度，项目名/知识点压到句尾揭晓；产品细节放在开头之后。
- **讲述人是"我"**：做法和道理用"我建议""你可以"；不说自己在做本题这个项目（不写"我一般会挂…""我的做法是…"），身份只说"做闲鱼的"；不写"同行 X 说过""我看同行的做法"，不点同行名字；别人的踩坑故事写成"我见过很多人……"，不编"我踩过"。
- **从同行买来的现成货，不教自己逐个核对（用户 2026-10-03 定）**：资料、模板、工程、安装包这类从同行手里买来再转卖的货，不写"买回来每一套先自己打开检查一遍""装到自己手机上从头走一遍""素材字体都看一遍再发"这类自检步骤，也不把它当成卖得好的关键。这门生意本来就简单：从同行买、分开挂、拍下自动发。把简单的事讲复杂就是讲偏。用户原话：「这种纯卖资料类的产品没必要自己再去一个一个核对，因为这些资料都是直接从同行那儿买过来的。所以，你这样写的话，其实会让原本很简单的事变得很复杂。」
- 不预告（"今天聊聊""我讲三点"）；中间不用"首先/其次/接下来/第一第二"；结尾不总结。
- 结尾不写"把这条转给他"类转发句；不用"不是……而是……""从来不是……只是……"这类句壳（开头、结尾都不用）。
- 直接承诺换软：不写"回来感谢我/大搞一笔/搞到米/99%/躺赚/稳赚"；不带月份、"暑假"这类时间词；不放资源引流。
- 话说全：保留"之后/的话/如果/同时"这类连接词和主语；不用比喻、黑话、我们内部术语（红条/口子/规则卡等）。
- 观众稿里不出现过程话（"原文里""SRT 里""资料里""根据你提供的"）。
- "其实/说白了/关键是/你想想"一批里每个 ≤1 次。
- 软件名照用户平时念法写（Obsidian 就写 Obsidian）。

7. "否掉了什么"只能写 dbs 实际提出过的建议（能在原始诊断里找到），不许照本节第 3 条的清单凑数；dbs 提出但你没改的问题，要写明原因（比如与规格冲突、SRT 没依据）。

## 6. 交付

正稿 → NAS `待审文案\<选题>\`（见第 0 节）：
- 每条一个 txt：`<期号>-<选题>-<MMDD>-<骨架>.txt`，纯口播正文，一句一行，UTF-8。
- 每条一个同名 `.素材.md`（见 5c）——唯一允许跟正稿放一起的资料。
- 文件名开头不能是下划线。

资料 → NAS `资料\<选题>\`（中控台不扫这里）：
- `说明.md`：一张表，列：序号｜选题｜素材路径｜骨架｜开头结构｜开头依据（经历清单编号或 SRT 原话）｜结尾｜字数｜check 结果；表下每条列出"超出原文的推断句"和"待用户确认的事实"。

**按账号交付（用户 2026-09-29 定；daily-plan 派的活一律照这个，上面的 `<期号>-<选题>-<MMDD>-<骨架>` 命名只用于没指定账号的老用法）：**
- 竖版皮肤稿：`<YYYYMMDD>-<选题>-<skin>-v.txt` + 同名 `.meta.json` + 同名 `.素材.md`：
  ```json
  {"skin":"lime-capsule","orientation":"v","lengthTarget":"1-2min","date":"2026-09-29","topicSlug":"c-pan-qing-li","title":"C盘清理"}
  ```
- 真人出镜：`<YYYYMMDD>-<选题>-selfie-<NN>.txt`（NN 是当天第几篇真人出镜：01/02/03）+ 同名 `.meta.json`，不放 `.素材.md`：
  ```json
  {"kind":"selfie","orientation":"v","lengthTarget":"1-2min","date":"2026-09-29","title":"新手标题怎么写才搜得到"}
  ```
- `.meta.json` 和正稿同名只换扩展名（`xxx.txt` 配 `xxx.meta.json`）；UTF-8 不带 BOM；用 node 写、写完 `JSON.parse` 读一遍。`skin` 照派单抄（拼错中控台配不上账号也不报错）；`topicSlug` 是素材库 slug，素材库没有就不写这个字段；真人出镜不写 `skin`、`topicSlug`。
- 骨架、开头结构写进说明.md 的表，不再放进文件名。同名文件已存在末尾加 `-2`，不覆盖。完整规矩见 `.claude/skills/daily-plan/SKILL.md` 第 5 节。
- 这类活要登记：**不自己跑** registry、不改台账（并行批次会互相覆盖），在报告里交主会话三样：
  1. registry 命令：`node engine/return/registry.mjs add --id <正稿文件名去掉 .txt> --version v1 --topic <选题> --film <topicSlug，没有就选题拼音> --draft <本机 scratch 里的原件> --angle <骨架+开头结构> --date <YYYY-MM-DD> --note "写稿模型 <模型>；<短稿|真人出镜>；账号 <skin>-v（真人出镜写 selfie-<NN>）；lengthTarget 1-2min；骨架 <骨架>；NAS <正稿完整路径>"`
  2. `docs/每日/账号选题台账.md` 对应账号那一节要追加的一行（日期｜选题｜topicSlug｜稿件文件名｜存稿）。
  3. 用了"来之不易"故事的，`docs/每日/故事登记.md` 要追加的一行（没用就写"无"）。
