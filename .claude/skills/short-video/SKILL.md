# short-video · 短视频口播稿

规则唯一真身：`docs/短视频规格.md`（v1，2026-09-24 用户定）。本文件只讲**怎么干**；规格和本文件冲突时以规格为准，并在报告里指出冲突。

## 3. 排组合表（写之前）

每条定：素材 → 骨架（A1/A2/A3 或 B1/B2/B3，按素材挑合适的）→ 开头结构（规格开头菜单 1–7）→ 结尾（结尾菜单 1–5）。

- 同一开头 10 条内 ≤2 次；相邻两条开头、结尾都不同；骨架轮到。
- 开头 2 资历+唯一、3 向往+卖点连发、4 门槛+承诺 要用"我"的经历，先在经历清单/SRT 找到依据再排；找不到就换结构。
- 写 5 条及以上时，先把组合表给用户看，用户点头再写（用户说"直接写"就不停）。

## 4. 写（每条都对一遍）

- 300–600 字（汉字），约 1–2 分钟（用户 2026-09-29 定，原 280–340 字作废），一句一行。
- **先钉理解**（见规格「动笔前先把理解钉死」）：每条先写"这条讲什么生意"（照抄选题核心「卖什么」+类型），前两句说的生意必须跟它一致；产品题站在"他还没做，我介绍一门生意"的立场，不用"大部分新手都卡在……""多数人怎么做"这类默认对方在做的写法（这类开头只给知识题、真人出镜口播）。写完自检两问，答案写进说明.md：①开头的生意 = 那一句吗？②有没有一句默认观众已经在做？
- **一条讲完一个最小闭环**（用户 2026-10-02 定，见规格「总规矩」）：产品题必须交代 ①什么生意、钱从哪来 ②谁买、为什么 ③货/工具从哪来、怎么交付 ④一个关键做法（重点）⑤新手第一步；知识题交代 ①什么问题、谁碰到 ②为什么 ③怎么做（重点）④做对/做错的结果 ⑤新手第一步。写完逐条对一遍，缺一样就补，交付说明里每条标出这五样各在第几句。不许只讲一个细节就收。五样里哪样的事实在 SRT / 选题核心 / 资料里都找不到（常见是"货从哪来"），不编，在说明.md 和报告里列为"缺的事实"，交主会话问用户补一句原话。
- **讲闲鱼、讲数据**：前两句里必须出现"闲鱼"和至少一个闲鱼数据（想要人数/浏览数/标价），来自 SRT 或 `research-runs/<期>/事实卡-终版.md` 的闲鱼实采；都没有就停下报告，不写这条。
- **结尾三步**（用户 2026-10-02 定，见规格「结尾三步」）：新手第一步之后 → 收拢一句 → 自我包装（只说自己是做闲鱼的；不说自己做过本题项目、不报自己号的单量）→ 最后一行「学闲鱼，找圣矾。」。不放彩蛋、不扣关键词。
- **第一句就是钩子**：讲观众想要的（搞钱、少走弯路、省心）或"我"的态度，项目名/知识点压到句尾揭晓；产品细节放在开头之后。
- **讲述人是"我"**：做法和道理用"我建议""你可以"；不说自己在做本题这个项目（不写"我一般会挂…""我的做法是…"），身份只说"做闲鱼的"；不写"同行 X 说过""我看同行的做法"，不点同行名字；别人的踩坑故事写成"我见过很多人……"，不编"我踩过"。
- 不预告（"今天聊聊""我讲三点"）；中间不用"首先/其次/接下来/第一第二"；结尾不总结。
- 结尾不写"把这条转给他"类转发句；不用"不是……而是……""从来不是……只是……"这类句壳（开头、结尾都不用）。
- 直接承诺换软：不写"回来感谢我/大搞一笔/搞到米/99%/躺赚/稳赚"；不带月份、"暑假"这类时间词；不放资源引流。
- 话说全：保留"之后/的话/如果/同时"这类连接词和主语；不用比喻、黑话、我们内部术语（红条/口子/规则卡等）。
- 观众稿里不出现过程话（"原文里""SRT 里""资料里""根据你提供的"）。
- "其实/说白了/关键是/你想想"一批里每个 ≤1 次。
- 软件名照用户平时念法写（Obsidian 就写 Obsidian）。
