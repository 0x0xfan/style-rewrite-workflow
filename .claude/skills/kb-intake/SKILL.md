# kb-intake · 新文章入库工作流

目标：`cleaned/` 里每一篇没进过台账的文章，最后都在 `docs/真人语料包/intake-ledger.json` 里有一条定案（已入库 + 分表名，或已丢弃 + 一句理由），可用的那些变成 `docs/真人语料包/part-inbox-<日期>.md` 里的条目，并合进 `总表.{json,md}`；同一批文章里的玩法、做法、坑，转述成经验条目，贴好适用标签，追加进 `docs/闲鱼经验库/`（第 ③b 步）。

## 先读（每次都读，不凭记忆）

1. `docs/真人语料包-抽取口径.md` —— 抽什么、怎么标。全文不长，逐字读。
2. `docs/真人语料包/part-2.md` 前 80 行 —— 分表格式（表头、编号、⓪ 的用法）。新分表照这个格式写，表头一个字都别改（合表脚本按表头名取列）。
3. `docs/真人语料包/总表.md` 的「使用须知」十条 —— 合表时机器会做的事（品类重判、效果倍数删除、防审查还原、去重），抽的时候心里有数。
4. `DECISIONS.md` 2026-09-08 那一行 —— 用户定的规矩原话。
5. `docs/闲鱼经验库/总表.md` 第 0 节「使用须知」+ `适用标签.json` 前几条 —— 第 ③b 步的口径和标签格式。

## 三个角色

- **脚本**：`engine/corpus-pack/intake-triage.mjs`（找新文件、粗分、写台账、抽查）、`engine/corpus-pack/merge-pack.mjs`（合表）。
- **执行者**（跑这个 skill 的会话 / worker）：定夺"招生晒收入?"堆、逐篇抽取、写分表、跑脚本、写报告。
- **用户**：看抽查报告和统计，点头后才 commit；拿不准的条目由用户裁。

## 步骤

### ① 找新文章（脚本）

```powershell
node engine/corpus-pack/intake-triage.mjs                 # 列 cleaned/ 里不在台账 entries 的文件，并粗分
node engine/corpus-pack/intake-triage.mjs --since last    # 只看台账「更新」日期之后改动的（或 --since 2026-09-10）
```

已入库 / 已丢弃的以台账 `entries` 为准，脚本只列不在里面的。输出按堆分组：可用 · 招生晒收入? · 重复 · 内部，每篇带作者猜测（正文"大家好我是 XX"，没有就按公众号 `__biz` 查台账里同号的作者，会标"按公众号 ID 猜的"）、字数、粗分理由。输出"未入库 0 篇"就到此为止，告诉用户没有新文章。

### ② 分堆（脚本粗分 → 执行者定夺）

```powershell
node engine/corpus-pack/intake-triage.mjs --write-ledger   # 把粗分结果写进台账 pending 区
```

粗分规则（脚本已按此分，执行者只复核）：

| 堆 | 判据 | 处置 |
|---|---|---|
| 内部 | `source: local_archive`；文件名 / 标题像模板、JSON/HTML 导出、日报、纯日期、朋友圈复盘、运营方案 | 整篇丢 |
| 重复 | 文件名带 v2 / _full / index；标题、source_ref 或正文与台账 / 本批别的文件相同；正文不足 80 字 | 整篇丢 |
| 招生晒收入? | 标题 + 开头 300 字里的招生 / 晒收入词打分 ≥3，或不足 300 字的短帖 | **执行者逐篇读开头 200 字定夺**（见下） |
| 可用 | 其余 | 进第 ③ 步 |

"招生晒收入?"那一堆的定夺尺子（2026-09-08 主线程分 220 篇时的做法）：

- **整篇丢**：闪光学员、学员出单报喜、陪跑营 / 训练营 / 课程页、合伙人招募、网盘拉新群报喜、"卖 X 赚了 Y"案例贴、货源福利、当日销售额日记。判据一条：把招生和晒收入的句子删掉后，剩下的撑不起一篇文章。
- **剥头尾留正文**：头是"关注我送你五个项目"、尾是"加我微信 / 报名陪跑"，中间是真在讲怎么做（猫KK 那种）。堆写"可用"，`note` 写"剥头尾"。
- **可用**：标题带钱数但正文是讲机制的（韩九《5月复盘》《熬出来的》、陈陈《4个节点》这类），堆写"可用"。

定夺完，直接改台账 `pending` 里每条的 `pile`（内部 / 重复 / 招生晒收入 / 可用，去掉问号）、`author`（脚本猜错的改过来；真不知道写"匿名"）、`reason`（丢的写一句为什么，例：`整篇闪光学员报喜`）。然后转正：

```powershell
node engine/corpus-pack/intake-triage.mjs --finalize --part part-inbox-<日期>
```

`pile` 还带问号的会被拒绝。转正后 `pending` 清空，可用的进 `entries`（status 已入库、part = 你给的分表名），其余进 `entries`（status 已丢弃 + reason）。

粗分不是终审：第 ③ 步抽到一半发现整篇其实是招生晒收入（脚本漏判的，两篇里大概会漏一篇标题只带一个词的），一样丢——把台账里那条 `status` 改成已丢弃、`pile` 改成招生晒收入、写 `reason`，分表里不留它的条目。

### ③ 抽取（执行者，逐篇，按口径）

对"可用"堆逐篇抽，写到 `docs/真人语料包/part-inbox-<日期>.md`，格式同 part-2：标题行写"篇数 + 作者分布"，四节 `## 一、开头层` / `## 二、说法层`（下面 `### 场景 A` … `### 场景 I`）/ `## 三、原声层` / `## 四、作者档案`，文末 `## 统计`、`## 拿不准的条目`、`## 附录 · 文章简称对照`（简称 | 作者 | 文件，**文件名一定写全**，第 ⑤ 步抽查靠它定位原文）。

每篇抽的东西（口径原文为准，这里只列清单）：

- **开头层，只存结构**：切入方式 + "① ② ③"每句干什么（动词开头）+ ⓪ 标自报家门的位置（作者的"大家好我是 XX"不算结构，跳过；招生头也跳过）+ 原文句数（超五步注"口播要压缩"）+ 适合讲什么 + 品类 + 出处。**一个原句都不抄**，线索最多五个字。
- **说法层，原句照录**：按九个场景 A–I 找，每条原句（一到三句，不删不改不转述）、作者、文章简称、亲历（纯措辞 / 含作者亲历）、品类（通用 / 实物专用）、口播（✅ / 图文腔 / ？）、用过的期留空。**收入数字、效果倍数、招生话术不收；句子里夹着的，整句不收。** 自嘲式小数字（"第一个月只赚三百"）可收，标含作者亲历。
- **原声层，原句照录**：买家、学员、厂家、家人、卖家自己回的话，带引号或明显是对话。谁说的、原句、情境一句、品类、出处。
- **作者档案**：新作者写一段（他是谁、怎么说话举一句、擅长讲哪几块、要剥掉什么）；老作者只在有新发现时补一行，表格列名与 part-2 一致。

编号：`K-开头-作者-序号` / `K-说-场景字母-作者-序号` / `K-声-作者-序号`。**作者已经在总表里的，序号从总表该作者的最大序号 +1 起编**（`总表.json` 里搜 `"id": "K-说-E-韩九-`），别从 01 重来。合表后 inbox 里老作者的条目编号会带 `·pinbox-<日期>` 后缀（脚本对"同一作者跨分表"的统一处理，part-4 的 `·p4` 同理），这是正常的，原编号存在 `原编号` 字段里。

品类判据一条：这句话离了实物就不成立（退货、运费、快递、物流、品控、面单、囤货、包邮、运费险、七天无理由、签收、破损、发货慢）才标实物专用；否定句里的实物词（"不用囤货"）算通用。口播判据一条：一个闲鱼博主对着镜头会不会这么说；四字成语堆叠、对仗、书面比喻、超五十字长句标图文腔；拿不准标"？"。

防审查写法（🔗、💧、dan、Li、feng、lian接）**照录**，合表脚本会还原。原文错别字照录。

### ③b 抽经验条目，追加进闲鱼经验库（执行者，逐篇）

`docs/闲鱼经验库/` 是写稿时"干货单"的来源（daily-write 第 4.2 节用 `engine/brief/pick-experience.mjs` 从这里挑）。它是 2026-09-06 一次性从 220 篇文章人工抽出来的，**没有脚本，也不会自己长**；新文章不走这一步，就永远进不了经验库。所以第 ③ 步抽完语料包，同一批"可用"文章再过一遍这一步。

**口径跟第 ③ 步反过来：这里要转述成一句话，不录原句。** 以 `docs/闲鱼经验库/总表.md` 第 0 节「使用须知」为准，先读一遍，要点：
- 只抽玩法机制、做法、坑、判断（类型五选一：机制 / 做法 / 判断 / 坑 / 数据）；环节十一选一：选品、养号、上架、引流、客服话术、交付、售后、合规违禁、账号风控、运营心态、其他。
- **收入宣称整层剥掉**：日入、月入、营业额、销售额、利润率、回本周期，一个不留；效果数字（"一周曝光破万"）也剥。
- 进稿标记：✅ 可当行业常识用；⚠️ 原句带收入或效果数字、或口径存疑，剥完能用，**备注写清剥了什么**；🚫 纯收入宣称、拉人头、教违规或侵权操作，照样记下但只当反面例子。
- 条目是同行说的，不是用户的经历，别写成"我"。

**1. 写分表** `docs/闲鱼经验库/part-inbox-<日期>.md`，表头照 `part-00.md` 一字不改：`| 编号 | 经验一句话 | 环节 | 类型 | 出处 | 原文短引 | 进稿标记 |`；编号 `PI<YYYYMMDD>-001` 起；原文短引三十字以内；文末附录列本批每篇的文件全名。

**2. 并进总表**（手工追加，只追加，不重排老编号）：
- 先在 `总表.json` 同环节里找意思相同的老条目。有 → 不新建，只改这条的 `来源`（加上 PI 编号）和 `支持数`（按不同文章数 +1），标记按"组里有 🚫 整组 🚫、有 ⚠️ 整组 ⚠️"重算。
- 没有 → 新编号 `X-<环节简称>-<该环节最大序号+1>`（简称：选品 / 养号 / 上架 / 引流 / 客服 / 交付 / 售后 / 合规 / 风控 / 心态 / 其他），字段跟老条目一样（id、环节、类型、经验、支持数、来源、标记、备注），追加到 `总表.json` 末尾；`总表.md` 对应环节表格末尾加一行，改该节标题的条数和第 0 节"一行统计"。
- 跟老条目意思相反的，写进本批报告"拿不准的条目"，由用户定要不要进第 2 节冲突表。

**3. 同时贴适用标签**：每个新 X 编号在 `适用标签.json` 末尾追加一条，字段和取值跟已有条目完全一样：
- `适用`：通用 / 实物专用 / 虚拟专用（判据：离了实物就不成立 → 实物专用；只在虚拟品上成立 → 虚拟专用；其余通用）
- `虚拟子类`：从 资料类 / 代办服务类 / 软件账号类 里选适用的；实物专用写 `[]`
- `换说法`：要把实物词换成虚拟说法才能用的，写 `实物词→虚拟说法`；不用换就空
- `把握`：高 / 低；`理由`：一句话
- **把握写"低"的，同时追加到 `适用标签-待用户确认.md` 的表里（"你选"一栏留空），交用户定。** 用户定了以后照他的改 `适用标签.json`。
- 老条目只是支持数加一的，标签不动。

**4. 核对**（三条都过才算完）：
```powershell
node -e "const T=require('./docs/闲鱼经验库/总表.json'),G=require('./docs/闲鱼经验库/适用标签.json');console.log(T.length,G.length)"   # 两个数相等
node engine/brief/pick-experience.mjs --subtype 资料类 --out <临时文件>      # 抬头"没贴标签 0"
```
另两个子类（代办服务类、软件账号类）各跑一次，抬头也都是"没贴标签 0"；再从新条目里抽五条，回原文看剥干净没有（收入数、效果数一个不剩）。

经验库这批改动（分表、总表.json/.md、适用标签.json、待用户确认.md）和语料包一起，等用户看过报告再 commit。

### ④ 合表（脚本）

```powershell
node engine/corpus-pack/merge-pack.mjs
```

脚本扫 `docs/真人语料包/part-*.md`（含 `part-inbox-*`），编号分表在前、inbox 按文件名在后，重新生成 `总表.json` + `总表.md`。看 stdout 里 `before` 多出了你的分表、`after` 三个总数比上次大；有 `列数不对` 报错就是你表格某行少了或多了一个 `|`，按行号改。`manual-overrides.json` 里是人工裁定（子场景、立场、效果倍数保留 / 删除、收入数字改判、品类改判），新条目若被机器误删（效果倍数）或误判品类，把编号加进去再跑一遍，不要改脚本。

### ⑤ 抽查（脚本抽、执行者核、用户看）

```powershell
node engine/corpus-pack/intake-triage.mjs --spotcheck docs/真人语料包/part-inbox-<日期>.md --n 10
```

从说法层 + 原声层随机抽十条原句，去掉标点空格后回原文找整句。`✅` 整句在原文；`△` 只对上片段（你拼了句或改了字，回去看）；`✗` 原文里没有（转述了，必须改回原句或删掉）；`?` 定位不到原文（附录没写文件名）。**十条不全 ✅ 就先改分表再重跑，直到全 ✅ 再报用户。** 报告里贴抽查输出、合表 stdout 的 before/after、分表文末统计，让用户看。用户看过说可以，才 commit（分表 + 总表 + 台账 + CURRENT 一个 commit）。

### ⑥ 收尾（执行者）

- 台账：第 ② 步 `--finalize` 已写；第 ③ 步里丢掉的补改 status / reason；核对 `entries` 条数 = `cleaned/` 里 .md 数（`index.json` 不算）。
- `CURRENT.md` 最上面那个日期段加一行：`kb-intake <日期>：新入 N 篇（作者 …），丢 M 篇，分表 part-inbox-<日期>，总表 开头 x / 说法 y / 原声 z；经验库 新增 a 条、并入老条目 b 条、标签待用户确认 c 条。`（CURRENT.md 只由主会话改：跑这个 skill 的是 worker 时，把这行写进报告交主会话。）
- 报告五项：改动文件清单 / 命令与结果 / 产物路径 / commit SHA（用户点头后才有）/ 剩余风险（拿不准的条目列出来）。

## 不许做的

- 语料包（第 ③ 步）不转述、不总结、不合并、不评价、不补写：原句就是原句，结构就是结构。经验库（第 ③b 步）反过来要转述成一句话，两边别弄混。
- 经验库只追加：不删老条目、不重排老编号、不改老条目的经验文字；老条目只许动 来源 / 支持数 / 标记（按第 ③b 步）。标签拿不准的不自己拍板，交用户。
- 开头层不抄原句；说法层、原声层不收收入数字、效果倍数、招生话术（整句不收）。
- 招生晒收入为主体的整篇丢，不"抽几句留着"。
- 分表表头、节名不自创；编号不从 01 重编老作者。
- 不改 `merge-pack.mjs` 的判定规则来迁就新条目（用 `manual-overrides.json`）。
- 不 commit，直到用户看过抽查报告。
- 不动 part-1 … part-5：老条目有问题写进"拿不准的条目"交用户。
