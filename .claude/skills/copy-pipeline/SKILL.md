# copy-pipeline · 文案总流程

用户圣矾：做闲鱼虚拟项目的 B 站 UP 主，非技术人员。说大白话、给选项带推荐、一次只问一件事；先讨论，用户说干再干。

目标（2026-09-29 定，取代 09-25「每天 10 长 + 6 短」）：13 个账号每天各写一篇存稿（横版 6 个：黑黄 / 荧光绿 / 署名墙 / 对账台 / 蓝图拆解 / 像素街机，5 分钟、1300–1600 字；竖版 7 个：同六套皮肤竖版 + 聊天记录，1–2 分钟、300–600 字）+ 3 篇真人出镜口播（竖版 1–2 分钟，用户自己录，不出片）。选题只两条硬规矩：同一账号不重复；同一天各篇选题不同。写稿交给 Gemini；员工改稿要越来越少，直到不用改。

## 整条线

```
每天第一步：daily-plan 排「今日选题表」（16 行：账号｜选题｜产品/知识｜来源｜该账号用过吗｜选题核心状态）
  读 docs/每日/账号选题台账.md + 选题池（SRT 各期 / 素材库 topic.json / 选题卡 / 闲鱼经验库）+ docs/每日/选题核心/ 目录

                        ↓
每篇选题再走下面这条线（2026-09-29 起：走 daily-plan 派单时，核心卡门已经在选题表那一步过了，下面"出核心卡→用户确认"这段对新选题 worker 只是把选题表给的要点扩成正式选题核心卡存档，不再停下问用户；对老选题直接读文件，都不停）：

入口一：用户视频 SRT（优先）          入口二：用户发的选题卡（补充）
  用户说"写第 47 期"                    五行卡，模板 docs/每日/选题卡模板.txt
  → npm run srt:find 找字幕和原片          ↓
  → 按字幕自动填选题卡（每行附原话+时间）   ↓
  → 按字幕时间点从原片截图 frames:srt     ↓
              ↘                        ↙
        选题核心：docs/每日/选题核心/<选题>.md 已存在？
          有 → 直接读，接着走；没有 → 出选题核心卡 → 【用户确认】（不走 daily-plan 时才在这里单独停下；走 daily-plan 时选题表已确认，直接存档）
                        ↓

                        ↓
        补其他来源：百度需求佐证（demand）/ 货源证据-GitHub或官网或官方价格页（supply）/ 教程演示（tutorial），见 daily-write 第 4.2 节
                        ↓
        从闲鱼经验库挑干货（engine/brief/pick-experience.mjs）
                        ↓
        写长稿 / 短稿 → 自检（npm run check:draft）
                        ↓
        放 NAS 待审文案\<选题>\（只放正稿 + 同名 .meta.json + 同名 .素材.md；正稿按账号命名 <日期>-<选题>-<skin>-<h|v>.txt / <日期>-<选题>-selfie-NN.txt），素材和 说明.md 放 NAS 资料\<选题>\
                        ↓
        主会话汇总：registry.mjs add 登记（账号写进 --note）→ 追加 docs/每日/账号选题台账.md、故事登记 → 用户去中控台「今日任务」逐套审
                        ↓
        员工改稿，放 NAS 已用（原「已审」，2026-09-28 改名）→ npm run stats:edits 看改动率（基线约 13%）
                        ↓
        script-return 技能：学习改动 → 进视频项目 → 配音 → 分镜 → 渲染
```

## 硬规矩（细节见 AGENTS.md）

- 钱数只来自用户 SRT 里亲口说的或选题卡上写的；闲鱼数据只来自实际截图；查不到就停，不编。
- 原片截图里可能有昵称、订单号，标了"可能要打码"的图等人看过才能交视频项目。
- 同一期可以写很多篇，但新稿换开头、换讲法，不和旧稿共享例子和说法。
- 每天按 daily-plan 的 16 篇分批写，一批验收完再派下一批，不一次全派；不反复重试；同一个问题失败两次就停下交回。

## 主会话（Claude）在这条线上做什么

不亲自写稿。只做：跟用户确认选题和核心卡、派活、验收（抽查稿子和截图）、从员工改稿里学习、改进 daily-write。共享文件（DECISIONS / HANDOFF / 稿件登记 / 词表 / 规则表）由主会话改。
