# script-return · 回稿处理工作流

依据：`docs/计划-回稿闭环-20260908.md`（用户 2026-09-08 已审，五个决策：D1 贴对话也行；D2 只负责把文案和素材放进视频项目；D3 员工改动与用户点名同等效力；D4 **发来的改稿就是通过稿**，改动句数只做趋势不做门；D5 音频不归我方管）。

两条线共用前三步：**第一条线（学）**走到第 ④ 步；用户说"这篇定了"才走**第二条线（送视频项目）**⑤–⑨。

## 先读（每次都读）

1. `docs/稿件登记.json` —— 登记表；认稿靠它，配料包 / 事实链 / 事实卡 / 素材目录都从它取。
2. `docs/交接口规范.md` 的「从成稿到 script.txt 的转换规则」和文末「回稿交付」一节。
3. `D:/项目仓库/remotion视频制作/docs/handoff/film-input-spec.md` —— 视频方的合同（script.txt 只含要念的字、句号分句、单句 ≤50 字、「我是圣矾」独占一句全篇一次）。

## 三个角色

- **脚本**（`engine/return/`）：`identify.mjs` 认稿、`diff-sentences.mjs` 对照表与趋势、`to-script.mjs` 转稿与逐字校验、`registry.mjs` 登记表。
- **主线程**（跑这个 skill 的会话）：存稿、跑脚本、归类学习、写分镜、落地、commit、回报。
- **用户**：给回稿；对归类学习的每一条点头；说"这篇定了"。

## 硬边界（先记住再动手）

- **不动**视频项目的期根 `script.txt`、`episode.json`、素材池（`intake/` 与视频方登记的 assets）。只写 `films/<filmId>/copy/qian17/`。
- **不管**采用、终审、配音、生成、音频。落完地告诉用户在哪就完了。
- 归类学习写进校准词表 / 规则 / 语料包之前，**每一条都要用户点头**；与用户旧裁定冲突的先问。
- 认不出的稿（`identify` 退出码 2）**不猜**，请用户指认。

## 步骤

### ① 存稿（用户 → 主线程）

用户贴稿或给文件。主线程存到 `docs/回稿/<日期>-<选题>-<序>.txt`（例：`docs/回稿/2026-09-10-苹果多开-1.txt`），原样存，不改一个字。选题名先按用户说的写，认稿后如不符再改名。

### ② 认稿（脚本）

```bash
node engine/return/identify.mjs docs/回稿/<文件>.txt
```

打印重合率前三、判定、源稿的全部登记信息（id、filmId、配料包、事实链、事实卡、素材目录）。退出码 0 认出；2 认不出 → 停下问用户"这是哪一篇的改稿"。以下把认出的 id 记作 `<id>`，源稿路径记作 `<源稿>`。

### ③ 对照表（脚本）

```bash
node engine/return/diff-sentences.mjs --source <源稿> --returned docs/回稿/<文件>.txt \
  --out docs/回稿/<文件名>-对照表.md --json docs/回稿/<文件名>-对照表.json \
  --trend docs/回稿/趋势.md --label <id>
```

每句一行：原句 / 改后 / 改动类型（未动 · 换词 · 改通顺 · 删句 · 加句 · 挪位置）/ 备注；数字不一样的追加「改事实?」。文末统计员工改动句数并列出所有「改事实?」句。`--trend` 同时往趋势表追加一行（见文末）。

### ④ 归类学习（主线程做，用户点头才写）

读对照表，逐类处理，**先列清单给用户看，点头后再写文件**：

| 类型 | 去处 | 怎么写 |
|---|---|---|
| 换词 | `docs/用户校准词表.json`（+ 重渲染 md） | 新条目：禁=原词，换=员工的词，类型按现有分类，日期，`用户原话`=对照表那一行，`来源稿`=`<id>`，**录入="员工修改"**。与旧条目冲突（同一个词用户以前裁过不一样的）→ 先问用户，不自动录 |
| 改通顺 / 删句 / 加句 | `docs/写稿规则.md` 或 `docs/人设说明书-钱十七.md` | 归成类再写："某类句子员工一律删" → 规则一条；"某处员工一律补一句" → 说明书条款。一次改稿只有一例的先记在对照表备注里，攒到两篇以上再立规则 |
| 改事实? | 不进规则 | 回 `<事实链>` 核：员工改的数对得上 → 我方原稿写错，记反馈台账；对不上 → 列出来报用户，由用户定 |
| 改后的句子（换词 / 改通顺 / 加句） | `docs/真人语料包/part-5-圣矾本人.md` | 按场景放进"圣矾本人"分区，标期号 `<id>`；下次配料包优先抽这些 |
| 挪位置 | 对照表备注 | 记"员工把 X 挪到 Y 之前"，攒够再看是不是结构规则 |

第一条线到此为止。用户没说"这篇定了"就停，回报：对照表路径、改动句数、归类清单、待用户裁的项。

### ⑤ 转纯口播稿（脚本；用户说"这篇定了"才做）

```bash
node engine/return/to-script.mjs docs/回稿/<文件>.txt --out docs/回稿/<文件名>-script.txt
```

去掉一切不念的东西；单句超五十字只把逗号升成句号（不改字）；阿拉伯数字 / 字母 / 百分号、「我是圣矾」不是恰好一次独占一句、拆完仍超六十字 → 退出码 2 并列出，**主线程改回稿文件里对应处**（数字改成汉字念法要问用户或按稿内既有写法），再跑。成功后打印字数、句数、最长句、拆了哪几句。
再跑一遍 `npm run check:draft -- docs/回稿/<文件名>-script.txt --topic <选题>` 看有没有退回级命中；有的话**只报告不改**（改稿是通过稿，D4），让用户定。

### ⑥ 写分镜 storyboard.md（主线程）

- 按稿子的"点"分段（开场 / 第一点 / 第二点 / … / 交底收尾），格式沿用视频项目现有 `copy/qian17/storyboard.md`：`### 段名` + `**画面**：` + `**口播**：` + `**目的**：`。
- 每段**画面**指到 `D:/项目仓库/remotion视频制作/ips/xianyu-fanshen/films/<filmId>/intake/assets.md` 里已有的文件名——用 `<事实卡>` 的来源列反查"这句的数来自哪张截图"。清单里有但本稿不再讲的图，在分镜末尾列「本稿不用」，文件不删。稿子引用了清单里没有的图 → 记入素材缺口，按 `docs/交接口规范.md` 素材导入规范补采补交（另开任务，不在本 skill 里做）。
- 每段**口播**逐字 = script.txt 对应片段。写完必跑：

```bash
node engine/return/to-script.mjs --verify docs/回稿/<文件名>-script.txt --storyboard <storyboard.md>
```

退出码 1 打印第一处差异，改到一致为止。**脚本比，不目测。**

### ⑦ 落地到视频项目（主线程）

目标目录 `D:/项目仓库/remotion视频制作/ips/xianyu-fanshen/films/<filmId>/copy/qian17/`，覆盖旧稿（git 留历史）：

- `script.txt` ← ⑤ 的产物；`storyboard.md` ← ⑥ 的产物。
- `copy-order.json`：保留 `schema`、`filmId`、`styleId`、`topic`、`audience`、`lengthPreset`；改 `mode: "manual"`、`rewriteSourcePath: "<回稿路径（风格仿写仓库相对路径）>"`、`createdBy: "script-return"`、`createdAt` 当前时间。
- `generation-report.md`：写 来源稿 `<id>`（源稿路径 + 回稿路径）、对照表统计（总句数 / 各类型 / 员工改动句数 / 改事实? 列表）、检查结果（to-script 字数句数最长句、check:draft 结论、--verify 通过）、素材缺口与「本稿不用」清单。
- 在视频仓库 commit，信息写选题和源稿 id，例：`copy/qian17: 苹果多开分身 员工改稿落地（源稿 P-v2）`。**不动**期根 `script.txt`、`episode.json`、素材池；驾考那期根正稿已配音并终审通过，只在回报里提醒用户"采用新稿等于重录"，不替用户定。

### ⑧ 更新登记表（脚本）

```bash
node engine/return/registry.mjs update --id <id> --status 已回稿并交付 \
  --returned docs/回稿/<文件>.txt --diff docs/回稿/<文件名>-对照表.md --changed <员工改动句数>
```

第一条线单独走完（没送视频项目）的，状态写 `已回稿待定稿`。在本仓库 commit：回稿、对照表、趋势表、登记表、归类学习改的文件。

### ⑨ 回报用户

一段话：期名（选题 + filmId）、草稿目录（`films/<filmId>/copy/qian17/`）、素材是否齐（缺的逐张列出）、员工改动句数与趋势、待用户裁的项（改事实? 对不上的、与旧裁定冲突的换词）。之后采用、终审、配音、生成都是视频项目的事，我方不管。

## 改动句数趋势表怎么维护

- 文件：`docs/回稿/趋势.md`，一行一篇回稿：日期 / 稿件 id / 源稿句数 / 回稿句数 / 员工改动句数 / 换词 / 改通顺 / 删句 / 加句 / 挪位置 / 改事实? / 对照表路径。
- 只由 `diff-sentences.mjs --trend docs/回稿/趋势.md --label <id>` 追加，不手改；文件不存在会自动建表头。
- 同一篇跑了两次会有两行，留最新那行，删旧行时手动删（脚本不去重）。
- 看趋势：同一选题按轮次看改动句数往下走就是在学到东西；只看趋势不做门（D4）。一轮四篇回来后一起处理，处理完贴这张表给用户。

## 新交一篇稿时（配套动作，不在回稿流程里）

每交出去一篇稿都要登记，否则以后认不出：

```bash
node engine/return/registry.mjs add --id <选题字母-vN> --topic <选题> --film <filmId> --draft <稿件路径> \
  --brief <配料包> --chain <事实链> --factcard <事实卡> --assets <素材目录> --angle <开头角度> --date <交付日期>
```

## 分镜之后必跑：上屏字过词表（2026-09-12 起）

视频项目的分镜生成器会自己编上屏标签，不过我们的词表。2026-09-12 两期实测把用户判过的词带回屏幕（电影票「三件事讲完 / 九成九好评 / 最后一块」，苹果多开「三件事说清 / 先卖后进货 / 开鱼小铺」），口播稿本身是对的。

分镜任务成功（lint error 0）后、交用户 Studio 审之前：

```bash
node engine/return/screen-check.mjs --film <filmId> [--topic-type 虚拟|实物]
```

- 退出码 1 = 有命中，逐条打印 场景｜上屏字｜换成。
- 改法：上屏字**照口播稿原话**改（稿里说"三点"屏上就写"三点"），`slices/SceneNN.tsx` 和 `scenes.spec.json` **同改**（否则重编译会把旧字带回来），长度尽量不变；改完重跑 `node scripts/by2/storyboard-lint.mjs --film <filmId> --stills --json`，error 0 才提交。
- 上屏字与口播逐字相同会多一条 L4「口播复读」提示，属预期，不用管。
