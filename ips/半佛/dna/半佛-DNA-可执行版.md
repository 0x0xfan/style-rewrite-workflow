### 生成器分派规则

1. **先判定目标内容类型**（默认走恰饭稿——本项目所有推广稿本质是恰饭稿）。
2. 再套用对应类型的结构（见【二】【三】【四】）。
3. 段子/魔幻类比的密度**按类型给上限**，不要无差别拉满：
   - 恰饭稿：段子为点缀，服务于说清痛点与方案；bf09 小鹏是**极端反例**，12 节几乎无类比、无吐槽、无魔幻定性，通篇严肃技术路线分析。恰饭稿允许"零段子变体"。
   - 纯评论：段子密度可高（bf02 西贝、bf05 亚朵）。
   - 惊叹夸赞：段子密度最高、魔幻类比最集中（bf04 五菱）。

> 结论：**"魔幻现实主义段子手"只描述了 10 篇里的 2 篇（纯评论）加 1 篇（惊叹夸赞），不是主结构。** 主结构是下面的恰饭稿六段式。

## 【二、恰饭稿六段式（主结构）】

审计发现的最大缺失：旧档案完全没有恰饭稿结构。这是本项目最该用的骨架。

7 篇恰饭稿（bf01/bf03/bf06/bf07/bf08/bf09/bf10）基本同序。各段职责与证据篇目如下。

### ① 第一人称踩坑经历 / 困扰

- **职责**：用一段具体、自嘲、有画面的第一人称经历开场；不抽象说事，先让读者看到"我"栽过跟头或被什么困扰。
- **证据**：bf03（第一人称踩坑经历开场）、bf06/bf07（第一人称消费经历开场）、bf10（后台提问引出自身买房经历）。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行 `[我]+[场景]+[画面]` 标签，补齐槽位如下。

- **槽位：** [场景 Sc]（"我"真实做过的一次具体消费／生活场景）+ [动作 Ac]（在这个场景里我做了什么、遭遇了什么）+ [自嘲点 Se]（把这次遭遇归到"我自己蠢/我自己贪便宜/我自己想省事"）+ [画面 Pic]（一个能在脑子里立刻浮出来的细节镜头）。
- **槽位关系（硬约束）：** 四个槽位必须收束到**同一问题域**——即后文第 ④ 段要推的方案所解决的那个问题。踩的这个坑，必须正好是方案要兜住的坑；场景 Sc 越具体、自嘲点 Se 越把责任揽到自己身上，读者越不设防。Ac 与 Pic 要落在一个可想象的镜头上，不能只用形容词概括。
- **功能：** 用"我"的一次亲身翻车换取读者的信任与代入——先承认自己栽过，读者才愿意跟着往下看，为第 ② 段"这不是我一个人"铺路。
- **失效条件：**
  - **卖惨化**：画面写得太惨、太悲情（负债、家庭破裂、被逼到绝境），语气从自嘲滑向诉苦，读者只剩同情、无法代入。
  - **与方案无关**：踩的坑和后文第 ④ 段要推的方案不在同一问题域（开头吐槽通勤堵车，方案却卖二手回收），代入断裂。
  - **泛泛化**：写成"很多人都遇到过……"的普遍现象，不是"我"的一次具体经历，画面立不起来。
- **示例（仅演示结构，用词全新，非来源场景）：**
  1. 选题＝租房押金难退：上一次租房退租，我为了图省事没拍验收视频，搬走那天房东指着一道我根本没碰过的墙缝，从押金里扣走大几百，我站在空屋里愣是没词反驳——纯纯我自己的锅。（Sc＝退租验房 / Se＝图省事没留证据）
  2. 选题＝二手数码回收：我第一次卖旧手机，贪那家报价高二十块，寄过去人家验机说屏幕有暗斑要压价，我又不敢让他寄回来怕路上摔，最后捏着鼻子认了——就为多那二十块，绕了一大圈还亏。（Sc＝寄卖旧手机 / Se＝贪二十块）
  3. 选题＝线上技能课：我冲动报过一个九块九引流的课，进去才发现真东西全在后面三千八的进阶班里，九块九买的是两小时听人讲"你一定要学"，我盯着那个付款页面坐了半天——钱不多，蠢是真蠢。（Sc＝报引流低价课 / Se＝冲动付款）
  - 生成时不照抄以上示例，并先查批次账本（`npm run ledger`）避开本批次其他稿件已用过的场景与坑，避免同一结构约束下撞出同一实例。
- **检查点**：开场是否是"我"的具体一次经历（而非泛泛现象）？有没有一个能想象出来的画面？语气是否自嘲而非诉苦？踩的坑是否与第 ④ 段方案同一问题域？

### ② 个人困扰上升为普遍问题

- **职责**：把"我这一次"扩成"其实所有人都会遇到"，让读者对号入座。
- **证据**：bf03、bf10 均在开场段之后立即完成这一跳。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行 `[我的坑]→[不是我一个人]→[凡做 X 都躲不掉]` 标签，补齐槽位如下。

- **槽位：** [我的坑 K]（承接第 ① 段那一次具体遭遇）→ [去个人化 U]（"这不是我一个人的运气差"）→ [人群锁定 G]（"凡是做／买／碰 X 这件事的人，都躲不掉这一关"）。
- **槽位关系（硬约束）：** K 必须是第 ① 段那个坑本身，不能中途换一个新问题；U→G 是一次**由个案到人群的放大**，放大的边界要正好圈住目标读者（写给想薅餐饮券的人，G 就锁"凡是想省顿饭钱的人"，不外扩到全体网民）；这一跳要顺着 K 的因果自然滑出，不能硬拗成"这背后其实是一个时代命题"式的大道理。
- **功能：** 让读者从"看别人翻车"切换到"这说的就是我"，把第 ① 段建立的信任转成"我也需要解决它"的动机，为第 ③ 段的反问连打准备好一个对号入座的读者。
- **失效条件：**
  - **人群圈错**：G 圈的人群和目标读者不重合（个案是租房、却放大到"所有成年人"），读者对不上号。
  - **拔高成大道理**：跳过人群锁定，直接升华到宏大命题，读者接不住、也代入不了。
  - **换了问题**：U/G 讨论的坑已不是 K 那个坑，第 ① 段的铺垫作废。
- **示例（仅演示结构，用词全新，非来源场景）：**
  1. 选题＝租房押金：别以为就我一个倒霉。你去问一圈租过房的，十个里有八个押金都被莫名其妙扣过，只要你是租房党，这一关早晚轮到你。（G＝凡是租房的人）
  2. 选题＝二手回收：这真不是我手背。凡是家里攒了几件闲置想出手的人，都会在"报价高的不敢信、报价低的不甘心"这道坎上卡住。（G＝凡是想处理闲置的人）
  - 生成时不照抄以上示例，并先查批次账本（`npm run ledger`）避开本批次其他稿件已用过的人群与坑。
- **检查点**：读者能否在这一段里认出"这说的就是我"？跳转是否自然，没有硬拗成大道理？G 圈的人群是否正好是目标读者？

### ③ 穷举式反问连打（说清为什么难）

- **职责**：连续抛出大量反问，把一件事所有可能的坑/难点一次性砸出来，制造"我一个人根本扛不住"的压迫感。这是引出解决方案前的势能积累。
- **证据**：**bf10 第 3 节**是最典型样本——连续二十余问，把一桩大额交易的各个风险面逐一砸出，再引出第三方兜底的价值。此手法与闲鱼/二手交易选题高度契合。
- **注**：这是 7 篇恰饭稿里辨识度最高、最该复用的段落级手法，本次作为本档案的结构规格样板重写。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行"连续 N 个反问、换角度、不给答案"标签，是本档案对项目最有用的一条，补齐为完整结构如下。

- **单问槽位（每一问填什么）：** 每一个反问 = [风险维度 Dᵢ] 上的一个具体担忧。Dᵢ 从目标事物的**风险面清单**里取一个维度，每问换一个维度，例如：来源真假、质量稳定性、合规资质、售后追责、时间成本、金额损失、信息不对称、被坑后维权难度。一问一维度，问的是"这个维度上我会不会出事"，不是抽象地问"这靠谱吗"。
- **问与问之间的关系（槽位间约束）：**
  - **同一决策的不同风险面**：所有问都挂在同一个决策对象上（都在问"要不要/敢不敢做这一件事"），只是每问切换到这件事的另一个风险面，不是跳到别的话题。
  - **有排布顺序**：由浅入深（先问显而易见的表面坑，再问隐蔽的深层坑）或由外向内（先问外部客观风险：来源、合规；再问落到自己头上的后果：赔钱、维权、耗时间）。顺序让读者感到"坑一个比一个深，越想越怕"。
  - **维度不重复**：相邻的问不能是同一维度的同义反复（"会不会是假的"和"是不是骗人的"算同一维度，只能留一个）。
- **长度与节奏：** 连续 N 问一口气砸出，情绪势能段 N 建议 ≥15；反问句多独立成行、短促，**连问期间一律不给答案**，把所有压迫感攒住，直到这一节末尾（或紧接的第 ④ 段）再统一收口、引出方案。中途任何一问被就地回答，压迫感就泄了。
- **功能：** 用密集、多维、不给答案的追问，在读者心里堆出"这件事坑太多、我一个人根本扛不住"的压迫感与无力感；正是这种"扛不住"的顶点，才让随后第 ④ 段的方案显得是被逼出来的救命稻草，而不是硬广插入。
- **失效条件（什么情况下这条会坏）：**
  - **同义反复**：多问其实是同一维度换词重说，读者听出"绕来绕去就一个意思"，压迫感变啰嗦。
  - **边问边答**：问一句答一句（"会不会被坑？其实平台管着呢"），每答一次就卸一次压力，攒不出势能，也提前剧透了方案。
  - **数量太少**：只问三两句就停，不成"连打"，够不到"扛不住"的临界点，第 ④ 段的方案也就顶不出来。
  - **维度发散**：问着问着跳出这件事去问别的（从"这券能不能用"跳到"现在生意难做吗"），决策对象散了，读者不知道在替什么担心。
- **示例（仅演示结构，用词全新，非来源选题；生产时问数须补到 ≥15，此处每例只列 5–6 问示范"换维度、逐层加压、不给答案"的排布）：**
  1. 选题＝闲鱼餐饮券转卖：这券是哪来的？商家自己发的还是别人手里倒出来的？到店认不认？过没过期你敢确定吗？万一到了店人家说系统查无此券，你找谁？转你券的人拉黑你了呢？店家和卖家互相甩锅，最后掏钱的是不是还是你？（维度：来源→有效性→时效→售后追责→对方跑路→夹在中间）
  2. 选题＝二手数码回收：你怎么知道这家报价实在？寄过去它压价你敢不敢让它寄回来？路上摔了算谁的？它说你机子有暗病，你拿什么证明寄出去时是好的？钱到账前它反悔了呢？维权你耗得起那个时间吗？（维度：报价可信→压价风险→运输责任→举证难→反悔→时间成本）
  3. 选题＝找线上家政/上门服务：来的人是平台自己的还是临时拉的散工？出了事平台认不认？他手脚不干净你事后怎么查？磕坏了东西谁赔？不满意想退单，钱退得回来吗？下次换个人是不是又得从头担一遍这些心？（维度：人员来源→平台担责→安全→财物损失→退款→复购的重复风险）
  - 生成时不照抄以上示例，并先查批次账本（`npm run ledger`）避开本批次其他稿件已用过的选题与追问维度组合，避免同一结构约束下两稿撞出同一串问。
- **检查点**：反问数量是否够多（建议 ≥15）？每一问是否指向一个**不同**的风险维度、而非同义反复？连问期间是否**全程不给答案**、把压迫感留到第 ④ 段释放？所有问是否都挂在同一决策对象上、且有由浅入深/由外向内的顺序？句式生成参数另见【六】6.2。

### ④ 引出解决方案

- **职责**：势能积累到顶点后，用一个转折把品牌/产品作为"兜底方案"引出。
- **证据**：bf10 第 2 节以"所以为啥要用……？第一……第二……"分点承接、bf03、bf07。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行 `[所以为啥用 X?]→[第一…第二…]` 标签，补齐槽位如下。

- **槽位：** [转折词 T]（"所以／说白了／但"，把压迫感一把接住）→ [方案点名 X]（品牌/产品作为兜底方案登场）→ [分点承接 P₁…Pₙ]（"第一……第二……"，每个 Pₖ 对应第 ③ 段砸出的一个坑）。
- **槽位关系（硬约束）：** P₁…Pₙ 必须与第 ③ 段的风险维度**一一对应回收**——③ 问了来源、时效、售后，④ 就分点答来源怎么保、时效怎么保、售后怎么兜；问出来的坑一个都不能漏答，也不新增③ 没铺过的卖点。方案是被前面"扛不住"顶出来的下一步，不是并列的一段广告。
- **功能：** 把第 ③ 段攒住的压迫感在此一次性泄压，让读者感到"原来这些坑有人替我兜"，方案因此像救命稻草而非硬广。
- **失效条件：**
  - **硬广插入**：方案与第 ③ 段的坑没有对应关系，读者感到话题被广告打断。
  - **答非所问**：分点讲的卖点不是③ 问过的坑（③ 问售后，④ 却夸界面好看）。
  - **提前泄压**：转折来得太早，③ 的势能还没到顶就抛方案，压迫感没兑现成解脱感。
- **示例（仅演示结构，用词全新，承接上文 ③ 示例1 的选题＝餐饮券转卖）：** 所以为啥宁可走平台担保也别私下接券？第一，券的来源平台帮你验过，不是谁手里随便倒的；第二，到店核销不认，钱能原路退回，不用你去堵卖家；第三，卖家拉黑跑路，找平台就行，不用你夹在中间。（P₁→③的来源问、P₂→③的售后问、P₃→③的跑路问）
  - 生成时不照抄示例，并先查批次账本（`npm run ledger`）避开本批次已用的分点措辞。
- **检查点**：方案是否被"穷举反问制造的压迫感"顶出来，而不是硬广插入？分点是否与第 ③ 段砸出的坑一一对应（方案解决的正是前面问出来的问题）？

### ⑤ 数据 + 案例证明能力

- **职责**：给出具体数字和品牌落地案例，证明方案不是空话。
- **证据**：bf03（标题即含量级锚点）、bf07、bf06。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行 `[数字]+[案例]` 标签，补齐槽位如下。

- **槽位：** [量级数字 Num]（投入／规模／覆盖／时长中取一类具体数）+ [可感落地案例 Case]（一个读者能想象出使用场景的具体例子）。
- **槽位关系（硬约束）：** Num 与 Case 必须**证明的是同一件事**——即第 ④ 段承诺的那个兜底能力；数字给量级、案例给画面，两者互为佐证，不能一个讲 A 能力、一个讲 B 能力。数字与案例都取自目标 contract 的真实事实，不得凭空造数（造数另触合规，见【七】禁令 4 与平台合规）。
- **功能：** 把第 ④ 段的方案承诺从"它说它能"落到"它已经在这么大规模上这么做了"，用可核实的量级与可想象的场景消掉读者"你是不是吹的"这层怀疑。
- **失效条件：**
  - **数字悬空**：只有形容词（"投入巨大""覆盖极广"）没有具体量级，读者无从掂量。
  - **案例抽象**：案例是功能罗列（"支持退款、支持验券、支持追责"）而非一个能想象的使用场景。
  - **数字与案例各说各话**：Num 证明的能力和 Case 展示的能力不是同一个。
- **示例（仅演示结构，用词全新，承接餐饮券选题）：** 光去年一年，平台就替用户拦下过百万笔核销异常的券；上个月有人买的券到店说过期，客服十分钟内原路退款，人饭照吃、钱一分没亏。（Num＝百万笔拦截量级 / Case＝十分钟退款的可感场景，两者都证"售后能兜"）
  - 生成时不照抄示例，并先查批次账本（`npm run ledger`）避开本批次已用的数字与案例。
- **检查点**：有没有至少一个具体数字？案例是否可感知（读者能想象出使用场景）而非抽象罗列功能？数字与案例是否证明的是同一件事（＝④ 承诺的能力）？

### ⑥ 类比升华收尾

- **职责**：用一个类比把话题从"这个产品"拉高到"一种生活方式/普遍道理"，收束全文。
- **证据**：bf01、bf10 结尾均以类比升华收束。

**结构规格（2026-08-22 结构化修订）：** 旧版只有一行 `[重新定义]+[类比]+[短句]` 标签，补齐槽位如下。

- **槽位：** [本体 Vehicle-source]（正在讲的产品/行为，先被重新定义一次）+ [喻体 Vehicle]（拿来打比方的另一件事物）+ [共享属性 Attr]（本体与喻体之间真正共有的那一条道理）+ [落地短句]（把这条道理落回普通人日常的一句话收口）。
- **槽位关系（硬约束）：**
  - **喻体来自观众日常**：喻体必须是目标读者天天见、一听就懂的事物（家里的锁、雨天的伞、体检、备用钥匙），不能拿更冷僻、更专业的东西作喻体。
  - **贵贱档次与本体匹配**：喻体的分量／档次要和本体相称——给一件小工具作比，喻体也该是日常小物；不能用宏大意象去比一件日用品，也不能用鸡毛蒜皮去比一件重决策，档次错位则升华变儿戏或变浮夸。
  - **类比要在共享属性上真正成立**：本体与喻体必须在 Attr 这条实质道理上相通（都是"花小钱买个安心""都是替你先扛住风险"），不能只在一个表面词上搭一下就散。
- **功能：** 把话题从"你该用这个产品"抬到"这是一种更省心的活法"，让读者带走一个能复述给别人的道理，而不是一句广告词；收尾的落地短句把这个道理还给普通人的日常，全文收束。
- **失效条件：**
  - **喻体比本体更难懂**：拿一个更抽象/更专业的东西打比方，读者还得先理解喻体，越比越糊涂。
  - **表面词类比**：本体与喻体只在一个字面词上相似（都带"卡"字、都叫"通行证"），共享属性根本不成立，一推就穿。
  - **档次错位**：用宏大喻体比日用品（把一张券比作"人生的护城河"）显浮夸，或用琐碎喻体比重决策显轻佻。
  - **挂账号资产**：收尾套用账号固定签名/自称/矩阵话术（见【七】禁令 2），不算类比升华。
- **示例（仅演示结构，用词全新，非来源喻体）：**
  1. 选题＝担保交易：说到底，平台担保不是帮你占便宜，是给你这笔交易配了把锁——门照进，钱照花，只是多一层"出事有人拦"。锁不贵，图的就是你不用整宿惦记门关没关。（喻体＝锁 / Attr＝花小钱买"出事有人拦"）
  2. 选题＝二手回收验机：其实第三方验机就像出门前顺手带的伞，不是天天用得上，是省得你在半路被浇成落汤鸡时干着急。多带这一步，图的就是心里有底。（喻体＝伞 / Attr＝平时不显、出事才知值）
  - 生成时不照抄示例，并先查批次账本（`npm run ledger`）避开本批次其他稿件已用过的喻体，避免同一结构约束下两稿撞出同一个比方。
- **检查点**：收尾是否从"这个产品"升到了"一种普遍道理/生活方式"？喻体是否取自观众日常、档次与本体相称？类比是否在共享属性上真正成立（不是只在一个表面词上搭一下）？最后一句是否落回普通人？
- **禁令**：收尾**不得**使用账号固定资产（见【七】禁令 2）。

> **变体提示**：bf09 小鹏是"评论型恰饭稿"，六段被拉成 12 节严肃分析，第 ③ 段的反问连打与段子几乎消失。生成严肃技术/商业选题时可切到此变体：保留 ①②④⑤⑥ 的逻辑骨架，弱化 ③ 的情绪势能。

## 【三、纯评论 / 吐槽结构（2/10）】

- **样本**：bf02（4 节）、bf05（1 节，最短，1573 字）。
- **骨架**：
  1. 由一个外部新闻事件起笔。
  2. 先给出"表面上大家怎么看"的矛盾。

  4. 用类比 + 自身背景把结论钉死。
- **段子密度**：可高。魔幻类比、荒诞动作描写在这一类里最自由。

## 【六、句式级控制】

对【五】表中辨识度最高的两条稳定特征给出可操作参数。**这些是句式功能的抽象描述，不含任何原文句子；生成时须自造内容填充，不得复用原文示例。**

### 6.1 短句独立成行承担判断与转场（稳定特征 #2）

- **功能**：用一个极短句单独占一行，完成一次判断落定或话题切换，制造停顿与节奏顿挫。
- **槽位（2026-08-22 结构化修订）：** [极短句 S]（1–6 字）+ [占位 Pos]（段落收口处／两话题之间）+ [用途 Use]（判断型／转场型，二选一）。
- **槽位关系（硬约束）：**
  - S 必须紧贴它要作用的对象：判断型 S 紧接在被它定性的那段长句之后（对前文下一个短促定性）；转场型 S 卡在旧话题结束、新话题开始的接缝上。
  - S 靠长句衬托才有力——密度一节内 1–3 处，不能句句极短（句句短则失去顿挫）。
- **失效条件：**
  - **句句极短**：整段都是短句，没有长句作背景，顿挫感消失，读起来像喘不上气。
  - **空短句**：S 不下判断也不转场，只是把一句普通话拆行（"然后呢。""就这样。"充数），占了位却没功能。
  - **落用原句**：直接搬原文里的既有短句作成品（见禁令）。
- **示例（仅演示结构，用词全新，非来源短句）：**
  1. 判断型：（长句铺垫某报价看着划算之后）｜换行｜别信。
  2. 判断型：（讲完一堆看似周到的条款之后）｜换行｜全是坑。
  3. 转场型：（上一段讲完风险之后）｜换行｜说回正事。
  - 生成时不照抄示例，并先查批次账本（`npm run ledger`）避开本批次已用的短句成品。
- **禁令**：短句内容必须自造。禁止直接落用原文里的既有短句作为成品。

### 6.2 反问连打（稳定特征 #3，恰饭稿第 ③ 段核心）

- **功能**：连续反问累积压迫感，或在拆解"为什么难/为什么不合理"时逐层追问。
- **生成参数**：
  - 数量：情绪势能段建议 ≥15 问；一般追问段 3–6 问。
  - 每问指向一个**不同**的风险维度，避免同义反复。
  - 句式在同一决策对象下换维度推进（从一个坑跳到下一个坑），由浅入深/由外向内，保持递进而非平铺。
  - 反问句多独立成行，通常**不即时给答案**——答案留给随后的方案段。
- **完整结构规格：** 恰饭稿情绪势能段的反问连打已在【二】③ 写成完整结构规格（单问槽位＝风险维度、问间关系＝同一决策的不同风险面且有排布顺序、长度节奏、功能、四条失效条件、3 个全新选题实例），本条只作句式参数摘要，生成时以【二】③ 为准。一般追问段（3–6 问，如评论稿推翻表面矛盾处）沿用同样的"换维度、不同义反复"约束，规模缩小。
- **参照结构**：bf10 第 3 节（不抄句，只学"换维度穷举、逐问加压"的排布方式）。

### 6.3 类比密度的类型上限

| 内容类型 | 类比/段子密度上限 | 参照 |
| --- | --- | --- |
| 恰饭稿 | 低—中（服务于讲清痛点与方案；允许零段子变体） | bf09 零段子、bf10/bf07 低密度 |
| 纯评论 | 中—高 | bf02、bf05 |
| 惊叹夸赞 | 高（全语料最高） | bf04 |

- **规则**：类比只在"把抽象讲具体"时使用，密度按上表封顶；严肃选题宁可不用，也不硬塞。
- **禁令**：类比必须新造。禁止复用原文既有类比（旧档案因复用导致过往稿件出现原文类比的仿写残影）。
- **2026-08-22 结构化审计：** 结构完整——本条是密度预算规则（按内容类型给类比上限＋失效＝上表封顶与禁令），非造句槽位，不改。单个类比自身的槽位约束（本体/喻体/共享属性/失效）见【二】⑥。

### 6.4 篇幅与分节校准（manifest 直接数据）

以下区间来自 corpus-manifest 的 10 篇 `chars` 与 `numbered_sections` 字段，是可核实的实测范围，**不是权重**。

- **篇幅**：10 篇 3,490 字级为常见，全距 1,573–5,193 字。恰饭稿普遍偏长（bf07 5,193、bf10 4,832、bf03 4,493、bf06 4,336）；纯评论偏短（bf05 1,573、bf02 2,531）；惊叹夸赞最短高密（bf04 2,011）。
- **分节数**：全距 1–12 节。恰饭稿分节跨度大（bf03 仅 2 节，bf09 达 12 节），说明**节数服从内容而非固定值**。
- **生成规则**：
  - 恰饭稿默认铺到 6 节上下，可按选题在 2–12 节间伸缩；六段式是逻辑骨架，不等于恰好 6 个数字节。
  - 纯评论压短（约 1,500–2,500 字）。
  - 惊叹夸赞短而密（约 2,000 字、4 节内）。
- **注意**：这些区间只反映这 10 篇，不设为硬约束；选题需要时可越界，但越界要有理由。
- **2026-08-22 结构化审计：** 结构完整——本条是从 manifest 直接数出的篇幅/分节校准区间（可核实实测范围＋生成规则），是校准数据不是造句槽位，不改。

### 6.5 先表面矛盾、再推翻（稳定特征 #4）

- **功能**：先摆出一个看似成立的表面判断，再一把推翻它，指出真实矛盾所在。用于纯评论稿的核心动作（【三】第 2→3 步），也可在恰饭稿里用来破除读者对某个"看着划算/看着周到"的错觉。
- **槽位（2026-08-22 结构化修订）：** [表面判断 Surf]（读者/大众一眼会认同的那个说法）+ [推翻词 Turn]（"但／可你仔细想／问题是"）+ [真实矛盾 Real]（推翻后指认出的那条实质矛盾：成本／人性／商业逻辑／信息差）。
- **槽位关系（硬约束）：** Surf 与 Real 必须是**同一件事的两面**——Real 不是换了个新话题，而是掀开 Surf 那层表象后底下真正在起作用的东西；Turn 之后必须真的落到一个可指认的 Real，不能只是"其实没那么简单"式的空转。Surf 越是读者默认成立，推翻的反差越大。
- **失效条件：**
  - **只摆不翻**：给了表面判断却没推翻，停在复述舆论/常识。
  - **翻到空处**：推翻后没落到一个具体的真实矛盾，只留一句"没这么简单"。
  - **换了话题**：Real 和 Surf 不是同一件事的两面（表面讲价格、真实却跳去讲服务态度），反差断裂。
  - **连续机械复用**：整篇反复用"很多人以为……其实……"同一句壳（见【六】禁令与钱十七同类边界），读者听腻。
- **示例（仅演示结构，用词全新，非来源事件）：**
  1. 选题＝低价引流券：都说这种一块钱的券是商家在亏本赚吆喝。可你到店就明白了——它压根没打算让你只花这一块，真正的账，在你进门之后才开始算。（Surf＝商家亏本 / Real＝一块钱是入口，消费在进门后）
  2. 选题＝"包邮"心理：大家都觉得包邮是卖家让了利。但运费从来没消失，它只是被拆进了商品价里——你以为省了运费，其实是替所有退货的人一起分摊了。（Surf＝包邮＝让利 / Real＝运费转嫁进定价）
  - 生成时不照抄示例，并先查批次账本（`npm run ledger`）避开本批次已用的表面判断与真实矛盾组合。

## 【七、硬禁令（来自审计）】

生成器**必须**在输出前做这几项排查。

### 禁令 1：不得保存或输出来源原句

- 本档案的所有"公式"都必须是**抽象结构描述**（讲句式功能与骨架），**不得**包含任何可从 10 篇原文定位的原句或近似句。
- 旧档案把来源原句只换名词当模板，直接导致过往稿件复读原文句子。这类"套模板"行为一律禁止。
- **生成后自查**：任意连续 8 字以上若能在原文中找到对应，判为抄句，必须重写。

### 禁令 2：不得使用账号固定资产

- 结尾签名、账号矩阵、抽奖暗号、自我称谓等**属于账号固定资产，与单篇内容无关**，出现在 10/10 篇末尾不代表它是"文章内容"。
- 生成器**禁止**产出任何账号固定签名、账号自称、固定版块话术。收尾只能用【二】⑥ 的类比升华公式，不得挂签名。

### 禁令 3：不得把段子密度恒定拉满

- 段子/魔幻类比密度**按内容类型给上限**（见【一】【二】【三】【四】）。恰饭稿尤其要克制，允许 bf09 式零段子变体。
- 严肃技术/商业选题若强塞魔幻类比，判为风格误用。

### 禁令 4：不得凭空给权重

- 任何百分比权重、评分系数若无法从 corpus-manifest 的 10 篇分布数出来，**禁止写入**生成参数。

### AI 味负面清单（2026-08-23，依据 `docs/de-ai-writing.md`）

生成半佛稿时，除上述禁令外，额外过这几条去 AI 味排查。半佛的短句成行、反问、"不是 X 是 Y"、金句收尾都是**本人签名，只降密度、不清零**：

- **句长必须有落差。** 半佛真人是长段分析句 + 短句猛砸交替，不能摊成清一色的中短句。句长变异系数（CV）下限见 `engine/naturalness/ai-flavor-rules.json` 的半佛阈值——过匀就是"太整齐"，补一个长铺陈句再短句砸下。
- **反问连打保留，但控密度。** 反问是半佛推进手法，连打（第 ③ 段情绪势能段）照旧；但连续反问上限与问号密度上限见 rules，反问之间要夹陈述句喘气，不得整篇机械轰炸（半佛短稿问号约 4 倍超标）。
- **"不是 X 是 Y"与金句收尾只降密度。** 两者都是半佛本人风格，保留；但不得每段一句、每节一收、对仗过密到读不出口，密度按 rules。
- **破折号基本不用。** 半佛真人几乎不用破折号，别拿它抖包袱、接补充、做揭晓；用句号自然分句代替。
- **总结壳口头禅按阈值。** 说白了 / 这就是 / 一句话 / 记住一条 / 核心是 / 本质上——按 `engine/naturalness/ai-flavor-rules.json` 的半佛阈值控量，删壳直接说。
- **跨 IP 不撞骨架。** 核心判断句、结尾动作序列、互动与下期壳必须是半佛自己的一套，不得与钱十七等其他 IP 稿件同构（见 `docs/variation.md`）。
- **自检**：写完过 `npm run check:ai-flavor`，再人工读——有没有一句"人嘴里说不出来"的压缩句、有没有一段"换个 IP 也能原样用"。

依据：`docs/research/ai-flavor-diagnosis-20260823.md` 第 4 节。

```
6. 收尾用类比升华，禁挂账号签名

7. 输出前跑硬禁令排查（【七】禁令 1–4）

```

## 【十、常见误用 → 修复】

审计与过往稿件暴露的典型错误，生成器与复核者对照排查。

| 误用 | 症状 | 修复 |
| --- | --- | --- |
| 把"魔幻段子手"当全局特征 | 恰饭稿里硬塞魔幻类比、严肃选题也段子拉满 | 先判类型；恰饭稿走六段式、密度封顶，严肃选题切 bf09 变体 |
| 默认凌晨困惑式开篇 | 每篇都从"睡不着/迷惑"起笔 | 凌晨困惑仅 1/10；恰饭稿默认走第一人称踩坑/消费经历或后台提问 |
| 复用原文句子/类比 | 出现能在原文定位的句子或其近义仿写 | 走禁令 1、【六】自造要求；连续 8 字命中原文即重写 |
| 挂账号固定签名 | 结尾出现账号自称、固定签名、矩阵话术 | 走禁令 2；收尾只用类比升华公式 |
| 凭空写权重 | 参数里出现无来源的百分比/系数 | 走禁令 4；只用可从 10 篇数出的 N/10 |
| 反问连打退化 | 反问三两句就停，或同义反复 | 恰饭稿第 ③ 段 ≥15 问，每问一个不同的坑，不给答案 |
| 方案硬广插入 | 品牌与前文无逻辑衔接 | 第 ④ 段方案必须回应第 ③ 段砸出的坑 |
