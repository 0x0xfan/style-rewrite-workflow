# 通用口播风格拆解工作流

## 目录

1. 目标与非目标
2. 输入契约
3. M1–M7 工作流
4. 通用核心与 IP 档案边界
5. 失败处理

## 1. 目标与非目标

目标是从多篇中文短视频口播稿中建立可审计的 IP 风格档案。档案描述结构、句式、节奏、说服和证据位置，不保存来源事实。

本 Skill 不负责：事实核验、正式文案仿写、UI、飞书读取、TTS、视频、发布、账号运营或把某个 IP 的金句做成素材库。允许制作隔离评测稿来检验 DNA 的生成控制力。

## 2. 输入契约

最低输入：

- `ip_name`：被分析的 IP 名称。
- `source`：一个 Markdown/TXT 文件，或由多个 Markdown/TXT 文件组成的目录。
- `output_root`：项目内存放该 IP 档案的位置。

推荐元数据：标题、发布日期、平台、内容类型、是否转写稿、是否同一视频的不同版本。

输入文件支持三种边界：

- 多文件目录：每个文件视为一个口播单元。
- Markdown `##`：每个 H2 视为一个单元，H1 只作总标题。
- `---` 分隔：没有 H2 时按水平分隔符切分。

只有一个单元时允许形成观察报告，但不得形成候选 DNA。

## 3. M1–M6 工作流

### M1 语料登记与分段

生成稳定 unit ID、标题、来源位置、行号、字符数和估计时长。原文只留在私有语料位置，公开 DNA 不复制正文。

### M2 样本健康与人工取舍

检查：近重复、同一视频转写变体、固定开场、过短样本、题材和时期覆盖。工具只提出候选，不自动排除。

人工对每组问题作出：`keep_separate`、`merge_as_variant`、`exclude` 或 `unresolved`。解决后的决定记录必须包含 `reviewer_type=human`、`record_id`、人工确认者和 ISO 8601 时间。`unresolved` 存在时，可以继续做观察，但不得产生 candidate 或批准档案。

独立支持度按 `independence_cluster_id` 计算，不按原始 unit 数计算。

### M3 语义与生成作用标注

- L0 口播规格：字数、段落、短句簇、停顿和节拍。
- L1 钩子与落点：停留理由、承诺兑现、结尾动作。
- L2 结构路径：内容类型、段落职责和相对顺序。
- L3 口语与节奏：句式关系、反问、转折、重复和互动重置。
- L4 核心解释逻辑：项目/观点/故事如何进入，主体靠什么推进，结果如何收束。
- L5 证据与素材位：哪项材料证明哪项主张，出现在哪里。
- L6 可选增强：样本确有证据时，再标叙事位置、局部认知纠偏、价值包装、段落价值承接或受众代入。段落价值承接专指主要章节边界上的“上一环节/当前状态 → 下一问题的重要性、收益或后果 → 进入方法”，不等于写一个小标题。
- L7 边界与风险：哪些只学形态，哪些不得进入新稿。

每个锚点同时标注：预期受众作用与信息角色。它们描述文本承担的功能，不证明真实心理效果。

必须先标语义关系，再归纳公式。不能因为出现“注意”就认定排雷，不能因为出现“数据”就认定证据。

### M4 生成控制建模与冲突处理

先形成 observation。升级 candidate 时同时满足：

- 至少两个独立样本簇；
- 关系相同，而非只有词汇相同；
- 适用内容类型一致；
- 框架必需节拍在至少两个独立路径中出现且顺序一致；
- 已写明不适用条件和风险边界。

先建立：

- 一句话核心模型：先压缩成“如何进入主题 → 如何展开 → 如何收束”，它必须能解释多数高质量样本；
- content type / framework selector：用抽象内容信号选择或拒绝框架；
- 核心内容策略：反复出现、直接影响框架推进的解释、证据和行动逻辑；
- `attention_rhythm`：按相对位置记录注意力意图，不把文本推断伪装成真实受众数据；
- pattern 生成动作、使用预算和 `avoid_when`；
- `avoid_patterns`：有证据的负面风格，不用“样本里没出现”直接推断“永远不用”。

再按需建立：

- `communication_persona`：可观察的说话姿态、受众关系、权威来源和确定性策略；`narrator_position` 只有在说话者反复明确自身介入动作时才建立，不能靠一次“我看/我拆”推导；
- `cognitive_journey`：只有多篇样本存在完整、同序的认知变化路径时才建立；局部“不是 X 而是 Y”只属于句式或 reasoning move；
- `opportunity_packaging`：只记录反复出现的价值呈现顺序，不能把普通的案例切入、数据解释和总结拼成一个理论层。
- `section_value_bridge`：若多个独立样本在主要章节切换前，反复用一两句描述性内容抬高下一段的必要性或收益，再进入动作，可建成可选 transition beat 或局部 pattern。不得把“接下来/第一/第二”本身算作证据，不得对每个小步骤强制包装，也不得另建顶层命名空间。

若顺序冲突，拆成不同框架或条件分支。若只在一个题材簇出现，不宣称跨题材通用。

如果样本不能支持叙事位置、认知推进或机会包装中的某一层，直接留空，不用通用创作常识补齐。每轮新增规则后都做减法审查：删除与框架重复的规则、只解释一次测试稿的规则、使简单基线变差的规则。不得因为档案更完整、术语更高级就判断风格更准确。

### M5 DNA 打包与人工确认

机器版只保存抽象规则、指标、锚点 ID、独立样本簇、适用条件、置信度和边界。人读版展示为什么这么判断，但不复制原文事实。

默认状态：

- `observation` + `review_only`
- `candidate` + `profile_approval_required`；校验时必须同时提供 manifest、health、decisions 和 annotations
- `approved` + `selectable`，仅在整个 profile 已由用户确认时允许

Skill 不自行把 draft 改成 approved。

### M6 留出解释验证与回归

至少留出一条未参与融合的独立样本，检查档案能否解释其主要内容类型、框架、节奏和证据位置。样本不足以留出时，明确写入 limitation，不伪造验证。

跨 IP 前向测试至少检查：

- 不改通用代码即可创建新档案；
- 不同 IP 得到不同规则；
- 任一参考 IP 的事实不进入另一份档案；
- observation 不能成为正式仿写选项。

### M7 隔离生成验证

使用未参与规则抽取的目标内容或合成事实夹具，建立私有 generation test：

- 选择器可匹配正确内容类型/框架，也可在不匹配时 abstain；
- 只允许 candidate/approved 控制项进入评测稿，observation 不可应用；
- 使用外部 content contract 锁定目标内容关系，并用绑定真实 output 的 output audit 提取同一组关系；
- 工具重算 input、contract、output、audit 的 SHA-256，再比较两侧规范化关系值；
- pattern 次数、位置和相邻重复符合 application control，并绑定到 output 字符 span；
- 每条 candidate/approved avoid pattern 的违规数为 0；
- 没有新增事实、来源 IP 事实或过程性元话语；
- 人工判断风格控制是否有效且没有过拟合。

Reviewed suite 还必须为每个可选框架覆盖 positive、excluded/abstain 与 fallback，为每条可选 pattern 覆盖 max budget，为每条可选 avoid pattern 覆盖 trigger。单个案例不能批准整个多分支档案。

generation test 只能证明本次绑定测试。Output audit 是人工/独立语义审计的结构化记录；validator 不能凭 hash 自动证明其提取正确，也不能自动批准 profile。

## 4. 通用核心与 IP 档案边界

通用核心可以包含：语义分析法、生成控制字段、证据门槛、审批状态、数据结构、健康检查和验证工具。

IP 档案才可以包含：该 IP 的内容类型、框架、句式、节奏、说服动作、证据位置和 CTA 形态。

平台或行业风险词典应作为可配置输入或 profile 内容，不能把任一具体平台、业务、健康、财经等领域规则写成通用风格。

## 5. 失败处理

- 样本重复：暂停候选融合，等待人工决定。
- 样本太少：只输出 observation。
- 转写质量差：标记不可验证的节奏项，不按标点估算停顿。
- 框架顺序冲突：拆分，不平均。
- 找不到跨样本证据：降级观察或删除。
- 来源泄漏：删除复制片段并重新抽象；不得只换同义词规避扫描。
- 用户未批准：保持 draft，禁止下游选择。
- 选择器无匹配：明确 abstain，不强套最近框架。
- generation test 未人工审阅：不得批准 1.1 profile。
- 任何获批 profile、evidence bundle、generation suite 或 output 发生变化：旧 approval record 立即失效。
