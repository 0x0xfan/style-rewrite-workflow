你是外部高级工程师，负责源码审计、生成机制诊断、候选实现和可复现交付。Codex 是总负责人，负责本地应用、测试和最终验收。你的自评、模型自述或静态推断不能替代本地验证与用户评价。

## 核心问题

找出为什么系统出现“机器门禁通过，但真人不满意”的断层，并做最小、完整、可回归的修复。

重点攻击以下可能性，但不要预设结论：

1. `style-copywriter` 实际只是规范和后置验证器，缺少真正执行 Style DNA 1.1 的 selector/beat/pattern 计划器或生成入口。
2. legacy workbench 仍用旧风格卡和大提示词，可能绕过 approved/review_only、三输入、角色锁、selector、pattern 预算和 output audit。
3. “场景型价值预演”、过多章节包装、编号、免责声明、审计边界或知识补充把稿子变成课程说明书。
4. 规则数量、术语完整度和技术门禁替代了人类风格相似判断；辅助层压过“一句话核心模型 + 内容类型框架”。
5. 当前测试只验证事实不丢、禁词不出现，却没有验证口语节奏、信息揭晓方式、句间因果、语气密度、自然断句、具体对象推进和去 AI 腔。
6. 当前失败稿的讲述者、目标观众、案例买家、内容目标虽然已锁定，但生成动作仍可能站错视角或频繁解释“为什么这样写”。

## 不可破坏的边界

1. 风格拆解只回答“怎么说”；来源事实不得迁移到新稿。
2. 所有正式生成仍必须使用事实 contract、非空可回读知识包、指定风格档案三类输入。
3. 未批准 profile 只能用于 `evaluation_only`，不得改成 approved 或正式可交付。
4. selector 无唯一匹配、beat 缺必要槽位、事实关系不明或知识不可验证时必须 abstain。
5. 数据主体、数值、单位、周期、条件、步骤含义、CTA、风险和证据归属不得改变。
6. 不得为了“像”而复制来源原句、收益、案例、平台策略或 CTA 关键词。
7. 钱十七唯一人读主版本仍是 `style-engine/evaluation/spoken-style-profiler-qian17/钱十七-DNA-重构版.md`；不得创建 V2/正式版等并行主版本。
8. 不得把单篇修稿意见直接升级为稳定 IP DNA。新增规则必须与更简单基线比较，没增益就删除或降级。
9. 不接触真实平台、真实账号、生产模型或用户数据；不提交、不推送、不部署。

## 工作顺序

### 第一阶段：失败诊断

逐段比较：

- `user-feedback-case/unsatisfactory-output.md`
- 钱十七唯一人读主版本
- 机器 Style DNA 1.1
- `style-copywriter` 与 `qian17-copywriter` 的生成/验证规则
- legacy workbench 真实调用链

输出一张“现象 → 代码/提示词根因 → 证据位置 → 最小修复”的表。必须区分：

- 风格档案问题；
- selector/plan 执行问题；
- 生成提示词问题；
- 事实/知识输入问题；
- 评测指标问题；
- 单篇目标内容本身的问题。

### 第二阶段：建立失败优先的回归

把当前不满意稿作为失败案例，但不要把你自己的改写句子硬编码为期望输出。设计能捕捉错误机制的合同/性质测试，例如：

- 主框架先于辅助规则，且辅助动作有总预算；
- 主要章节并非全部强制包装；
- 禁止连续同壳纠偏、解释型过渡和课程目录式推进；
- 每段必须围绕具体案例对象、判断或动作推进，不能只做抽象价值说明；
- 角色锁定在卖家/操盘者视角，不把买家痛点写成观众任务；
- 真实事实边界保留，但不重复转写成免责声明；
- 简单主框架基线与增强版同时生成审计记录，增强版不能自动胜出。

测试必须因当前机制的真实缺陷失败，而不是匹配某一句理想文案。

### 第三阶段：最小实现

优先在以下范围内形成可运行闭环：

- `style-engine/skills/style-copywriter/**`
- `style-engine/tests/**` 或新的同级测试
- 为 selector、generation plan、pattern budget、avoid findings、baseline comparison 所需的最小模块
- `external-skills/qian17-copywriter/**` 中直接导致生成质量问题的规则
- legacy workbench 只做必要适配，避免 UI 大改

不要只改文档或重写这一篇稿。需要让同类后续任务可复用，并让错误机制有确定性回归。

### 第四阶段：候选影子稿

使用附件中的事实/知识/风格输入生成一份 `evaluation_only` 候选影子稿，用于说明修复后的行为差异。它不是最终成稿，也不能声称用户会喜欢。

## 验收标准

- 找到并修复至少一个可由源码和失败稿共同证明的根因。
- 形成可执行生成计划或等价机制，而不是继续堆提示词形容词。
- 当前失败机制有回归测试，旧安全门禁继续通过。
- 影子稿更少课程化、解释腔和重复包装，更接近“具体对象 → 为什么成立 → 边拆边给动作 → 回到案例算清”的自然推进。
- 不突破事实、知识、批准和来源边界。
- 改动最小、可应用、可复现；最终接受权属于 Codex 和用户。
