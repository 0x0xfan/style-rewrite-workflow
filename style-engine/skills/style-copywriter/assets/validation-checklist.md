# 生成后检查清单

## 事实锁

- [ ] 每个数值、单位、主体、时间范围和条件都与 contract 一致。
- [ ] 收益、交付或因果关系的触发机制没有被改写。
- [ ] 步骤顺序与动作含义没有变化。
- [ ] 只使用 contract 明确允许的 CTA、资源和后续安排。
- [ ] 必要风险边界被保留，未新增平台规则、收益保证或合规结论。
- [ ] 已运行 `scripts/validate-generated-copy.mjs`，并保存 `generation-validation-report.md`。

## 知识输入

- [ ] 已实际检索知识库并保存非空 `knowledge-pack.json`，不是用模型记忆补写。
- [ ] 长稿优先筛选 2–4 条相关知识，且至少 1 条已自然融入正文。
- [ ] 每条实际使用的知识都在元数据中记录有效 `source_id`、获来源允许的 `use_as`、章节和正文 `output_excerpt`。
- [ ] 知识只丰富解释、方法、机制或必要边界；其中的数值、定量/结果主张、新案例、收益和平台结论没有越过 contract。
- [ ] 知识来源说明没有进入观众稿。

## 风格控制

- [ ] selector 有唯一匹配；所用 framework 与 profile 状态允许。
- [ ] 每个 required beat 都有来自 contract 的输入。
- [ ] 所有 pattern 均在适用位置和预算内。
- [ ] 未触发任何 avoid pattern。
- [ ] 没有迁移风格样本中的事实、案例、项目、收益或 CTA。

## 观众稿隔离

- [ ] 不出现原稿、contract、DNA、截图、后台、审计、验证、生成过程等内部元话语。
- [ ] 不用编排式悬念替代真实内容衔接。
- [ ] 文本可直接朗读；元数据与审计结果不混入稿件。

## 自动报告解释

- `passed`：已提供的机器检查全部通过；不等于自动证明事实真实或风格相似。
- `warning`：缺少可机器核对的 contract 锁或引用源，需人工回读。
- `failed`：缺少强制知识输入/使用证据，或存在事实字面值、数据主体关系、禁用词、20 字连续引用重合问题；不得标为最终稿。
