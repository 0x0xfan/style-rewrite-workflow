# Spoken Style Profiler V2 - 快速入门

## 核心改进一句话

**从"什么都提取"变成"只提取有充分证据且实测有效的规则"**

---

## 5分钟快速理解

### 问题：V1 版本出了什么问题？

1. **单个样本就生成规则** → 规则不可靠
2. **修改意见被当成稳定规律** → 过度复杂
3. **风格样本的事实被迁移** → 数据归属混乱（你发现的问题）
4. **规则不断累加，没有减法** → 辅助压过主干

### 解决方案：V2 的核心机制

```
分层提取 + 证据分级 + 减法审查 + 事实分离 + 对抗测试
```

---

## 三层规则体系

### Tier 1: 核心主干（必须遵守）
- **要求**: 3+ A/B级样本
- **内容**: 框架、信息优先级、段落职责
- **权重**: 1.0
- **示例**: "开场用具体项目+数据"

### Tier 2: 稳定辅助（按需使用）
- **要求**: 2+ A级 或 3+ B级样本
- **内容**: 修辞、包装、过渡
- **权重**: 0.5-1.0
- **示例**: "先指出常见做法失效，再给新判断"

### Tier 3: 待验证（只记录，不使用）
- **要求**: 1个样本
- **内容**: 所有单样本观察
- **权重**: 不用于生成
- **示例**: "生活化消费阶梯翻译"（只在u02中出现）

---

## 样本质量分级

| 等级 | 标准 | 可以提取什么 | 最低数量 |
|-----|------|-------------|---------|
| **A级** | 可回听音视频 + 高质量转写 | 框架、句式、修辞、节奏 | 框架2个、句式2个、修辞3个 |
| **B级** | 有原文但无音频 | 框架、句式 | 框架3个、句式3个 |
| **C级** | 低质量单行转写 | 框架（宏观） | 框架5个 |

**禁止**: C级样本不得单独支持句式和修辞规则

## 减法审查流程

每次添加新规则后：

```
1. 生成 Baseline 版本（不用新规则）
2. 生成 New-rule 版本（用新规则）
3. 盲测：判断哪个更像目标
4. 决策：
   - New-rule 明显更好 → 保留，权重 1.0
   - New-rule 轻微更好 → 保留，权重 0.8
   - 差不多 → 降权，权重 0.5
   - Baseline 更好 → 删除规则
```

**累积3次"更差"判断 → 自动删除该规则**

## 事实与风格分离

### content-contract.md（事实契约）
```markdown
锁定所有事实：
- 数据：数值、主体、范围、条件
- 步骤：顺序、依赖关系
- 身份：谁在说、谁的数据
- 风险：授权、合规边界
```

### style-dna.md（风格表达）
```markdown
只提取表达方式：
- 怎么开场
- 怎么编号
- 怎么过渡
- 怎么收束
```

**关键原则**: DNA只能重构表达，不能改变契约锁定的事实

## 对抗式测试

### 4类测试用例

1. **正例测试** - 应该生成（验证正常功能）
2. **负例测试** - 应该拒绝（验证边界检查）
3. **边界测试** - 应该降级或确认（验证边界处理）
4. **破坏性测试** - 应该检测错误（验证安全性）

### 核心破坏性场景

- **数据主体混淆** - 把案例数据说成个人数据
- **样本事实迁移** - 把风格样本的事实复制到新内容
- **收益夸大** - 把条件性收益说成固定收益
- **身份篡改** - 把他人经历说成自己的
- **步骤顺序篡改** - 擅自调整契约锁定的顺序

**通过标准**: 破坏性测试必须 100% 通过

## 使用流程

### 1. 采集样本
```bash
spoken-style-profiler-v2 add-sample \
  --file "sample-001.mp4" \
  --transcript "sample-001.txt"

# 自动评分为 A/B/C 级
```

### 2. 提取核心框架（需要3+样本）
```bash
spoken-style-profiler-v2 extract-tier1

# 检查：至少3个A/B级样本支持
```

### 3. 提取辅助模式（需要2+样本）
```bash
spoken-style-profiler-v2 extract-tier2

# 检查：至少2个A级或3个B级样本支持
```

### 4. 对每条新规则运行减法审查
```bash
spoken-style-profiler-v2 subtraction-audit \
  --rule T2-P05 \
  --contract test-contract.md

# 生成对比版本，等待人工判断
```

### 5. 运行对抗式测试
```bash
spoken-style-profiler-v2 adversarial-test

# 必须100%通过破坏性测试
```

### 6. 生成测试
```bash
spoken-style-profiler-v2 generate \
  --contract test-contract.md \
  --output test-output.md
```

## 关键检查点

### 提取阶段
- [ ] 每条Tier1规则有3+ A/B级样本
- [ ] 每条Tier2规则有2+ A级或3+ B级样本
- [ ] 单样本观察全部在Tier3
- [ ] 模板复用段落已隔离

### 生成阶段
- [ ] contract和DNA严格分离
- [ ] 数据主体清晰（谁的数据）
- [ ] 条件性收益保留了条件
- [ ] 未迁移样本事实

### 审查阶段
- [ ] 每条规则都运行了减法审查
- [ ] 对抗测试100%通过
- [ ] 事实锁未被破坏

## 常见错误及避免方法

| 错误 | 后果 | 正确做法 |
|-----|------|---------|
| 单样本就生成规则 | 规则不可靠 | 记录到Tier3，等待更多样本 |
| 跳过减法审查 | 不知道规则是否有效 | 每条规则必须审查 |
| 同时测试多条规则 | 无法定位问题 | 逐条测试 |
| C级样本支持句式 | 提取质量差 | C级只能支持宏观框架 |
| 事实写在DNA里 | 迁移样本事实 | 事实全部写在contract |
| 跳过对抗测试 | 安全漏洞 | 破坏性测试必须100%通过 |

---

## 与V1的主要区别

| 维度 | V1 | V2 |
|-----|----|----|
| 证据要求 | 单样本可生成规则 | Tier1需3+，Tier2需2+ |
| 质量分级 | 无分级 | A/B/C三级，不同支持能力 |
| 减法机制 | 无 | 每条规则必须审查 |
| 事实分离 | DNA和事实混在一起 | 严格分离contract和DNA |
| 对抗测试 | 只测正例 | 4类测试，破坏性必过 |
| 规则层级 | 扁平 | 三层：核心/辅助/待验证 |
| 迭代方式 | 累加 | 减法审查，可删除 |

## 典型工作流

### 场景1: 从零开始提取新风格

```
Day 1: 采集样本
- 收集5-10个样本
- 评估质量（A/B/C）
- 录入样本库

Day 2-3: 提取核心框架
- 找到3+ A/B级样本支持的共同框架
- 每条规则运行减法审查
- 只保留"实测更好"的规则

Day 4: 提取辅助模式
- 找到2+ A级样本支持的修辞/包装
- 每条规则运行减法审查
- 降权"差不多"的规则

Day 5: 对抗式测试
- 准备4类测试用例
- 重点测试破坏性场景
- 修复所有P0/P1问题

Day 6: 生成测试
- 准备3-5个真实契约
- 生成并人工评估
- 迭代优化

Day 7: 审批发布
- 检查所有检查点
- 对抗测试100%通过
- 标记为approved
```

### 场景2: 改进现有V1档案

```
Step 1: 审计现有规则
- 检查每条规则的样本支持
- 单样本规则 → 移到Tier3
- 低质量样本支持的规则 → 标记为待审查

Step 2: 运行减法审查
- 对每条Tier2规则运行审查
- 删除"让生成变差"的规则
- 降权"差不多"的规则

Step 3: 分离事实与风格
- 把数据、案例、资源从DNA移到contract模板
- DNA只保留表达方式
- 检查是否有样本事实泄漏

Step 4: 对抗式测试
- 重点测试数据主体混淆
- 重点测试样本事实迁移
- 修复所有安全问题

Step 5: 重新批准
- 满足V2标准后重新标记approved
```
