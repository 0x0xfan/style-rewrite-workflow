# Source Contract：社区咖啡店预约与回访表服务

> 本 contract 由人工从 `source-raw.md` 锁定；阶段 2 自动提取器未实现。

## 项目核心

- 主题：为社区咖啡店搭建预约、取餐记录和回访表。
- 目标受众：需要减少预约消息整理时间的本地门店店主。
- 内容类型：低门槛项目/服务拆解。
- 允许的 CTA：评论“咖啡表”领取表格结构和搭建清单。

## 锁定数据与主体

| ID | 数据与主体 | 条件或范围 |
|---|---|---|
| d01 | 社区咖啡店 7 天收到 41 条预约消息，对应 26 位到店顾客 | 试运行前的咨询整理 |
| d02 | 店主此前每天花 2 小时处理确认、聊天记录和回访 | 日常操作 |
| d03 | 首次搭建服务收 399 元 | 首次搭建 |
| d04 | 服务包含 3 张表 | 预约表、取餐记录、回访表 |
| d05 | 预约确认时间为每天 10:00 到 20:00 | 确认时间窗口 |
| d06 | 超过 24 小时未回复的咨询单独标记 | 咨询处理规则 |
| d07 | 12 位老顾客进入回访名单，第 6 天再回访 | 到店后回访机制 |
| d08 | 试运行记到 18 单复购 | 试运行记录 |
| d09 | 后续维护为 99 元一个月，先给 2 家门店试用 | 维护与试用范围 |
| d10 | 店主第一次学会填表约 30 分钟；每日收店前看表 5 分钟 | 使用动作 |
| d11 | 目标是把回复预约消息的时间压低 60% | 目标，不承诺已实现 |

## 锁定步骤

1. 按到店、改期、未回复分类最近咨询。
2. 搭建 3 张表，并设置 10:00 到 20:00 的确认时间。
3. 设置回访名单和每日复盘。

## 锁定边界

- 这是合成测试素材，不得写成真实案例或讲述者个人业绩。
- `60%` 是目标，不能改写成已经实现的结果。
- `18 单复购` 仅属于试运行记录，不能外推给所有门店。
- 不新增平台流量、收益保证、资格或合规结论。
