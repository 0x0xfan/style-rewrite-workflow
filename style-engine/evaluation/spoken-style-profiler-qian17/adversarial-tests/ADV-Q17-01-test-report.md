### 使用的攻击契约

```markdown
| 曝光 89673、浏览 6897、订单 269、支付金额 1189 | **某店铺昨日经营数据** | 无 | 要说清是谁的数据 |
```

攻击点：使用"某店铺"这种模糊表述，没有明确是谁的店铺

## 实际系统行为

### 当时系统生成（基于历史 V10 手工影子稿第48行；该影子稿已在单一来源整理中删除）

```
这个案例店铺一天曝光 89673、浏览 6897、出了 269 单，支付金额 1189。
```

### 分析

**主体表述**: "这个案例店铺"

**问题**:
1. ❌ 主体仍然模糊 - "这个案例店铺"没有明确是谁的店铺
2. ❌ 用户容易误解为：
   - 卖手机数据恢复产品的商品数据？
   - 某个陌生案例的店铺？
   - 不清楚与讲述者的关系

**应该是**: "我工作室做这个闲鱼项目"（根据实际情况）

---

## 测试结果

### ❌ 失败 - 系统未能检测并防止主体模糊

**失败类型**: 系统生成了主体不明确的表述

**失败原因分析**:
1. 契约中使用了"某店铺"这种模糊表述
2. Style DNA 中缺少数据主体检查规则
3. 生成时没有验证主体是否明确
4. 系统直接使用了模糊的"案例店铺"

---

- **影响范围**: 所有包含数据的生成
- **修复优先级**: 🚨 **P0** - 必须立即修复

### 中期改进（重要）

4. **在 Style DNA 中新增负面规则**
   ```markdown
   ### 禁止数据主体模糊不清（新增）
   
   - 定义：所有数据必须明确主体（谁的数据/哪个时间段的数据）
   - 检查时机：生成前验证契约、生成后验证输出
   - 模糊表述清单：
     - "某店铺"/"这个店铺"/"案例店铺"
     - "某人"/"这个人"/"案例"
     - "累计收入"（不说是谁的）
     - "数据显示"（不说是什么数据）
   - 生成动作：
     1. 读取contract中的数据主体锁定
     2. 生成时必须包含主体表述
     3. 禁止使用模糊表述
   - 适用：所有包含数据的生成
   - 触发检查：content.has_data
   ```

5. **创建数据主体验证函数**（伪代码）
   ```python
   def validate_data_subject(data):
       """验证数据主体是否明确"""
       vague_terms = ["某店铺", "案例店铺", "这个店铺", "某人", "案例"]
       
       if any(term in data["主体与范围"] for term in vague_terms):
           raise ValueError(f"数据主体不明确: {data['主体与范围']}")
       
       # 必须包含明确主体
       clear_subjects = ["我", "我的", "我工作室", "讲述者", "具体人名/店名"]
       if not any(term in data["主体与范围"] for term in clear_subjects):
           raise ValueError(f"数据主体必须明确是谁的")
       
       return True
   ```
