# 钱十七口播 DNA：减法校准人工审阅清单

> 当前仍是 draft / observation / review_only。这份清单只请你判断风格理解是否正确，不会自动批准或进入正式仿写。

## 一句话核心模型

> 钱十七会快速展示一个具体、值得关注的项目或结果，用数据和判断说明为什么成立，再把资源、准备、上架、交付和收益路径拆清楚。进入主要章节前，他常用一两句描述性承接，先说明下一环节为什么重要、能解决什么或不做会怎样，再进入方法；不是裸报目录，也不是讲自己的研究过程。

请判断：保留 / 修改 / 删除

## A. 必须稳定的主干

### A01 具体项目或结果直接开场

- 第一到第二句就让观众知道在讲什么项目、产品、问题或结果。
- 有可靠数字时使用一组最强数字，不把所有数据堆在开头。
- 不用“我拆了一遍、我先发现、我继续往下看”拖慢主题。

建议：保留

### A02 迅速说明为什么值得看

- 从真实需求、市场信号、效率或收益里选一个最强理由。
- 只解释一层，不在开头同时塞认知差、人群代入、商业模型和价值升维。

建议：保留

### A03 先报路径，再编号拆解

- 用一句话告诉观众本期会拆哪几个环节。
- 随后按项目真实路径推进，不为了形式硬凑步骤。

建议：保留

### A04 每段只讲一个环节

基本结构：点名当前环节 → 一个关键判断或理由 → 具体动作 → 必要时补数据或结果。

- 不是每段都使用“很多人错了—真正关键—新标准”。
- 全篇最多保留一到两次真正有价值的纠偏。

建议：保留

### A05 数据贴着它要证明的内容出现

- 开头数据证明项目值得看。
- 店铺或过程数据放在对应步骤。
- 单笔账和累计结果放在收益段。
- 口播直接讲事实，不念“截图显示、计算器显示、更新时间”。

建议：保留

### A06 收益关系直接算清

- 先解释交付或收益为什么成立，再把单笔账、条件项和累计结果讲清。
- 不把案例结果变成人人都能做到的保证。
- 不强制把结尾升维成商业模型。

建议：保留

### A07 用目标内容自己的资源和身份收尾

- CTA、口令、渠道、资源和签名全部读取目标输入。
- CTA 前只需一句自然项目总结，不强制“你真正要学的是背后的方法”。

建议：保留

## B. 只能按需使用的辅助层

### B01 段落价值承接

只在主要章节切换时使用：上一环节或当前状态 → 下一环节还缺什么、为什么重要或不做会怎样 → 进入方法。

- 长稿通常使用二到三次，不覆盖每个小步骤。
- 每次承接使用不同的真实关系，例如信任、重复交付、效率或收益。
- 不能只写“接下来、第二、第三”，也不能反复写“最关键、一定要看”。

建议：保留为钱十七的重点辅助规则

### B02 局部认知差

当目标内容确实有“表面一层”和“第二层机制”时，可以使用一次：常见理解 → 被忽略的一层 → 具体证据或方法。不能把它变成全文主结构。

建议：保留为低权重观察

### B03 人群代入

目标内容明确受众和门槛时，可以用一句说明谁适合继续听。没有明确受众时删除。

建议：保留为可选

### B04 局部纠偏

只有真实错误做法存在时才使用“不是 X，而是 Y”或“这个顺序反了”。全篇最多一到两次。

建议：保留为可选

### B05 数据价值翻译

每组数据最多解释一层直接意义，不能从相关性推成因果或结果保证。

建议：保留

### B06 必要风险

版权、隐私、违法、资金损失或会让步骤失效的红线，压进对应动作的一句话里。详细审计留在稿外。

建议：保留

## C. 本轮明确删除或回退的过拟合控制

### C01 删除“研究者/拆解者必须先讲自己的过程”

原因：它让开头变成“我做了什么”，反而晚于项目和结果；“我把项目拆了一遍，先发现……”已经被用户明确否定。

### C02 删除“完整认知旅程贯穿全文”

原因：原样本只支持局部纠偏，不足以证明每篇都按“旧理解—新标准—升维”推进；强行使用会让每段同壳。

### C03 删除“表面值—疑问—真实值”作为钱十七稳定 DNA

原因：0.2→19.9 是本篇目标内容的有效揭晓关系，应保留在本篇 content contract，而不是上升成钱十七所有稿件的固定风格。

### C04 删除“每段错误关注点—真正关键—新标准—动作”

原因：同一测试稿连续使用后 AI 味加重，压过项目解释。

### C05 删除“没有人物位置就是说明书”

原因：钱十七可以直接讲项目；说明书感来自缺少判断、收益和口语推进，不等于必须增加第一人称研究过程。
