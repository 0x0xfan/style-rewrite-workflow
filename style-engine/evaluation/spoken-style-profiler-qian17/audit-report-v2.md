#### 2. 新增数据主体检查规则

```markdown
### 禁止数据主体模糊不清（新增）（observation）

- 定义：所有数据必须明确主体（谁的数据/哪个时间段的数据）
- 生成动作：
  1. 读取contract中的数据主体锁定
  2. 生成时必须包含主体表述（"我的"/"我工作室的"/"案例商品的"/"XX店铺的"）
  3. 禁止使用模糊表述（"某店铺"/"这个店铺"/"案例"）
- 适用：所有包含数据的生成
- 触发检查：content.has_data
- 依据：human_boundary + adversarial_test_required
```

#### 3. 加强 contract 模板的数据锁定

在 source-contract.md 中，每个数据都必须包含：
- 数值
- **主体**（明确是谁的）
- **范围**（多久的/什么条件下的）
- **输出要求**（口播必须如何表述）

### 中期改进（中优先级）

#### 4. 运行减法审查

对以下规则运行对比测试，判断是否真的有效：

- "案例环节自然承接"（这条规则可能会让生成变啰嗦）
- "数据—说明什么—为什么值得关注"（可能会过度解释）
- "在可保存信息旁提示互动"（可能会打断节奏）

测试方法：
1. 生成不用这条规则的版本
2. 生成用这条规则的版本
3. 盲测对比
4. 决定保留/降权/删除
