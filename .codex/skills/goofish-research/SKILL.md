# Goofish Research

只采集真实页面事实和真实截图，不生成文案，不用模拟数据补齐失败项。

## 读取

- 开始前读取 [references/capture-schema.md](references/capture-schema.md)。
- 浏览器任务使用已登录的 Chrome 插件；不要启动独立 Playwright profile，也不要读取 Cookie、Storage、密码或令牌。
- 需要把证据包交给文案 Skill 时，只传递生成后的 `report.md`、结构化 JSON 和实际存在的图片。

## 工作流

1. 根据用户产品名确定一个精确搜索词。需要同义词时逐个执行；一个词失败两次后停止该词，不扩大猜测。
2. 在已登录的 Goofish 搜索页读取页面标识、首屏商品卡片、价格、可见“人想要”、链接和卖家自述。卡片数量只是本次采样数，不是搜索结果总量。
3. 使用浏览器截图接口保存搜索页和必要的详情页截图。每次写入后必须检查文件存在、文件大小大于零且可被图片库解码。
4. 只有真实文件通过检查后，才能把它登记进 `capture.json.screenshots`。截图失败时写 `status: blocked_screenshot` 和原因；不得先写文件名再声称已截图。
5. 把浏览器读取结果写成符合 schema 的 `capture.json`，为每项事实保留 `source_url`、`captured_at` 和来源层级。
6. 运行证据包构建器：

   ```powershell
   python scripts/build_evidence_package.py `
     --capture '<capture.json>' `
     --output '<run-directory>'
   ```

7. 回读 `meta.json`、`products.json`、`analysis.json`、`report.md` 和 `screenshots/manifest.json`。逐张打开 manifest 中的图片；图片数与磁盘文件数必须一致。

## 截图规则

- 优先使用稳定的可视区域截图。整页截图或坐标裁剪失败时，不得把裁剪当作成功条件；可改为直接打开目标详情页后截取可视区域。
- 搜索总览截图必须能看到搜索词、页面标识和至少一排商品卡片。
- 详情截图应同时覆盖价格、想要数/浏览量和商品描述中的目标事实。
- 截图路径使用证据包内相对路径；manifest 同时保存 SHA-256、像素尺寸、来源 URL 和采集时间。
- 不生成或复用与本次页面无关的历史图、模拟图、占位图或虚构文件名。

## 数据红线

- “人想要”只能写成单品兴趣信号，不能写成订单、销量或总市场需求。
- 店铺卖出件数、好评率和店龄属于店铺，不得当成单品销量。
- 卖家的交付时间、成功率、退款、赠送额度和服务效果必须标为卖家自述。
- 同一页面的数字会实时变化；搜索页和详情页不一致时分别保留时间与来源，不强行合并。
- 没有详情页证据时，不生成浏览量、发布日期、店铺销量或详情结论。

## 输出边界

成功的证据包至少包含一个可解码的真实截图。若页面数据可以读取但截图失败，输出部分证据包和明确阻塞报告，不得标为完整采集。
