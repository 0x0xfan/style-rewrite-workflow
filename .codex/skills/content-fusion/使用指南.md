# content-fusion Skill 使用指南

## 简介

content-fusion 是一个整合"项目事实 + 项目知识 + 风格化"三源数据，自动生成闲鱼运营文案的工具。

**核心能力**：
- 生成 B站视频脚本（含口播、画面、时间轴）
- 生成闲鱼标题优化方案（3-5个方案，带评分）
- 生成商品描述
- 自动合规检查（违规词检测）
- 数据可追溯（每个关键数据标注来源）

## 快速开始

### 第1步：准备数据

使用 goofish-research 采集项目事实数据：

```bash
cd D:\圣矾IP运营\skills\goofish-research
python main.py --product "你的产品名" --mode quick
```

这会在 `outputs/` 目录生成证据包，包含：
- `meta.json` - 元信息
- `analysis.json` - 市场分析（价格、需求、竞争）
- `products.json` - 商品列表
- `keywords.json` - 关键词
- `report.md` - 可读报告
- `screenshots/` - 截图素材

### 第2步：创建输入配置

在证据包目录创建 `fusion_input.yaml`：

```yaml
# 证据包路径（必需）
evidence_package: "D:\\圣矾IP运营\\skills\\goofish-research\\outputs\\你的证据包目录"

# 场景类型（必需）
scenario: "video"  # 可选: video, title, description

# 知识检索参数（必需；缺失即停止生成）
knowledge_params:
  product_type: "虚拟产品"  # 必填，或 "实物产品"
  tags:
    - "服务类产品"
    - "其他标签"

# 风格参数（可选）
style_params:
  style_card: null  # 使用通用风格，或指定风格卡名称如: "钱十七"
```

### 第3步：生成文案

```bash
cd D:\项目仓库\风格仿写\.codex\skills\content-fusion

# 生成视频脚本
python main.py --input "证据包目录/fusion_input.yaml" --output "证据包目录/content-output"
```

## 场景使用示例

### 示例1：生成 B站视频脚本

**输入配置** (`fusion_input.yaml`)：
```yaml
evidence_package: "D:\\圣矾IP运营\\skills\\goofish-research\\outputs\\2026-07-27_codex代安装_quick"
scenario: "video"
knowledge_params:
  product_type: "虚拟产品"
  tags: ["服务类产品", "远程服务"]
style_params:
  style_card: null
```

**运行命令**：
```bash
python main.py --input fusion_input.yaml --output content-output
```

**输出文件**：
- `video_script.md` - 视频脚本（Markdown格式，人类阅读）
- `video_script.json` - 视频脚本（JSON格式，程序处理）
- `knowledge-pack.json` - 可审计知识包（`schema_version` 固定为 `1.0`）；style-copywriter 应引用每个来源的 `id`、`excerpt`、`locator`、`allowed_uses` 和 `content_sha256`
- `compliance_report.json` - 合规检查报告
- `material_list.json` - 素材清单（截图、知识文章）

**视频脚本结构**：
- 开头钩子 (0-10s)
- 需求验证 (10-30s)
- 价值说明 (30-60s)
- 实操演示 - 价格策略 (60-90s)
- 实操演示 - 交付说明 (120-150s)
- 避坑提示 (150-180s)
- CTA (180-200s)

每段包含：
- 画面描述（截图、动作）
- 口播内容
- 数据来源标注（事实来源、知识来源、风格特征）

**市场数据**（来自 goofish-research）：
- 搜索结果：10个首屏商品
- 价格范围：7.9-19.9元
- 中位价格：11.84元
- 最高想要数：1536人

- 环境搭建与安装报错处理
- 大模型/API接入与配置指导
- 中文化、插件、微软商店与启动问题
- 面向不会配置环境的Windows/Mac新手

**竞争信号**：
- 首屏10条均为远程安装/部署/调试类服务
- 价格带集中在7.9—19.9元
- 多条强调10—15分钟完成、全程远程

**价格策略** (60-90s)：

## 配置文件说明

### 主配置文件 (`config.yaml`)

位置：`D:\项目仓库\风格仿写\.codex\skills\content-fusion\config.yaml`

```yaml
# 知识库 API 路径
knowledge_api_path: "D:\\项目仓库\\闲鱼知识库\\scripts\\knowledge_api.py"

# 风格卡目录
style_cards_dir: "D:\\项目仓库\\风格仿写\\风格卡"

# 违规词列表
violation_words:
  - "躺赚"
  - "零成本"
  - "日入"
  - "月入"
  - "暴利"
  - "必赚"
  - "保证"
  - "绝对"
  - "100%"
  # ... 更多

# 场景配置
scenarios:
  video:
    description: "B站视频文案生成"
    output_format: ["markdown", "json"]
    include_compliance: true
    include_materials: true
  
  title:
    description: "闲鱼标题优化"
    output_format: ["markdown", "json"]
    title_count: 5
  
  description:
    description: "商品描述生成"
    output_format: ["markdown"]
```

**一般情况下不需要修改主配置文件**。

### 输入参数文件 (`fusion_input.yaml`)

每次生成文案时需要创建的文件：

```yaml
# 1. 证据包路径（必需）
evidence_package: "证据包的完整路径"

# 2. 场景类型（必需）
scenario: "video"  # 可选: video, title, description

# 3. 知识检索参数
knowledge_params:
  product_type: "虚拟产品"  # 必填，或 "实物产品"
  tags:
    - "标签1"
    - "标签2"

# 4. 风格参数（可选）
style_params:
  style_card: null  # 或指定风格卡名称
```

`knowledge_params` 是每次生成的硬性输入：缺失、API 不可读、零结果或任一结果缺少正文都会终止流程，不会回退到默认或模拟知识。每次成功输出都会包含 `knowledge-pack.json`，供下游 style-copywriter 逐条引用和审计。

## 常见问题

### Q1：显示"已加载项目事实: codex代安装，Top 想要数: 0"

**原因**：fact_loader 没有正确读取数据。

**解决**：确认证据包目录包含：
- `meta.json`
- `analysis.json`
- `products.json`

### Q2：报错“知识库没有返回相关内容，停止生成”

**原因**：知识库 API 路径不可读、查询没有结果，或返回条目没有正文。Skill 不会使用模拟数据、默认知识或旧结果继续生成。

**解决**：
1. 检查 `config.yaml` 中的 `knowledge_api_path`
2. 确认 `D:\项目仓库\闲鱼知识库\scripts\knowledge_api.py` 可导入，并且 `KnowledgeAPI` 能读取 `cleaned/index.json`
3. 调整必填的 `knowledge_params.product_type` 和可选 `tags`，直到检索到带正文的条目

### Q3：报错“缺少必需参数: knowledge_params”

**原因**：每次文案生成都必须提供知识库检索条件，不能退回只用项目事实或风格卡的模式。

**解决**：在输入文件中添加至少：

```yaml
knowledge_params:
  product_type: "你的产品类型"
  tags: []
```

### Q4：发现违规词

**原因**：生成的文案包含违规词列表中的词汇。

**解决**：查看 `compliance_report.json`，手动修改生成的文案。

### Q5：Windows 控制台乱码

**原因**：编码问题。

**解决**：已在代码中添加 `sys.stdout.reconfigure(encoding='utf-8')`，如果仍有问题，运行前执行：
```powershell
$OutputEncoding = [System.Text.Encoding]::UTF8
```

## 技术架构

```
输入层：fusion_input.yaml
   ↓
加载层：
   ├── FactLoader (加载 goofish-research 证据包)
   ├── KnowledgeRetriever (检索知识库)
   └── StyleLoader (加载风格卡)
   ↓
生成层：ContentGenerator (融合三源数据 → 生成文案)
   ↓
输出层：OutputFormatter (格式化 → Markdown/JSON)
   ↓
输出文件：video_script.md, titles.md, compliance_report.json
```
