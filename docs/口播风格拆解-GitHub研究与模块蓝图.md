# 口播风格拆解：GitHub 研究与模块蓝图

日期：2026-07-22  
状态：历史研究蓝图；已由 F008 `$spoken-style-profiler` 的外部证据与批准契约落地并取代，仍不包含 UI 或改写功能实现。

## 当前目标

项目的近期目标不是做通用“文章仿写器”，也不是视频生成器，而是可靠地把一批**短视频口播稿**拆成可验证、可复用、但不携带原文事实的风格资产。

第一对象仍为钱十七闲鱼口播样本。用户已确认 `ips/钱十七/dna/钱十七-DNA-重构版.md` 为合格写作基准；`ips/钱十七/dna/钱十七-DNA-重构版.md` 是同一文件的工作台 hard-link 别名。机器 JSON 的正式证据状态仍独立保持 `draft/review_only`。

## 口播专用的七层 DNA

长文的“语言、结构、选题、素材、认知、视觉”不能直接照搬。口播需要先接受时长、声音和停留机制的约束，因此采用下列七层：

| 层 | 要回答的问题 | 典型产物 |
| --- | --- | --- |
| L0 口播规格 | 一条常见多长、每段承担什么节拍、哪里适合停顿或切镜头？ | 时长范围、字数范围、节拍序列 |
| L1 钩子与落点 | 前 3–10 秒怎样让人停留？结尾如何让人记住或行动？ | 钩子类型、兑现承诺、结尾落点 |
| L2 结构路径 | 痛点、立场、框架、排雷、方法、互动、CTA 如何排列？ | 按内容类型区分的结构模板 |
| L3 口语与节奏 | 句长、语气、推进词、反差句、生活化结果对比、停顿和重复如何使用？ | 口播指标、表达规则、句式公式、禁用项 |
| L4 说服与关系 | 如何建立“我替你避坑”的可信关系，如何排雷，如何降低行动门槛？ | 说服动作及适用条件 |
| L5 证据与素材位 | 数据、截图、录屏、清单出现在哪里，各自证明哪句话？ | 素材功能矩阵与插入条件 |
| L6 边界与风险 | 什么只能学形态，什么不能带入新稿；哪些语气会变成收益/合规风险？ | 来源隔离、风险词和替换规则 |

其中 L4 只沉淀表达机制，例如“先排雷再给方法”，不沉淀原作者的项目判断、产品主张、收益数字或具体操作。

## 模块边界

```text
M1 语料登记与分段
  -> M2 样本健康与人工取舍
  -> M3 七层标注与证据索引
  -> M4 规则融合与冲突处理
  -> M5 DNA 打包、确认与版本
  -> M6 留出样本验证与回归
```

### M1：语料登记与分段

- 输入：用户拥有或获准用于研究的完整口播文本。
- 输出：样本 ID、标题、主题、发布日期（如有）、文本、段落/句子锚点、内容类型、估计时长。
- 规则：原始语料与 DNA 分开；DNA 只保留锚点 ID 和抽象规则，不复制原文段落或来源事实。

### M2：样本健康与人工取舍

- 检查：样本数、字数/时长分布、重复、固定开场、题材覆盖、过短样本、单条异常样本。
- 输出：健康报告、保留/排除清单、未解决警告。
- 决策：模板不能自动删除；只有用户确认后才不参与统计。

### M3：七层标注与证据索引

- 每条规则必须带：`rule_id`、层级、规则、适用条件、不适用条件、证据锚点至少 2 个、置信度、风险等级。
- 允许一条规则被否决：找不到跨样本证据，就只能写为“待验证观察”，不能进入稳定 DNA。

### M4：规则融合与冲突处理

- 将跨样本重复出现的规则合并为候选 DNA。
- 同一作者不同内容类型的结构分开保存，例如“项目拆解型”不能强行套到“故事复盘型”。
- 对冲突规则写清楚触发条件，而不是平均成模糊风格。

### M5：DNA 打包、确认与版本

- 人读入口：`Style-DNA.md`，按七层写成可执行规则。
- 机器入口：`style-dna.json`，只保存指标、规则、置信度、锚点 ID、版本与边界。
- 版本只有在用户确认样本取舍和规则后才标为 `approved`；否则为 `draft`。

### M6：留出样本验证与回归

- 留出至少一条未参与规则融合的口播稿，检查 DNA 是否能解释它的主要结构和节拍。
- 后续仿写前后分开评估：风格贴合、事实保真、证据覆盖、风险边界，不允许一个“像”掩盖另一个失败。
- 人工审批仍是最终门槛；模型打分只用于发现问题。

## 项目目录提案（暂不创建）

```text
engine/
  contracts/                 # 样本、规则、DNA、评测报告的 JSON 契约
  corpus/                    # 登记、切分、锚点，不放进公开 DNA
  health/                    # 重复、模板、覆盖度检查
  analyzers/                 # L0–L6 的独立分析器
  fusion/                    # 候选规则合并、冲突与置信度
  profiles/                  # 人读 Markdown + 机器 JSON + 版本快照
  evaluation/                # 留出验证、评分量表、回归案例
  cli/                       # 仅命令行入口；不包含 UI
```

## 对钱十七样本的第一轮动作

1. 固定“什么算一个样本单元”的规则，解决现有 DNA 写 8 个、健康检查写 9 个的冲突。
2. 对 8 个 `##` 口播单元建立元数据和锚点；标题行不再误计入样本。
3. 完成 M2：人工审阅已发现的近重复，决定保留还是排除。
4. 用七层而非现有三段式卡片重新标注；所有稳定规则都要能回查到多个锚点。
5. 生成钱十七 `draft` DNA，人工确认后才生成 `approved v1`。

## 明确冻结项

- 不改 UI、浏览器交互、飞书读取、TTS、视频生成、发布平台。
- 不生成新的仿写稿。
- 不引入第三方仓库代码、模型权重、未经授权语料或“金句库”。

## 已确认的执行边界

1. 当前阶段只处理“文字口播 DNA”；素材和视觉只记录其在口播中的证明/插入位置，不分析画面风格。
2. 先用钱十七的 8 个口播单元验证引擎，再接入其他 IP 的口播文案。
3. 每个 IP 的 DNA 必须经过人工确认才能升级为 `approved` 并用于正式仿写。
