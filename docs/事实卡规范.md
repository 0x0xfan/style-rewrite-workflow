# 事实卡规范

> 事实卡 = 生成环节的**事实 contract**。它是"这一选题里，哪些是真的、来源在哪、核到什么程度"的唯一凭据。写稿只能引用事实卡里的数字与结论，不得自带事实。
>
> 本规范以人写基准版 `research-runs/2026-08-26_ai拼车_验证/事实卡草稿.md` 为纲定版。机器组装器 `engine/factcard/build-fact-card.mjs` 按本规范自动填一部分字段，其余必须人补。
>
> **总状态红线：事实卡默认状态是"草稿"。未经用户抽检，任何事实卡都不得进入生成。** 核实以用户抽检为准，门禁不替代人判。

---

## 一、卡头（机器自动填）

| 字段 | 含义 | 来源 | 合格线 | 谁负责 |
| --- | --- | --- | --- | --- |
| 状态 | 草稿 / 已抽检 | 机器默认"草稿"，用户抽检后手改 | 进生成前必须是"已抽检" | 机器填默认，用户改 |
| 采集时间 | 数据什么时候采的 | capture.json `captured_at` | 有确切时间戳 | 机器 |
| 数据来源 | 采集脚本 + 采集范围 + status | capture.json `source` / `capture_scope` / `status` | status=ok/verified；范围写清"第几页几条 + TopN 详情" | 机器 |
| 搜索页 | 可回溯的搜索链接 | capture.json `source_url` | 链接可点开复核 | 机器 |

## 二、逐字段定义

下表"填法"一栏：**机器**＝组装器自动填且可信；**机器(草稿)**＝组装器给骨架/占位，必须人工核实或改写；**人补**＝机器不填，人写。

### 1. 受众档位
- **含义**：这篇讲给谁听——付费能力、痛点、对什么敏感。项目级事实，不属于任何 IP。
- **来源**：命令行 `--audience`；最终以 `docs/audience-lock.md` 的锁定为准。
- **合格线**：说清 narrator（谁在讲）/ target_viewer（讲给谁）/ content_goal（要他做什么）；不得写成"面向已入行卖家"（受众漂移，历史四次拒稿的根因）。
- **填法**：机器(草稿)——给了 `--audience` 就回填并标"仍需对齐 audience-lock.md"；没给标缺口。**人补/人锁**。

### 2. 核心结论
- **含义**：这个选题"是什么、需求成不成立、做主号/短测/放弃"的一句话判断。
- **来源**：命令行 `--conclusion`（人工题材判断的结论）。
- **合格线**：结论要能被下面的事实清单/同行数据支撑，不能是感想。
- **填法**：**人补**——机器不替代题材判断，只在缺口处提示可参考哪些信号（需求密度、标题一致性、价格分层）。

### 3. 事实清单（来源 + 核实状态 + 稿里怎么说）
- **含义**：本卡所有"事实"的清单，每条标来源、核到什么程度，**以及口播里怎么念**。这是 contract 的核心。
- **来源**：机器从 capture.json 派生可机械核对的事实；缺口项列出并标 `❌缺口`。
- **表头固定五列**：`| # | 事实 | 来源 | 核实状态 | 稿里怎么说 |`。
- **合格线**：
  - 每条事实必须能回到"数据或链接"（继承 goofish-research 证据底线）。
  - 实采项标 `✅已核实(实采)`；用户口头线索（如 `--cost`）标 `⚠️待核实(线索，非实采)`；没有来源的标 `❌缺口`。
  - **单品口径与店铺口径分行写，不混同一条。**
  - **每条事实都要有"稿里怎么说"**，不能念的也要填（写"不入稿（原因）"），不许空着进生成。
- **机器自动填的事实**：搜索页采集条数与"显示想要"条数、Top 想要分布、价格分层分桶、每个 Top 的单品指标（想要/浏览/价格）与店铺指标（店龄/累计已售/好评率）。机器把"稿里怎么说"留空。
- **人补/人核**：拿货价、供应路径合规性这类缺口的闭合；抽检时逐条核对机器填的数字与 capture 一致；**"稿里怎么说"一列全部人补**。

#### 3.1 事实清单的分节（固定四段，顺序不变）

| 小节 | 放什么 | 能不能念 |
| --- | --- | --- |
| **3A 实采** | 本次采集并核实的事实 | ✅ 按"稿里怎么说"念 |
| **3A-授权口径** | 用户明确授权或裁定可入稿的说法（如「一单约十块」「本产品无返利」），每条写明授权日期、来源、写法边界 | ✅ 按"稿里怎么说"念。**必须单独成节、紧跟 3A 之后，不得放在 🚫 小节底下**——2026-09-06 复盘：授权行放在 §3C 下面，写手不敢用 |
| **3B 用户历史口播 / 画面** | 用户往期讲过的数字与画面，标"历史经验需复核" | ✅ 按"稿里怎么说"念；来源说成"我之前看的时候"，不报期数 |
| **3C 🚫 收入 / 效果话术** | 只记录、不入事实、不入稿 | ❌ 整节不入稿；本节不放任何可念的东西 |

#### 3.2 "稿里怎么说"一列（写手唯一能念的一列）

- **含义**：每条事实给一句口播里可以直接念的说法。写的是"话"，不是"事实的摘要"。
- **写法四条**：
  1. **不带内部词**。
  2. **不带阿拉伯数字**：数字全用中文（"二十六块五""两万八千多""百分之九十九"），价格用"块"。
  3. **大数取整加"多"**：28893 → "两万八千多"；7020 件 → "七千多件"；不念到个位。
  4. **不带对同行的负面评价**。
- **不能念的也要填**，格式 `不入稿（原因）`：
  - 同行负面信息（好评率低、平台在店铺页挂的提示、店里什么都卖）→ `不入稿（负面）`（用户 2026-09-08：「不要把负面信息展示出来」；案例只炫不贬）；
  - 用户裁定不写的 → `不入稿（用户裁定：…）`；
  - 跟生意链挂不上的 → `不入稿（跟生意没关系）`；
  - 数字待核实的 → `不给数（待核实）` + 一句不带数的说法。
- **内部词只许出现在 编号 / 事实 / 来源 / 核实状态 / 备注 列，"稿里怎么说"一列一个都不许有。** 清单以 `docs/用户校准词表.json` 里 `类型=内部术语` 的条目为准（红条、挂红条、口子、规则卡、想要数、口径、实采、事实卡、事实链、SKU、Top1、环节、一跳、该学哪一家），另加 A6 / B7 这类事实编号和"店铺口径 / 单品口径"。
- **交卡前校验**：用词表的内部术语条目对"稿里怎么说"一列 grep，必须零命中。

#### 3.3 写手与审稿怎么用这一列

- **写手只许念"稿里怎么说"这一列**。事实、来源、核实状态、备注列是给主线程核数用的，写手不读、不抄、不改写。
- **主线程审稿对着这一列查**：稿里每个数字、每个说法都要能在这一列找到出处；稿里冒出内部词，先查是不是这一列没写干净——**改卡不改稿**，堵源头。

### 4. 同行数据（Top，单品 vs 店铺严格分开）
- **含义**：Top 几个同行的可验证数据，用来证明需求真实、给推算打底。
- **来源**：capture.json `detail_evidence[]`（有则用，单品/店铺分列）；没有详情则退回搜索页 Top 想要商品。
- **合格线（红线）**：
  - **单品口径**只有两项：想要、浏览。
  - **店铺口径**：店龄、累计已售、好评率——`累计已售`是**店铺**卖出总数，**不是本单销量**；闲鱼详情页不提供单品已售。
  - 表下必须保留红线注释。**把店铺已售写成单品销量＝口径造假，直接废稿。**
- **填法**：机器——全自动，数字须与 capture 逐一对得上。

### 5. 利润推算
- **含义**：从"想要"推估算单量，再看流水量级；**不出利润点估计**。
- **来源**：Top 商品的想要数 + 现价（capture）；拿货价来自 `--cost`（线索，需核实）。
- **合格线（口径红线，来自需求说明 2026-08-26 用户拍板）**：
  - 估算单量 = **想要数 × 30%–50%**，**只写区间**，每处标"推算"；拿不准取下限。
  - 组装器区间取 `下限 = floor(想要×30%)`、`上限 = ceil(想要×50%)`，并把原始算式打出来（如 `17×30%–50% = 5.1–8.5 → 约 5–9 单`）以便复核。
  - **流水** = 单量 × 现价，是成交额量级参考，**未扣成本、不是利润**；价格为区间/按量计价的商品不折算。
  - **利润 = 单量 × 单利，单利 = 售价 − 拿货价。拿货价缺口未核实 → 本卡不出利润数字。** 补齐并核实拿货价后才可推收益区间，且仍取下限、标"推算"。
- **填法**：机器——单量区间与流水量级自动算；**利润数字永远等人核实拿货价后再出，机器不给**。

### 6. 供应路径
- **含义**：货/额度从哪来、怎么交付、能不能合规复制、可不可持续。
- **来源**：命令行 `--supply`（线索）；正式结论须做资源溯源（GitHub/官方渠道/网盘）。
- **合格线**：核实前，文案**不得**写"零成本 / 直接拿货 / 稳赚 / 绝对稳定"。给了 `--supply` 标"待溯源核实"；没给标缺口。
- **填法**：机器(草稿)——回填线索或标缺口 + 保留稳妥表达红线；**人补**——做溯源、下合规判断。

### 7. 风险与规避
- **含义**：这个品的命门（封号/掉签/侵权/货源不稳/口径混淆/推算不透明）+ 怎么规避。
- **来源**：通用风险模板 + 机器从数据可推的风险（店龄短/累计成交少→货源不稳；最高想要偏低→泛词选词风险；店铺已售数字→口径混淆提醒）。
- **合格线**：风险要直说、指命门，紧跟规避法（信任装置，见 `docs/信任配方-保留清单.md`）。
- **填法**：机器——通用项 + 数据可推项自动列；**人补**——平台条款/侵权等需专业判断的具体结论。

### 8. 亲测 / 案例素材
- **含义**：讲述者自己的实操、踩坑、粉丝案例——最强信任装置。
- **来源**：**只来自用户**（52 期字幕库 + 口述）。
- **合格线**：**AI 不编造**。没有就明确标缺口。
- **填法**：机器固定标缺口"待从 52 期字幕库检索或用户口述"；**人补**。

### 待补清单
- **含义**：进入生成前必须闭合的项的自动汇总。
- **填法**：机器——把上面所有 `❌缺口`/未锁定项汇总去重；末尾注明终审抽检依据是 `docs/信任配方-保留清单.md`。

## 三、机器填 vs 人补 一览

| 区块 | 机器自动填 | 必须人补 / 人核 |
| --- | --- | --- |
| 卡头 | ✅ 全部 | 用户抽检后把状态改"已抽检" |
| 1 受众档位 | 回填 `--audience` 或标缺口 | **锁定**（对齐 audience-lock.md） |
| 2 核心结论 | 只在缺口处给信号提示 | **写结论**（题材判断） |
| 3 事实清单 | 实采事实全自动（"稿里怎么说"留空） | 闭合缺口 + 抽检核数 + **逐条填"稿里怎么说"**（写手只念这一列） |
| 4 同行数据 | ✅ 全自动 | 抽检核数（尤其单品/店铺口径） |
| 5 利润推算 | 单量区间 + 流水量级 | **核实拿货价**；利润数字人核后才出 |
| 6 供应路径 | 回填线索 / 标缺口 + 红线 | **资源溯源 + 合规判断** |
| 7 风险与规避 | 通用 + 数据可推项 | 平台条款/侵权等专业结论 |
| 8 亲测素材 | 固定标缺口 | **提供素材**（字幕库/口述） |
| 待补清单 | ✅ 自动汇总 | 逐条闭合 |

## 四、拒绝组装的情形（机器硬停）

- `capture.status = no_results`：该词无搜索结果（页面为"猜你喜欢"填充），无同行数据 → **拒绝组装并报错**，提示换等价具体产品词重采。
- `products` 为空：同上，拒绝。
- `status` 非 ok/verified 但已有商品：警告并继续，需人工确认采集完整性。

一句话：**机器只做能回到 capture 的活；凡是要判断、要核实、要用户素材的，留缺口给人，绝不替人拍板、绝不编造。** 写手只念"稿里怎么说"，内部词止于卡内。
