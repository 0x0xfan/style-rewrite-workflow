> 一个 worker 负责一个选题，从事实卡到三套稿到落 NAS 全包；写稿的子 agent **只读配料包**。本文是每个 worker 的操作手册，主线程派工时只填「本单参数」。

## 一、三套是什么

同一条事实链（项目事实固定）× 三个不同的开头大类 × 三批不同的故事和闲鱼经验 × 三次不同的真人语料抽样 = 三套。三套之间：故事不重、经验编号不重、开头大类不重；生意机制和三点顺序可以一样。已经有一套定稿/交付稿的选题（18 苹果多开、20 驾考、24 电影票、35 公众号排版、38 海底捞、41 京东家政）只补两套，大类要避开已用的那一类。

## 三、步骤（worker 按顺序做）

1. **读本单参数**（主线程给：期号、选题名、filmId、`$D` 目录、srt 路径、已有套数与已用大类）。
2. **事实卡**：`$D/事实卡-终版.md` 已有就用；没有就按规范从 `$D/capture.json` + `$D/delivery/<filmId>/assets.md` + `$D/原版内容包-E<期号>.md` 建（srt 只做真伪核对）。授权口径单独一节；「稿里怎么说」一列过 `check-words` 零命中。
3. **事实链**：`$D/事实链-<选题>.md` 已有就用；没有就按样板建（八环、三个数表、不许入稿表、故事单列）。
4. **开头角度清单**：写 `$D/开头角度清单-<选题>-<日期>.md`，三个角度（三个不同大类，避开已用），每个七句示意（⓪ 合同句）、故事编号、五条经验编号、不许。三套的故事不重、经验不重。
5. **三份配料包**：`node engine/brief/build-brief.mjs ...`（参数见配料包规范；`--episode <filmId>-<角度字母>` 三次不同；`--opening-types` 给该角度的大类再加两个相近大类；`--facts` 从事实卡挑 12–20 条，三套可以共用事实）。
6. **三个写手子 agent**（用 Agent 工具，各一个，同模型；**必须 `run_in_background: false` 逐个等结果**——后台派出去你自己就结束了，写手的回报会落到主线程而不是你手里，后面的审稿和落 NAS 就没人做）：每个**只读自己那份配料包**，写 `$D/口播稿-<角度字母><大类>-v1-<日期>.txt`（一句一行、句号结尾、单句 ≤50 字），跑 `check-words` + `check-all`（`--against` 七篇已定稿 + 本选题另外两套）。写手 prompt 照本文第五节的样板写。
7. **审稿子 agent**（一个，同样 `run_in_background: false`，读三份稿 + `docs/写稿规则.md` + 说明书 §13 + 校准词表 md）：按主线程验收口径逐句过——承诺句（"学完当天就能接单"）、金句化、拔高（"一条一条看下来"）、交底说两遍、比喻、代称、省主语、"很多人觉得…其实"同一开头三套撞、跨套重复的句子——直接改，改完重跑两个检查，退回级必须零。
8. **落 NAS**：目录 `//Zqkj_nas/一楼4t/素材生成库/ai文案/待审文案/<期号>-<选题>/`，文件 `<期号>-<选题>-<角度字母>-<大类>.txt`（三份，UTF-8，内容 = 稿子原文）+ `说明.md`（每套：大类、故事编号、经验编号、汉字数句数、检查结果；写手和审稿改了什么一两句；事实卡待补项）。已有定稿的选题把已有那套也复制过去，文件名加 `-已交付`。
9. **登记片段**：写 `C:/Users/admin/AppData/Local/Temp/claude/D-----------/a9461239-27e4-4389-9acf-78871838e5b1/scratchpad/registry-frags/<期号>.json`（数组，每套一条：id `<期号>-<角度字母>-v1`、选题、filmId、稿件路径、配料包、事实链、事实卡、素材目录、开头角度、日期、状态 已交付待回稿）。**不要自己跑 registry.mjs**（多 worker 并行会撞文件）。
