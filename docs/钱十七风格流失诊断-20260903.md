## 3. 归因：逐条对照本轮新规则

判定三档：**误杀**（这条规则直接压掉了钱十七的风格标志）／**无关**（跟这次风格流失没有因果）／**该留**（规则本身对，问题不在它）。

### 3.1 用户点名要验的三个问题，直接回答

> **问：钱十七本人是否大量使用"第一第二…"预告式报幕、"这一步最关键"式自标重要性、"你现在就去"式催促？如果是，那 announceCount/selfLabelCount 门禁和装置轮换就在直接压钱十七味。**

**三条全部证实，且结论就是你猜的那个。**

1. **预告式报幕：是，而且是他的开场标准件。** 语料 10 处，例：「我会用三个视频给大家讲清楚怎么起步、怎么提升选品、怎么处理售后」「这里给大家总结了四大核心维度，分别是：一、芝麻信用；二、好评数量；三、订单数量；四、活跃频率」「接下来，我会围绕这四个点讲通讲透」「准备工作一共有三点，账号注册、养号细节、账号包装」。→ **`announceCount ≤1`（block）正在压他的开场。**

2. **自标重要性：是，密度是门禁测出来的近 3 倍。** 语料 23 处，例：「起步**最重要的**地方就是账号」「**最关键的是**这种账号是可以无限复制的」「这里有个**重点**要注意」「最后一点**非常重要**，是 90% 新手都会踩坑的选品，特别是女生，**一定要认真看**」「账号包装环节大家**一定要注意听**」。→ **`selfLabelCount ≤2/≤3`（block）+ 提示词那句"内容重不重要听众自己会判断"正在压他的推进方式。**

3. **催促：是，密度最高的一项，且贯穿全篇。** 语料 11.0% 的句子带动作指令，例：「视频比较干货，**建议先点赞后观看**，以免后面找不到了」「**建议暂停截图保存**，新手**一定不要**踩坑」「这里特别强调一点，里面的个人资料选项**千万别动**，后面会有大用，动了就废了」「**一定要看完，不然损失就大了**」「**动动发财的小手**，给 17 点个赞和关注」。→ **`SIGNATURE_BLOCKLIST` 的 8 条里 5 条是这层的原句，拦了没给替代品；装置轮换菜单在三个位置各留了一个"这次可以不做"的出口。两条合起来把这层削到 12%。**

### 3.2 圣矾模式混入钱十七风格：确认成立，两条路径

**路径一（门禁级，最硬）**：`ai-flavor-rules.json` 的 `fillerWords` 后 9 个词 + `fillerPer1000.min=1.3` warn 门 + `prompt.mjs` 正向配额 1"至少 3 处"。这三样把**圣矾的口头禅表**当成"这个 IP 张嘴就来的话"写进了钱十七风格档。实测：这 9 个词在钱十七语料里 8 个是 0 次。

**路径二（装置级）**：`device-rules.json` 的 `audience-split.rotations[0]` 与 `navigationAlternatives[0]`，把"真人在这个位置放的是弹幕互动小钩子"写成硬指引，并给出圣矾的三条原句形制。五篇新稿全部照做。

**另有一条结构性混入（本轮之前就存在，不算本轮新问题，但要记下）**：`docs/信任配方-保留清单.md` 整份文档是从 `docs/用户文案模式研究.md`（圣矾 12 期）改写来的，第一部分十条硬规则是**圣矾的信任装置**。它跟钱十七的风格不天然冲突（mac 参照稿就是在这十条下写出来的、用户也认可），但它把讲述者的默认姿态定成了"**摆证据的调查者**"。当第 3 节那些新规则又把钱十七的"**教练姿态**"（教你/带你/一定要/最关键的是/给大家总结了）压掉之后，稿子就只剩调查者姿态了——**这就是用户说的"没有钱十七的感觉"的本质**。

### 4.c 提示词里钱十七风格段该怎么加强（改写草案）

现状：`cli/lib/prompt.mjs` 里**根本没有"钱十七风格段"**——钱十七的风格全靠 `ips/钱十七/dna/钱十七-DNA-重构版.md`（542 行）整篇注入，而它后面紧跟着 4 大段"少做什么"（学结构不学词 / 去 AI 味配额 / 去 AI 味细则 / 信任配方十条 + 八条新规则）。**位置靠前、篇幅巨大、语气是描述性的 DNA，打不过位置靠后、语气是命令式的负面清单。**

建议：新增一个 `buildQian17SignatureSection()`，**注入位置放在所有负面清单之后**（即 `buildDeviceRotationSection()` 之后、事实卡之前），标题写成硬规则同级。草案如下——

```
# 钱十七风格标志（硬规则 · 这一节的优先级高于上面所有"少做什么"的清单）

上面那些清单管的是"别写得像 AI"。**这一节管的是"写得像钱十七"。两者冲突时，以这一节为准。**
判据只有一句：**钱十七的老观众听完，听不出换了人。**

## 一、他是教练，不是记者（这一条定全篇的姿态）

钱十七全程站在"我知道内情、我教你怎么做"的位置上，不是"我去查了查、这是我看到的"。
- 每一段的落点是**你该怎么做**，不是**我看到了什么**。
- 全篇至少 **2 处**明确的教学承诺句：「这一块我给你讲透」「我教你一个最省事的办法」「这份表格我给你整理好了」「照着这三步做就行」。
- 反面（本轮五篇稿的通病，一律改掉）：整篇都是「我数了三十条」「我翻的时候就这两条」「我这回没问到人」——那是记者的稿子。

## 二、边讲边催（他最强的标志，全篇密度不得低于 6% 的句子）

钱十七是**一边讲一边催**的：催你点赞、催你收藏、催你截图、催你别错过、催你现在就动手。真人语料里**每九句就有一句**在催。
三个固定位置，**每期至少占到两个**：
1. **开场承诺之后**：把"值得听"和"先做个动作"扣在一起。
2. **干货密集处**（清单、公式、几个数一起出现时）：绑住"这块值得留存"。
3. **结尾收口前**：关注/互动/资源。

**下面这 8 句是他的原句，是账号资产，一个字都不许照搬**：先点赞后观看、以免后面找不到了、暂停截图保存、动动发财的小手、点赞是我更新的动力、一键三连、谈钱不伤感情、打在公屏上。

**但"不许照搬原句"不等于"这层不写"。自己新造，形制照下面这几种（每期换说法，别跨期复用同一句）**：
- 开场位：「这期数字有点密，先点个关注，回头你还得翻回来对着看。」／「这一段我一次说完，你先把赞点上，别听一半找不着了。」
- 干货位：「这三个数我念一遍就过，你手快的先截一张。」／「这几行是照着抄就能用的，停一下再走。」／「这份清单我不重复第二遍，要记就记这一屏。」
- 结尾位：「觉得这一期有用，点个关注，下期接着拆这一关。」／「你在哪个城市，评论区打一下，我下期拿你的数当开场。」

## 三、用确定句推进（含确定词的句子不低于全篇 8%，且确定句必须多于迟疑句 1.5 倍以上）

他的语气是**说定了**：「就是」「一定要」「肯定」「绝对」「必须」「妥妥的」「很简单」「照着做就行」。
- 保守报数照旧（信任配方规则 3/4/7 不变，缺口该认还得认），但**保守是给数字的，不是给语气的**。
- **数字可以给区间，判断不许给区间。**「三成到五成，我说不准落哪」——数字部分对，"我说不准"这句尾巴删掉。
- 迟疑词（可能／大概／说不准／我没查到／我不给你／另说／多半）**全篇不超过确定词的三分之二**。一处集中说完缺口，其余位置别每段挂一条。
- 反面（本轮 jingdong 篇，确定句只有迟疑句的 0.29 倍，等于把这个人的语气反过来了）：「我没拿到准数，所以城市数我这回不给你」「利润我就不往下算了」「我也不帮人找群」「这个我不讲，也不建议你碰」——四句连着都在往回缩。

## 四、编号推进 + 预告报幕 + 自标重要性（这三样是他的招牌，不是 AI 味）

**上面"报幕句 ≤1"和"自贴重要性标签"两条负面配额，对钱十七这个 IP 放宽，按下面执行：**

1. **预告式报幕是他的开场标准件，每期 1 到 4 处，写。** 形制：「这期我给你讲透三件事：一是……二是……三是……」「这里我给你总结了四条，分别是……」「接下来我围绕这四点讲通讲透」。
   - 被禁的是**空报幕**（「这里得讲清楚一件事」「我插一句」「还有一条我要单独说」）——报了幕却没交付新结构。
   - 允许的是**带清单的报幕**——报幕的同时把清单交出来（"分别是：一、二、三、四"）。**这两种差别就是钱十七和 AI 的差别。**
2. **自标重要性每期 2 到 6 处，写。** 形制：「最重要的地方就是货源」「最关键的是这个号可以无限复制」「这里有个重点要注意」「这一条一定要认真看，九成新手栽在这」。
   - 被禁的是**空标签**（「这段最值钱」「重点听」）——标了重要却没跟着给内容。
   - 允许的是**标签 + 立刻交付**——「最关键的是 X，因为 Y，所以你得 Z」。
3. **方向词密度不低于全篇句子的 15%**：先看、接下来、第一、第二、最后、这里注意、说回、回过头。他每四句就有一句带方向词，观众是被牵着走的。

## 五、他的口头禅（这些才是"张嘴就来"的话，全篇至少 3 处）

**给大家 / 一定要 / 我们（教练式的"我们"，不是公司的"我们"） / 大家 / 比如 / 建议你 / 很简单 / 非常简单 / 其实 / 讲透 / 接下来 / 这里**

**下面这些不是钱十七的话，一个都不许写**（它们是另一个人的口头禅，写进去等于换了个人在说）：
说白了、最起码、等等等等、大错特错、卖就完了、我跟你讲、轻轻松松、没有之一、思路打开。

## 六、句长（他的句子比你以为的长得多）
```

### 4.d 五篇稿的修复策略

**结论：不整篇重写，做"风格回填"局部改写。**

理由三条：
1. 事实层、口径层、结构层这轮做得**是对的**——单品/店铺口径分得干净、推算链条透明、命门段厚实、无期号、无书面词、无三类人分流。整篇重写会把这些一起赔掉，而且要重新过六道门。
2. 掉的六项（动作指令、确定句、方向词、句长、利益句、教学句）**全部是可以在既有骨架上加回去的**，不需要动骨架。
3. 整篇重写有把 AI 味带回来的风险；回填是**定点**操作，可控。

**回填时怎么不把 AI 味带回来——冲突清单与取舍口径：**

| 冲突点 | AI 味规则说 | 钱十七标志说 | 取舍 |
|---|---|---|---|
| 报幕 | 报幕句 ≤1 | 预告式报幕每期 1–4 处 | **按"空报幕 vs 带清单报幕"切**：报幕的同一句里必须把清单交出来（"分别是：一、二、三"），只宣布不交付的一律删。**这条切法两边都满足**。 |
| 自标重要性 | ≤2 处，"内容重不重要听众自己会判断" | 每期 2–6 处 | **按"空标签 vs 标签+立刻交付"切**：「最关键的是 X，因为 Y，所以你得 Z」保留；「这段最值钱」「重点听」删。 |
| 免责 | 缺口要交代，改用词级压低 | 确定句必须多于迟疑句 1.5 倍 | **段级免责集中在一处说完（≤2 句），词级迟疑不许超过确定词的三分之二**。缺口不能不说，但不能每段挂一条尾巴。**这是最容易反弹的一条，回填时逐句数。** |
| 催促 | 8 句原句硬拦截 | 动作指令 ≥6% 句子 | **原句不动，形制照写、说法自造**（4.c 第二节给了 7 个新说法模板）。**这条不是真冲突，是缺替代品。** |
| 句长 | 单句 ≤50 字、短句 ≥25% | 长句 ≥30% | **两个下限并存，不冲突**：短句 ≥25% + 长句 ≥30% + 中间段 ≤45%。现在的问题是只有前一个有门。 |
| 口头禅 | 至少 3 处、`fillerPer1000 ≥1.3` | 用钱十七自己的词 | **换词表，不换机制**。数量要求不变，词换掉。 |
| 收口序列轮换 | 五拍序列不许跨期复用 | 结尾必须有 CTA | **轮换的是说法，不是做不做**。把"干脆不给动作"这个出口从菜单里删掉。 |

## 6. 剩余风险与未做的事

1. **语料只有 9 期、20,199 字，且是转写稿。**句长类指标含标点伪影（已在 §0 说明），4.b 里 `longSentenceRatio.min=0.30` 这个阈值是**取语料 60.7% 与参照稿 50.7% 的一半再打折**得来的，不是从干净基线算的。落地前建议先在 mac 参照稿 + `qian17-styled-final-v2` 上做一次误伤验证。
2. **本诊断只覆盖"钱十七 vs 圣矾"这一对。**半佛档（`profiles.default` 之外唯一另一个 IP）没查——`fillerWords` 那张共用表对半佛是不是也配错了，本轮没验。
3. **`selfLabelCount` 放到 6 有风险。**它同时是一个真实 AI tell（"这段最值钱"）。4.d 给的切法（空标签 vs 标签+立刻交付）是**语义判断，正则抓不住**。这一条最终要靠 LLM 二审（`cli/lib/review.mjs`）判，而二审到现在**一次真模型都没跑过**（`AI味治理-外部对照.md` §7.7 明写"单测全部用 mock"）。放宽阈值之前，建议先让二审真跑一次。
4. **风格标志下限门会跟"跨稿骨架撞句"打架。**下限门逼每篇都写动作指令、都写报幕清单，五篇必然长得像；撞句门（Jaccard ≥0.30）会报出来。落地时需要给风格标志类句子一个**专门的轮换池**（不是白名单——白名单会让它们真的变成模板），池子容量至少 5 篇 × 3 个位置 = 15 种不同说法。4.c 的草案里只给了 7 种，不够。
5. **五篇回填后可能出现"催得太满"。**语料 11% 是钱十七在**教程型内容**里的密度（养号、选品这类"我教你做"的题材）；本批五篇是**拆解型**（我拆给你看这生意成不成立），题材本身就不如教程适合催。所以 4.b 的下限取的是语料的 55%（6%）而不是语料值本身。这个折扣系数是拍的，需要用户听一遍成稿才能定准。
6. **没有验证 `qian17-styled-final-v2`（人工校准通过稿）的指标为什么也偏低。**它的动作指令与确定句密度（确定 0.24/百字、CTA 0.29/百字）介于语料和新稿之间，但用户当时是认可的。可能说明**下限可以比 4.b 定的更松**，也可能说明那份稿子本来也偏了。本轮没深挖。

### 8.1 先修规则：A7 装置组的构造性误伤

**病灶。** `engine/variation/device-rules.json` 的 `a7-action-instruction` 是 `mandatory: true` + `mustChoose: true` + `scope: phrase`——**每篇必写**。但它只有 4 条粗粒度 pattern（`a7-pre-watch` / `a7-save` / `a7-comment` / `a7-dont-miss`），要覆盖 16 条轮换池（开场 5 / 干货 5 / 结尾 6）。实测这 16 条里有 **14 条**会命中那 4 条粗 pattern 中的某一条。而 `check-devices.mjs` 的 `checkDeviceReuse` 对 `scope=phrase` 是**按 patternId 判跨稿复用**——于是任意两篇只要都按规矩从池子里挑说法，就必然撞同一个 patternId 判 FAIL，五篇里没有任何一篇可能 PASS。

**一句话：pattern 拦的是解药，不是病。** §7.5 记的那次验证（「16 条两两撞骨架 0 对、模拟五篇各选一种跨稿 0 对」）只跑了 `check-repetition` 与 `check:skeleton` 两把尺子，**没跑 `check-devices` 自己那把**，所以这条漏到了回填之后才被五个 worker 同时撞上。

**修法：选 (a)——pattern 拆到与 16 条轮换池一一对应。**

- 每条池子一个 patternId（`a7-open-1..5` / `a7-mid-1..5` / `a7-end-1..6`，与 `rotations` 的顺序严格对齐），正则只匹配该条独有的搭配骨架。
- 跨稿判定的含义随之变成「**同一条池内说法被两篇用**才 FAIL」，正是需求描述的口径。
- 没选 (b)（按表面串归一化后 Jaccard≥0.5）的理由：A7 的 16 条池子彼此共享大量表面词（点个关注 / 点个赞 / 评论区 / 这一期），归一化后两两 Jaccard 天然偏高，阈值定在哪儿都是在「误伤」和「漏判」之间挑，而且判据不可读——FAIL 报告没法告诉作者「你撞的是池内第几条」。(a) 是确定性的、可解释的，且报告里能直接打印撞的那条池子原文（新增 `patterns[].label`）。

**顺带核对其余 mandatory / mustChoose 组。** 逐组把「轮换池」拿去命中「自家 pattern」，另查出**三处**同病，一并修：

| 组 | 结构 | 病灶 | 修法 |
|---|---|---|---|
| `a7-action-instruction` | mandatory + mustChoose，4 pattern / 16 池 | 16 条池子里 **14 条**自撞 | 拆成 16 条一一对应的 pattern（修法 a） |
| `free-homework` | mustChoose，5 pattern / 5 池 | 池 #1 结尾「数完在评论区报个数」命中自家 `hw-comment-report` | 该 pattern 删掉裸的「评论区报」这一支 |
| `closing-action-sequence` | mustChoose，5 pattern / 6 池 | 池 #6「你去数第一页有几条过百」命中自家 `close-count-first-page` | 该 pattern 第二支删掉「有几条」 |
| `nav-save-progress` | **`scope: device` + `mustChoose`** | 走的不是 patternId 而是 deviceId：device 级判定说「这个装置在历史池里出现过就 FAIL」，mustChoose 说「每期必写」——合起来同样是恒 FAIL | `scope` 由 `device` 改为 `phrase`；保住「每期必须给个干货位动作」这个决定，只把判定口径改成与其余必写组一致的「轮换的是说法」 |

`nav-save-progress` 这条一直**潜伏没爆**，因为五篇的干货位实际都从 A7 池里挑说法，它那三条陈旧表面形（先收藏一下 / 进度条拖 / 拿笔记一下）一次都没命中；一旦哪篇真写了「先收藏一下」，从第二篇起就永远 FAIL。

其余 mandatory 组（`estimate-disclaimer` / `no-unverified-profit` / `admit-unknown` / `risk-blunt` / `data-first` / `compliance-teaching` / `restrained-cta`）逐条跑过，**无自撞**——它们的 pattern 指的是「陈旧表面形」，rotations 是「换个写法的策略描述」，两者本就不重叠，属健康结构。

**把这条病灶写成不变量。** `check-devices.mjs` 新增 `auditDeviceRules()`，每次 `npm test` 都跑：

- 规则 A（所有组）：一个组的轮换池不许命中该组自己的 pattern——命中即「一边发药一边判它是病」。
- 规则 B（`patternsCoverRotations: true` 的组，目前只有 A7）：pattern 与 rotations 双射——每条池子恰好命中一条自家 pattern，且不同池子命中不同 pattern。这是「五篇各取不同池条目 → PASS / 两篇取同一条 → FAIL」的充要条件。
- 规则 C：`scope: device` 与 `mustChoose: true` 不许并存——「每期必写」＋「装置级复用判定」＝恒 FAIL。

新增 `engine/tests/device-rotation.test.mjs`（8 个用例）：规则自审干净、A7 id 命名与槽位对齐且每条带 label、16 条池子各自只被认成自己那一条、**五篇各取不同池条目判 PASS**（这正是修复前必然 FAIL 的那一档）、**两篇取同一条判 FAIL 且报出撞的是哪一条**、三个位置全撞报三条、没有任何组同时是 device 级 + mustChoose、两个 mustChoose 组的自撞已修。
