# 风格仿写升级蓝图

## 目标

把现有“风格卡 + DNA 评分”升级成一条可控、可审计的仿写工作流：既学到表达方式，也能证明新稿只使用用户自己的事实、证据与 CTA。

## 当前能力与缺口

| 已有 | 缺口 |
| --- | --- |
| Markdown 风格卡、DNA 提取与五轴匹配 | 样本是否混入模板、近重复或单篇偏差尚无健康报告 |
| 来源事实与风格的基本边界 | 尚无用户确认过的样本清洗步骤与 DNA 版本历史 |
| Feishu 文档读取、素材/风险摘要、改写入口 | 改写只有单一默认强度，缺少可解释的控制项 |
| 元引用与风险提示 | 缺少“新稿是否保住用户事实/证据”的独立报告 |
| 工作台风格库 | 缺少候选稿横向比较和固定回归案例 |

## 目标流程

```text
样本导入
  -> 样本健康报告（篇数、字数、近重复、模板）
  -> 用户确认保留/剥离项
  -> 生成并确认 Style DNA 版本
  -> 输入内容 Brief（事实、证据、受众、渠道、CTA、禁说项）
  -> 选择场景、仿写强度与表达维度
  -> 生成候选稿
  -> 五类检查
      1. 用户事实/证据覆盖
      2. 禁止来源事实与元引用
      3. 风险表达
      4. Style DNA 匹配
      5. 未执行或降权的规则
  -> 并排比较 + 用户批准
  -> 批准稿成为回归案例
```

## 分阶段实施

### F006：样本健康与 DNA 版本

- 为每次 DNA 提取生成健康报告：样本单元、字数分布、可疑近重复、跨样本重复模板、稳定性提示。
- 把模板候选作为“待确认”，不自动删除个人口头禅。
- 将已保存 DNA 追加版本号、生成时间、样本摘要、用户确认状态与变更原因。
- 验收：用户能看懂为什么该 DNA 仍是“初步”或可升级为“稳定”。

### F007：可控仿写与内容保真报告

- 新增场景、仿写强度、口播感/能量/直接性/证据/转化五轴偏好。
- 生成后显示“使用了哪些表达规则、哪些没有使用、为什么降权”。
- 将 `source_brief` 中的事实和证据作为覆盖检查输入；覆盖结果只标注，不能编造缺失事实。
- 验收：用户能分辨“风格像”与“信息完整”是否分别通过。

### F008：候选比较与回归集

- 支持同一 Brief 的保守版、标准版、强风格版并排对比。
- 以用户实际批准/驳回的案例建立本地回归集；改提示词、规则或评分公式前后都重跑。
- 只有模型代理恢复后才跑真实生成验证；离线阶段只实现数据结构和确定性检查。
- 验收：改动能被批准案例证实变好，且不会突破事实与风险边界。

## 不做

- 不接入外部训练模型、作者识别、自动发布或把他人事实塞进新稿。
- 不把 LLM 评委或 Style DNA 分数当作发布批准。
- 不引入 AGPL 项目的代码。

## 当前下一步

先实施 F006：样本健康报告与 DNA 版本资产。它解决“提取出来的到底是不是稳定风格”这一根问题，并为后续控制与评估提供可靠输入。
