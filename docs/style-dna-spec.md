# 短视频口播 Style DNA 规范

## 目的

将“像不像”拆成可回读、可验证、不会携带来源事实的风格资产。每张风格卡可选配一个同名 `.md.dna.json` 文件；Markdown 给人和模型阅读，JSON 用于评分和工作台展示。

## 适用范围与置信度

- 单条或单篇样本：只能形成初步格式画像，不能宣称稳定作者风格。
- 3–9 条完整口播：可形成可用的短视频风格卡，应持续补样本交叉验证。
- 10–19 条：可用于稳定改写，但要按内容类型分别观察。
- 20 条以上且覆盖不同主题：才可称为高置信度的账号/作者 Style DNA。

置信度只说明样本覆盖度，不代表文案质量、事实真实性或平台合规性。

## JSON 契约

```text
style_metadata     样本类型、篇数、字数、置信度与来源边界
metrics            句长、段落、标点、编号、疑问、证据、CTA、风险等可测信号
axes               口播感、能量、直接性、证据密度、转化力度（0–100）
signature_signals  高频推进词、连接词、互动词的计数，不保存来源事实
structure          钩子、编号方法、中段互动和结尾 CTA 的结构信号
replication        可执行的写作动作、禁止项和事实边界
```

## 评分规则

改写稿重新提取 DNA，并与目标 DNA 的五个轴比较。分数只衡量风格信号接近度，不衡量：

- 事实正确性或素材真实性；
- 平台合规、收益承诺、侵权风险；
- 文案商业效果；
- 对具体作者身份的冒充程度。

因此，风格分与既有 `risk_notes`、素材位和元引用拦截并列，不能替代它们。

## 隐私与来源边界

- JSON 不写入原始全文、收益数字、账号名、素材链接或 CTA 关键词。
- 只保存可复用的统计信号和写作规则。
- 参考样本的具体事实仍只属于来源样本；新稿只能使用用户自己的事实和证据。

## 参考与取舍

- `writing-dna-skill`：采用多层 DNA、样本量分级和总览文档思路。
- `writing-style-extractor`：采用“每项发现有置信度/可执行规则”的要求，但不保存来源原句。
- `writing-dna-studio`：采用离线可解释的轴向指纹与改写后再评分。
- InkOS：借鉴“生成后审计”的思想；不引入其 AGPL 代码或小说系统。
- StyleLLM：保留“风格与内容分离”原则；不引入微调模型。
