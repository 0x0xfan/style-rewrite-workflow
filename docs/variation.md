# 跨稿重复

批量出稿时，多篇之间原样复用句子和词组。这是 2026-08-22 之前一直没解决的问题。

## 问题有多大

只有 4 稿、同一个选题时的实测（修复前）：

| 对照 | 8 字连续重合 | 占比 |
| --- | --- | --- |
| 半佛长视频版 vs 钱十七长视频版 | 253 处 | **17.8%** |
| 钱十七短视频版 vs 钱十七长视频版 | 30 处 | 7.5% |

两个号称完全不同的风格，在同一选题上有 17.8% 的八字片段一模一样。原样复用的整句包括：

- `我是圣矾，下期讲怎么把货源稳定下来` —— 3/4 篇
- `今天就干一件事：打开闲鱼` —— 3/4 篇
- `小众餐饮没人搜，挂上去` / `标题把品牌、面额` / `宁可一张少赚两块` —— 直接从钱十七稿复制进半佛稿

**根因是生成时把已写好的稿子当模板抄，而不是重新应用 DNA。** 和"复印件的复印件"是同一个病。

## 四个成因

1. **事实层没有表达变体。** 同一组事实每次都用同一串词说出来，没有任何机制要求换说法。
2. **DNA 每个位置只给一种做法。** A6 规定结尾是"资源/下一步—动作—身份"，于是每篇都这么收。
3. **没有批次概念。** 每篇独立生成，不知道前几篇用过什么，没有东西在累积。
4. **同选题下骨架原样复用。** 四关结构不变，连讲的顺序都不变。

## 不是所有重复都该杀

**事实性重复是对的。** "企业福利、银行联名、会员专属"是一组事实，硬换措辞会扭曲事实。这类串登记在 `repetition-rules.json` 的 `protectedPhrases` 里，不计入重复。

**要杀的是表达性重复**：开头、转场、金句、CTA、下期预告。

## 检测

```bash
npm run check:repetition -- ips/钱十七/outputs/*.md ips/半佛/outputs/*.md
```

阈值（`engine/variation/repetition-rules.json`）：

| 项 | 阈值 | 理由 |
| --- | --- | --- |
| 跨 IP 两稿 8 字重合率 | ≤ 8% | 不同风格就该产出不同文本，超了说明风格没起作用 |
| 同 IP **不同选题** 8 字重合率 | ≤ 8% | 不同选题本该各讲各的，同 IP 也不例外——按跨选题口径 |
| 同 IP **同选题** 长/短/图文版重合率 | ≤ 15% | 同一内容的多个时长，允许更高 |
| 12 字以上片段 | 不得出现在 3 篇及以上 | 属于原样复用，不论整体比例 |

**「同选题」怎么判**：文件名去掉 `-长视频版`/`-短视频版`/`-图文版` 后缀后的主干相同即同选题（`闲鱼餐饮券-长视频版` 与 `闲鱼餐饮券-短视频版` 同选题，用 15%；`01-二手书回收转卖` 与 `02-账号养号基础` 不同选题，用 8%）。工具旧口径只按路径第一段判「同 IP」、一律套 15%，会漏掉「同 IP 不同选题」这一格——批量出稿恰恰几乎都落在这一格。CLI 两两输出里给同选题对打 `[同选题]` 标记。

`npm test` 里有多条测试锁住这些，其中一条直接断言已交付的四稿必须通过，另有一条对 10 篇压测批 + 餐饮券短稿的回归锁（压测目录存在时才跑）。

## 批次账本

写下一篇之前，先看前面几篇用过什么：

```bash
npm run ledger -- ips/钱十七/outputs/*.md ips/半佛/outputs/*.md
```

输出各篇的开头句、结尾句，以及已经出现在多篇里的句子。**开头、结尾、跨稿重句是重复的三个高发位置**，账本只盯这三处，不刷屏。

写第 N 篇的流程：跑账本 → 避开已用表达 → 写 → 跑检测 → 不过就改。

## 变体从哪来

**档案里本来就有多个选项，是生成时塌缩成了一个。**

- 钱十七 A1 明写了三种开头（具体结果反差 / 观众卡点 / 低门槛揭晓），但四稿里只用了两种。
- 半佛回源审计查出七种开篇（第一人称踩坑 3、后台提问 2、凌晨困惑 1、有人跟我说 1、你打开了吗 1、网上流行 1、场景白描 1），档案却只写了"困惑式权重 40%"。

所以做法不是发明新变体，是**强制轮换档案里已有的**。批量出稿时，按这几条轴分配：

| 轴 | 钱十七可选 | 半佛可选 |
| --- | --- | --- |
| 开头 | 结果反差 / 观众卡点 / 低门槛揭晓 | 第一人称踩坑 / 后台提问 / 外部新闻 / 现象起笔 |
| 骨架 | F1 全路径 / F2 筛选判断 / F3 查询目录 | 恰饭六段 / 评论三段 |
| 推进 | 编号环节 / 排雷后推荐 / 公式后验证 | 数字分节 / 反问连打 |
| 收尾 | 资源 CTA / 互动提问 / 下期预告 / 一句总结 | 类比升华 / 反问收 / 定性收 |

10 篇一批时，同一条轴上的同一个选项不得连续出现，且总占比不超过 40%。

## 10 篇压测发现（2026-08-22）

用同一 IP（钱十七）下 10 个不同选题各一篇 + 现有餐饮券短稿共 11 篇，压测本工具（完整报告见 `engine/fixtures/batch-test-20260822/report.md`）。要点：

- **正文真实重合最高只有 1.6%**（05 本地服务 vs 08 数码代卖），离 8% 上限有 5 倍以上余量。10 个选题正文事实零重合。
- **轴轮换有效**：开头 / 骨架 / 推进 / 收尾四条主轴每选项 ≤ 40% 且无相邻连续，覆盖了开头、选题、骨架三层的多样性，正文层面的跨稿重复被压住。
- **连接壳在每条轴选项第 3 次落地时开始枯竭**：残余重复全是子句级「连接壳」——转场（`避开这些，再说`）、下期口（`我是圣矾，下一回`）、P8 消费阶梯句框（`真做起来，可能就是从 X 变成 Y`）。轴轮换覆盖了开头 / 选题 / 骨架，却**没给转场、下期口、P8 句框这类连接壳提供轮换库**，写到第 7–8 篇（每个选项第 3 次复用）就只能磨旧说法。**这是下一个缺口**：连接壳也需要一个轮换库。
- **保护短语是按单一选题硬编码的**：现有 `protectedPhrases`（企业福利/银行联名、肯德基/麦当劳、使用期限/适用门店）全是餐饮券选题的事实串，换选题就完全空转——这批 10 篇一条都没用上。应改为**按批次/选题配置**保护短语，而不是写死一套。

## 已知局限

**检测的是字面重复，不是语义重复。** 半佛短的开头"上周我想买张肯德基券，闲鱼上五十的卖三十几"和钱十七短的"五十块的肯德基券，闲鱼上卖三十几"字面上过了阈值，但读起来是同一个意思。

这一层目前只能靠人看，或者靠上面的变体轴在结构上先岔开。
