# 知识包规范（knowledge-pack.json）

AI 直采内容流水线「三输入」之一。生成一篇稿件需要三样东西，缺一不可：

> 事实 contract（这篇要说什么、数据从哪来） + **知识包**（用什么背景知识把话说透） + 风格档案（用谁的腔调写）

**知识包只负责"丰富解释与方法"，不负责提供事实。** 它是把闲鱼知识库里的现有经验，按当前选题检索出来的一份可回读清单。

## 干什么用

给定一个选题（主题 + 关键词），到闲鱼知识库里检索相关的经验文章/案例/平台规则，产出一份 `knowledge-pack.json` 交给生成链路。它让 AI 写稿时"有料可依"，而不是凭空发挥。

## 命令

构建（在仓库根目录，用本机 .venv 的 python）：

```
.venv/Scripts/python.exe -X utf8 engine/knowledge/build_knowledge_pack.py \
    --topic "ai拼车" --keywords "拼车,合租,账号共享" \
    --out research-runs/2026-08-26_ai拼车_采集/knowledge-pack.json
```

常用参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--topic` | 必填 | 选题主题 |
| `--keywords` | 空 | 逗号分隔关键词 |
| `--out` | 必填 | 输出路径（相对仓库根或绝对） |
| `--top` | 12 | 最多保留条目数 |
| `--per-query` | 8 | 每个检索词取回条数 |
| `--min-score` | 1 | 聚合分下限，过滤纯噪声 |
| `--strict-coverage` | 关 | 无一命中主题/主关键词本身则**硬停不写包** |

违规词辅助扫描（生成后对成稿做商品侧词扫描，**是辅助报告，不是门禁**）：

```
.venv/Scripts/python.exe -X utf8 engine/knowledge/build_knowledge_pack.py check --file 稿件.md
```

退出码：`0` 已产出知识包 / 已完成扫描；`1` 零结果（或严格覆盖度未过）硬停，不写包；`2` 知识库不可访问。

> 依赖：分词用 jieba（已装入仓库根 .venv）。全程走 UTF-8，规避 Windows 控制台 GBK 乱码。

## 输出字段

顶层：

- `schema_version` / `generated_at` / `producer`：版本、时间、生产者与知识库路径
- `hard_rules`：**硬规则清单**（见下），随包下发供人工与下游把关
- `topic` / `query`：选题、关键词、实际展开的检索词（长词经 jieba 分词补召回）
- `retrieval`：
  - `result_count` / `usable_source_count`：条目数
  - `relation_distribution`：support / supplement / counterevidence 的分布
  - `primary_term_hits`：**真正命中主题/主关键词本身**的条目数（相关性诚实信号）
  - `coverage_warning`：当 `primary_term_hits == 0` 时给出的覆盖度告警
- `sources[]`：每条含
  - `title` / `locator`（知识库内 .md 绝对路径，可回读） / `source`
  - `excerpt`：摘录 / `content_sha256`：按落盘文件算的哈希（校验可回读）
  - `match_score` / `matched_in` / `matched_queries`：命中来源，便于审计
  - `matched_primary_term`：是否命中了用户给的主题/关键词本身（true=真相关；false=仅靠宽泛碎片召回）
  - `relation`：与选题的关系粗分
    - `support` 直接支撑选题（须命中主词且强匹配）
    - `supplement` 背景补充
    - `counterevidence` 反证/风险警示（封号、起诉、被罚…）

## 空结果处理

- **零命中**：不写空包，打印失败状态并以非 0 退出。按 `requirements.md`：知识库零结果时**停止生成，不得空包放行**。
- **有命中但无一命中主词**（`primary_term_hits == 0`）：默认仍产出包，但置顶 `coverage_warning`、全部条目 `matched_primary_term=false`，供人工/下游判断是否够用；如需把"相关性"也做成硬门，加 `--strict-coverage` 即硬停不写包。

## 硬规则（写进每个包的 `hard_rules`）

1. **知识包中的数字、案例、收益结论不得直接写入稿件，必须先进事实卡由人确认。**
2. 反证/冲突（counterevidence）条目只能用于约束风险，不能变成核心方法。
3. 知识用于丰富解释与方法，不得改变事实卡的数据、单位、主体、时间范围、条件与步骤含义。
4. 知识库零结果/不可访问/无法验证实际使用时停止生成，不得空包放行。
