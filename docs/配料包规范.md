# 配料包规范

> 用途：派写手写一篇口播稿之前，先用 `engine/brief/build-brief.mjs` 把这一篇要用的"配料"从各个大文件里按编号抽出来，拼成一份一两万字的**配料包**。写手只读配料包，不再读那二十万字。
> 建立于 2026-09-07。

---

## 一、为什么要有它

写稿公式是固定的：

```
一篇口播稿 = 项目事实（固定）+ 故事 + 一批闲鱼经验
风格固定，开头角度每篇换一个
```

配料只有故事和经验在换，事实和风格是死的。以前派活时把六个大文件（加起来二十多万字）全甩给写手，写手要么读不完，要么读串。现在改成：主线程挑好编号 → 跑一条命令 → 得到一份一万多字的配料包 → 写手只读它。

**规矩：配料包里没有的，就是不许写。**

2026-09-08 起配料包末尾多一张**用户校准词表**（禁 → 换），配一个交稿前检查脚本 `engine/brief/check-words.mjs`。用户对稿子的每一次字句纠正都进这张表，同样的错不再第二次到用户眼前。词表本身见 `docs/用户校准词表.md`。

---

## 二、命令

```
node engine/brief/build-brief.mjs \
  --style docs/人设说明书-钱十七.md \
  --factcard research-runs/2026-08-31_41_京东家政券_重制/事实卡-终版.md \
  --facts A2,A5,A6,A7,A9,A10,B1,B3,B4,B5,B7 \
  --chain research-runs/2026-08-31_41_京东家政券_重制/事实链-京东家政券.md \
  --links 2,3,4,5,6,7 \
  --angles docs/开头角度清单-京东家政-20260907.md --angle C \
  --stories docs/圣矾真实经历清单.md --story-ids 91,65 \
  --experiences docs/闲鱼经验库/总表.json \
  --exp-ids X-风控-014,X-心态-002,X-客服-001,X-风控-020,X-售后-017 \
  --topic "闲鱼卖京东家政券" --topic-type 虚拟 \
  --out research-runs/2026-08-31_41_京东家政券_重制/配料包-C-20260907.md
```

`node engine/brief/build-brief.mjs --help` 打印用法。
Windows PowerShell 里换行续行符用反引号 `` ` ``，或者干脆写成一行。

写手交稿前再跑一条：

```
node engine/brief/check-words.mjs <稿件.txt> --topic-type 虚拟
```

命中即改，报告里贴输出。有命中退出 1，没命中退出 0。

## 三、参数表

| 参数 | 值 | 干什么 |
|---|---|---|
| `--style` | 风格说明书 .md 路径 | 全文原样嵌进第二节；第七节再从中抽"交稿前机器查"那一节 |
| `--factcard` | 事实卡 .md 路径 | 配 `--facts` 用 |
| `--facts` | 逗号分隔的事实编号，如 `A2,A5,B1` | 抽事实卡表里这几行整行 |
| `--chain` | 事实链 .md 路径 | 配 `--links` 用；同时无条件抽第二、四、五节 |
| `--links` | 逗号分隔的环号，如 `2,3,4` | 抽事实链第三节链条环节表里这几环的行 |
| `--angles` | 开头角度清单 .md 路径 | 配 `--angle` 用 |
| `--angle` | 一个字母，如 `C` | 抽 `## 角度 C ·` 那一节 |
| `--stories` | 经历清单 .md 路径 | 配 `--story-ids` 用 |
| `--story-ids` | 逗号分隔的数字编号，如 `91,65` | 抽经历清单表里这几行整行 |
| `--experiences` | 闲鱼经验总表 .json 路径 | 配 `--exp-ids` 用 |
| `--exp-ids` | 逗号分隔的经验编号，如 `X-风控-014` | 从 JSON 里取这几条 |
| `--topic` | 一句话选题名 | 只用来做配料包标题 |
| `--topic-type` | `虚拟` 或 `实物` | 决定第八节用户校准词表里"实物专用"那一类进不进：虚拟选题进（退货、运费、快递这些词不许出现），实物选题剔掉。不给就照列并记进缺项 |
| `--words` | 用户校准词表 .json 路径 | 默认 `docs/用户校准词表.json`，一般不用给 |
| `--out` | 输出 .md 路径 | 不给就打到标准输出 |

**路径**：相对仓库根（`D:\项目仓库\风格仿写`）或绝对路径都行。目录不存在会自动建。

**全是可选的**。缺哪个就跳过那一节，并在配料包第八节"缺项"里写明缺了什么、后果是什么。成对的参数（`--factcard`/`--facts`、`--stories`/`--story-ids`、`--experiences`/`--exp-ids`、`--angles`/`--angle`）只给一半，那一节也跳过并记进缺项。

## 四、配料包各节来自哪儿

| 节 | 内容 | 来源 | 怎么抽 |
|---|---|---|---|
| 抬头 | 标题、写稿公式、落盘要求（五分钟一千三到一千五百汉字、一句一行、单句不超五十字、全汉字数字、零头取整加"多"、交稿前跑 `check-words.mjs`） | 脚本内置 | 写死在脚本里；`--topic-type` 会填进那条命令 |
| 二、风格说明书 | 全文 | `--style` | 原样整篇嵌入，一个字不动 |
| 三、开头 | 一个角度小节 | `--angles` + `--angle` | 从 `## 角度 X ·` 那行起，到下一条独占一行的 `---` 为止 |
| 4.1 生意句三个数 | 一整节 | `--chain` | 事实链 `## 二、` 到下一个 `##` |
| 4.2 链条环节 | 表里指定的几行 + 表头 | `--chain` + `--links` | 事实链第三节内，匹配行首 `\| **N.` 的行 |
| 4.3 项目事实 | 表里指定的几行 + 表头 | `--factcard` + `--facts` | 事实卡里第一格是 `A2` / `B3` 这种编号的整行；A 段 B 段各自带自己的表头 |
| 4.4 不许入稿 | 一整节 | `--chain` | 事实链 `## 四、` 到下一个 `##`，原样 |
| 4.5 一跳规则 | 一整节 | `--chain` | 事实链 `## 五、` 到下一个 `##`，原样 |
| 五、故事 | 表里指定的几行 + 表头 | `--stories` + `--story-ids` | 经历清单里第一格恰好是那个数字的整行。**前面加死规矩**："本人经历，写成'我'，只用原话的意思，不加工、不演绎成'我以为'" |
| 六、闲鱼经验 | 指定的几条，重排成表 | `--experiences` + `--exp-ids` | 按 JSON 的 `id` 取，每条给：编号 / 经验 / 环节·类型 / 支持数 / 标记 / 备注。**前面加死规矩**："同行经验，只能写成'有人这么做 / 行业里一般这么看 / 做闲鱼的都知道'，不写成亲历，不带收入数字；⚠️ 的按备注剥数字；🚫 的不用" |
| 七、交稿前机器查 | 一整节，重复列一次 | `--style` | 风格说明书 `## 十八、` 那一节。单独再列是因为写手总漏 |
| 八、用户校准词表 | 整表，按类型分组（禁 / 换成 / 日期 / 录入 / 用户原话 / 来源稿） | `docs/用户校准词表.json`（`--words` 可换） + `--topic-type` | JSON 里每条渲染成一行；`--topic-type 实物` 时剔掉"实物专用"那一类，`虚拟` 时保留并标"生效"。**这张表和 `check-words.mjs` 读的是同一份 JSON**，写手照表避开，交稿前脚本再查一遍 |
| 九、缺项 | 没给的参数清单 | 脚本自己攒 | 每条说明缺了什么、写手会因此少什么；没给 `--topic-type` 也记一条 |

### 编号在原文件里出现多处

经历清单的编号在"主表"和"③ 跨选题通用经历"两张表里都出现（比如 91、65）。脚本**两处都抽**，各自带自己的表头，并在小节开头注明"编号在原文件里出现多处"。这样写手能同时看到原话版和一句话版，不会漏掉更精确的那一条。

事实卡的 A 段和 B 段是两张表，抽到的行按表分组，各带各的表头和"出自"标注（3A 实采 / 3B 第41期），这样写手一眼能看出哪条要标采集日期、哪条要标"第41期"。

## 五、报错规则

**编号找不到 → 打印哪个没找到 + 文件路径，退出码 1。**绝不静默漏一条配料。四类编号都是这个待遇：

- `--facts` 里的事实编号在事实卡里找不到
- `--links` 里的环号在事实链第三节找不到
- `--story-ids` 里的编号在经历清单里找不到
- `--exp-ids` 里的编号在经验总表 JSON 里找不到

**结构找不到 → 同样退出 1。**包括：

- `--angle` 指定的角度小节不存在（`## 角度 X ·` 这行没有）
- 事实链缺第二 / 第四 / 第五节
- 风格说明书缺 `## 十八、` 那一节
- 用户校准词表缺文件、条目缺字段、类型或录入值不认识、标了"用户点名"却没有用户原话

**文件问题 → 退出 1。**文件不存在、读不出来、JSON 不合法、JSON 顶层不是数组。

**`--topic-type` 不是 `虚拟` / `实物` → 退出 1。**

**认不出的参数 → 退出 1。**打印可用参数表。

**缺参数 → 不报错。**跳过那一节，写进第八节缺项，退出码 0。

## 六、体量参考

2026-09-07 的角度 C 那一份：**11135 汉字 / 17817 字符**。其中风格说明书占 5900 汉字（一半多），剩下是事实、故事、经验和各种红线。这个量写手一口气能读完。2026-09-08 加上用户校准词表（58 条）后同一份重生成为 **13740 汉字 / 24327 字符**，词表占约 2600 汉字。

要是配料包超过两万汉字，多半是 `--facts` 或 `--exp-ids` 给多了——一篇稿正常是十条上下事实、五到六条经验、两三个故事。

## 七、注意

- 脚本**只读不写源文件**，只往 `--out` 写一个 markdown。
- 嵌进去的风格说明书带着它自己的 `#` 一级标题，所以配料包里会有两个一级标题层。这是"原样嵌入"的代价，没改。
- 挑编号是主线程的活，不是脚本的活。脚本不会替你判断哪条事实该配哪一环——它只负责把你点的名一条不落地端出来，或者告诉你哪条点错了。
- 用户校准词表的维护规矩见 `docs/用户校准词表.md`：用户亲口纠正的标"用户点名"，主线程推出来的标"主线程预防性"，后者不许冒充前者。加条目改 JSON，`check-words.mjs` 和 `build-brief.mjs` 都读它，别在别处再抄一份词表。

## 八、交稿前检查脚本 `check-words.mjs`

```
node engine/brief/check-words.mjs <稿件.txt> [--table docs/用户校准词表.json] [--topic-type 虚拟|实物]
```

- 逐行扫描，每处命中打印：行号、命中词、换成什么、类型、用户哪天说的、用户点名还是预防性，外加前后文。
- `--topic-type 虚拟` 时才查"实物专用"那一类（退货、运费、快递、物流、品控、面单、囤货、包邮、运费险、七天无理由退货、签收、破损、发货慢、补发；"退款"不在内）。实物词前面带否定（"不需要囤货"）只算提醒，不计命中。
- 内置三条结构检查：第一句是不是"今天给大家分享一个"；有没有连续三行都以"我"开头；有没有阿拉伯数字、英文字母、百分号。
- 末尾一行汇总：`词表 N 条（用户点名 a / 预防性 b），命中 M 处（用户点名 x / 预防性 y），结构检查命中 z 处`。有命中退出 1，报告里贴这段输出。
