# 配料包规范

> 用途：派写手写一篇口播稿之前，先用 `engine/brief/build-brief.mjs` 把这一篇要用的"配料"从各个大文件里按编号抽出来，拼成一份一两万字的**配料包**。写手只读配料包，不再读那二十万字。
> 建立于 2026-09-07。

---

## 一、为什么要有它

写稿公式是固定的：

```
一篇口播稿 = 项目事实（固定）+ 故事 + 一批闲鱼经验
风格固定，开头角度每篇换一个
```

配料只有故事和经验在换，事实和风格是死的。以前派活时把六个大文件（加起来二十多万字）全甩给写手，写手要么读不完，要么读串。现在改成：主线程挑好编号 → 跑一条命令 → 得到一份一万多字的配料包 → 写手只读它。

**规矩：配料包里没有的，就是不许写。**

2026-09-08 起配料包末尾多一张**用户校准词表**（禁 → 换），配一个交稿前检查脚本 `engine/brief/check-words.mjs`。用户对稿子的每一次字句纠正都进这张表，同样的错不再第二次到用户眼前。词表本身见 `docs/用户校准词表.md`。

2026-09-08 晚起配料包在"开头角度"和"项目事实"之间多三节**真人语料**（真人开头结构 / 真人说法 / 原声），从 `docs/真人语料包/总表.json` 按切入大类、场景抽出来，给写手学措辞用。规矩三条：借形不借句（交稿跑十二字连抄）、亲历要换、用过的期轮换（定稿后 `engine/brief/mark-used.mjs` 写回）。三个来源打架时：节奏听风格说明书，措辞听语料包，事实听事实链。详见第九节。

## 二、命令

```
node engine/brief/build-brief.mjs \
  --style docs/人设说明书-钱十七.md \
  --factcard research-runs/2026-08-31_41_京东家政券_重制/事实卡-终版.md \
  --facts A2,A5,A6,A7,A9,A10,B1,B3,B4,B5,B7 \
  --chain research-runs/2026-08-31_41_京东家政券_重制/事实链-京东家政券.md \
  --links 2,3,4,5,6,7 \
  --angles docs/开头角度清单-京东家政-20260907.md --angle C \
  --stories docs/圣矾真实经历清单.md --story-ids 91,65 \
  --experiences docs/闲鱼经验库/总表.json \
  --exp-ids X-风控-014,X-心态-002,X-客服-001,X-风控-020,X-售后-017 \
  --pack docs/真人语料包/总表.json --episode jingdong-jiazheng-C \
  --opening-types "命令你现在做一个动作,反常识揭晓,一个画面+反转" --n-openings 5 \
  --scenes "B,D,C,H,G,E:动作" --n-sayings 30 --n-voices 5 \
  --topic "闲鱼卖京东家政券" --topic-type 虚拟 \
  --out research-runs/2026-08-31_41_京东家政券_重制/配料包-C-v3-20260908.md
```

`node engine/brief/build-brief.mjs --help` 打印用法。
Windows PowerShell 里换行续行符用反引号 `` ` ``，或者干脆写成一行。

写手交稿前跑**一条**（2026-09-08 起，替代原来的 check-words + 连抄两条）：

```
node engine/brief/check-all.mjs <稿件.txt> --rules docs/写稿规则.json --topic 京东家政 --topic-type 虚拟 `
  --chain research-runs/2026-08-31_41_京东家政券_重制/事实链-京东家政券.md `
  --against "D:/项目仓库/remotion视频制作/ips/xianyu-fanshen/films/*/copy/*/script.txt" <其它已定稿...>
```

也可以 `npm run check:draft -- <稿件.txt> --rules … --against …`。它按 `docs/写稿规则.json` 逐条跑：用户校准词表、结构位置、真人语料十二字连抄、跨期八字重合和自造命名、平台合规；人工审的行只把该看的东西列出来。输出一张表（规则 / 结果 / 命中处），有「退回」级命中退出 1，报告里贴完整输出。`--against` 给已定稿（钱十七、半佛各篇 + 本选题当前定稿），稿件自己会自动剔掉。规则表的说明见 `docs/写稿规则.md`。

定稿后主线程跑一条，把本期写回语料包的"用过的期"（编号列表直接从配料包第十三节复制）：

```
node engine/brief/mark-used.mjs --pack docs/真人语料包/总表.json --episode jingdong-jiazheng-C --ids K-开头-xxx,K-说-xxx,K-声-xxx
```

## 三、参数表

| 参数 | 值 | 干什么 |
|---|---|---|
| `--style` | 风格说明书 .md 路径 | 全文原样嵌进第二节；第十节再从中抽"交稿前机器查"那一节 |
| `--factcard` | 事实卡 .md 路径 | 配 `--facts` 用 |
| `--facts` | 逗号分隔的事实编号，如 `A2,A5,B1` | 抽事实卡表里这几行整行 |
| `--chain` | 事实链 .md 路径 | 配 `--links` 用；同时无条件抽第二、四、五节 |
| `--links` | 逗号分隔的环号，如 `2,3,4` | 抽事实链第三节链条环节表里这几环的行 |
| `--angles` | 开头角度清单 .md 路径 | 配 `--angle` 用 |
| `--angle` | 一个字母，如 `C` | 抽 `## 角度 C ·` 那一节 |
| `--stories` | 经历清单 .md 路径 | 配 `--story-ids` 用 |
| `--story-ids` | 逗号分隔的数字编号，如 `91,65` | 抽经历清单表里这几行整行 |
| `--experiences` | 闲鱼经验总表 .json 路径 | 配 `--exp-ids` 用 |
| `--exp-ids` | 逗号分隔的经验编号，如 `X-风控-014` | 从 JSON 里取这几条 |
| `--topic` | 一句话选题名 | 只用来做配料包标题 |
| `--topic-type` | `虚拟` 或 `实物` | 决定第十一节用户校准词表里"实物专用"那一类进不进：虚拟选题进（退货、运费、快递这些词不许出现），实物选题剔掉。同时决定真人语料包剔"实物专用 + 反虚拟"（虚拟）还是"虚拟专用"（实物）。不给就照列并记进缺项 |
| `--words` | 用户校准词表 .json 路径 | 默认 `docs/用户校准词表.json`，一般不用给 |
| `--pack` | 真人语料包总表 .json 路径 | 给了才出第四、五、六节。一般就是 `docs/真人语料包/总表.json` |
| `--episode` | 本篇的期标识，如 `jingdong-jiazheng-C` 或 filmId | 两个用处：轮换（"用过的期"含本期或最近写回两期的条目不进）、抽样种子（同样参数同样结果）。定稿后 `mark-used.mjs` 用同一个值写回。不给就不轮换、种子用选题名，记进缺项 |
| `--opening-types` | 切入大类名，逗号分隔，如 `"反常识揭晓,命令你现在做一个动作"` | 第四节按它抽开头结构。匹配顺序：**先按总表"切入大类"精确匹配**（配料包里标"大类精确匹配"）；匹配不到再退到旧办法——给的名字是总表"切入方式"（抽取人起的原名）的子串就算（标"包含匹配"）；还不行按 ` + ` 拆片段任一匹配（标"部分匹配"）；都匹配不到就记进缺项并在标准错误里提醒，缺项里会列出总表现有的大类名。大类清单见下面"切入大类"一节 |
| `--n-openings` | 数字，默认 5 | 第四节条数。按大类轮转各取一条直到取满 |
| `--scenes` | 场景字母，逗号分隔，如 `"B,D,C,H,G,E:动作"` | 第五节按它抽说法。只认 A–J；E 可写 `E:动作` / `E:心态` / `E:选品判断` / `E:风险与合规` / `E:客服与成交` / `E:上架与文案` 指定子场景 |
| `--n-sayings` | 数字，默认 30 | 第五节总条数，按场景均分，余数给排前面的场景；某场景不够的名额轮给别的场景 |
| `--n-voices` | 数字，默认 5 | 第六节原声条数 |
| `--authors` | 作者名，逗号分隔，如 `"一鱼,陈陈,策主"` | 可选。第五节说法只取这些作者的（开头和原声不受它限制） |
| `--out` | 输出 .md 路径 | 不给就打到标准输出 |

**路径**：相对仓库根（`D:\项目仓库\风格仿写`）或绝对路径都行。目录不存在会自动建。

**全是可选的**。缺哪个就跳过那一节，并在配料包第十二节"缺项"里写明缺了什么、后果是什么。成对的参数（`--factcard`/`--facts`、`--stories`/`--story-ids`、`--experiences`/`--exp-ids`、`--angles`/`--angle`、`--pack`/`--opening-types`、`--pack`/`--scenes`）只给一半，那一节也跳过并记进缺项。

## 四、配料包各节来自哪儿

| 节 | 内容 | 来源 | 怎么抽 |
|---|---|---|---|
| 抬头 | 标题、写稿公式、落盘要求（五分钟一千三到一千五百汉字、一句一行、单句不超五十字、全汉字数字、零头取整加"多"、交稿前跑 `check-words.mjs` 和连抄检查、三个来源的优先级） | 脚本内置 | 写死在脚本里；`--topic-type` 会填进 check-words 那条命令，`--pack` 换成 .md 填进连抄那条 |
| 二、风格说明书 | 全文 | `--style` | 原样整篇嵌入，一个字不动 |
| 三、开头 | 一个角度小节 | `--angles` + `--angle` | 从 `## 角度 X ·` 那行起，到下一条独占一行的 `---` 为止 |
| 四、真人开头结构（学结构，不抄句） | 表：编号 / 大类 / 切入方式 / 结构（⓪ 位置）/ 步数 / 适合讲什么 / 作者，默认五条 | `--pack` + `--opening-types`（+ `--n-openings`、`--episode`、`--topic-type`） | 总表 `openings` 层先按"切入大类"精确匹配（退路是切入方式包含匹配），过滤后（见第九节）按"步数 ≤ 5 优先，再按种子打乱"排序，各大类轮转取。步数列超过五步的标"口播要压缩"。表后一行死规矩："超过五步的要压缩，开头预算八句含合同句和框架"。表前一行写明每个大类按哪种方式匹配了几条、取了几条 |
| 五、真人说法（措辞照走，内容换成我们的事实） | 按场景分小表：编号 / 原句 / 作者 / 亲历标记 / 场景，默认三十条 | `--pack` + `--scenes`（+ `--n-sayings`、`--authors`、`--episode`、`--topic-type`） | 总表 `sayings` 层按场景（E 可带子场景）分池，过滤后按"口播 ✅ 先于 ？、纯措辞先于含亲历，再按种子打乱"排序，按配额取。亲历标记列：纯措辞 / 含作者亲历（里面的事要换成圣矾的）/ 本人亲历（圣矾旧期的事，不许引旧期）；口播 ？ 的加注"念一遍再用"。表前写连抄命令 |
| 六、原声（学"引一句原话"的做法） | 表：编号 / 谁说的 / 原句 / 情境 / 出处，默认五条 | `--pack`（+ `--n-voices`、`--episode`、`--topic-type`） | 总表 `voices` 层过滤后按"不含收入数字优先，再按种子打乱"取。含收入数字的可以进但加注"含收入数字，只学引原话的形" |
| 7.1 生意句三个数 | 一整节 | `--chain` | 事实链 `## 二、` 到下一个 `##` |
| 7.2 链条环节 | 表里指定的几行 + 表头 | `--chain` + `--links` | 事实链第三节内，匹配行首 `\| **N.` 的行 |
| 7.3 项目事实 | 表里指定的几行 + 表头 | `--factcard` + `--facts` | 事实卡里第一格是 `A2` / `B3` 这种编号的整行；A 段 B 段各自带自己的表头 |
| 7.4 不许入稿 | 一整节 | `--chain` | 事实链 `## 四、` 到下一个 `##`，原样 |
| 7.5 一跳规则 | 一整节 | `--chain` | 事实链 `## 五、` 到下一个 `##`，原样 |
| 八、故事 | 表里指定的几行 + 表头 | `--stories` + `--story-ids` | 经历清单里第一格恰好是那个数字的整行。**前面加死规矩**："本人经历，写成'我'，只用原话的意思，不加工、不演绎成'我以为'" |
| 九、闲鱼经验 | 指定的几条，重排成表 | `--experiences` + `--exp-ids` | 按 JSON 的 `id` 取，每条给：编号 / 经验 / 环节·类型 / 支持数 / 标记 / 备注。**前面加死规矩**："同行经验，只能写成'有人这么做 / 行业里一般这么看 / 做闲鱼的都知道'，不写成亲历，不带收入数字；⚠️ 的按备注剥数字；🚫 的不用" |
| 十、交稿前机器查 | 一整节，重复列一次 | `--style` | 风格说明书 `## 十八、` 那一节。单独再列是因为写手总漏 |
| 十一、用户校准词表 | 整表，按类型分组（禁 / 换成 / 日期 / 录入 / 用户原话 / 来源稿） | `docs/用户校准词表.json`（`--words` 可换） + `--topic-type` | JSON 里每条渲染成一行；`--topic-type 实物` 时剔掉"实物专用"那一类，`虚拟` 时保留并标"生效"。**这张表和 `check-words.mjs` 读的是同一份 JSON**，写手照表避开，交稿前脚本再查一遍 |
| 十二、缺项 | 没给的参数清单 | 脚本自己攒 | 每条说明缺了什么、写手会因此少什么；没给 `--topic-type` / `--episode` 也各记一条 |
| 十三、本包选用的语料编号 | 逗号分隔的编号列表 + 一条现成的 `mark-used.mjs` 命令 | 脚本自己攒（只在给了 `--pack` 时出） | 第四、五、六节所有条目的编号。定稿后复制那条命令跑一下就写回了；没用上的编号可以从命令里删掉再跑 |

没给 `--pack` 时第四、五、六节照样占位（写"没给 `--pack`，空着"），后面各节编号不变，写手和主线程对"第几节"的说法就不会因参数变来变去。

### 编号在原文件里出现多处

经历清单的编号在"主表"和"③ 跨选题通用经历"两张表里都出现（比如 91、65）。脚本**两处都抽**，各自带自己的表头，并在小节开头注明"编号在原文件里出现多处"。这样写手能同时看到原话版和一句话版，不会漏掉更精确的那一条。

事实卡的 A 段和 B 段是两张表，抽到的行按表分组，各带各的表头和"出自"标注（3A 实采 / 3B 第41期），这样写手一眼能看出哪条要标采集日期、哪条要标"第41期"。

## 五、报错规则

**编号找不到 → 打印哪个没找到 + 文件路径，退出码 1。**绝不静默漏一条配料。四类编号都是这个待遇：

- `--facts` 里的事实编号在事实卡里找不到
- `--links` 里的环号在事实链第三节找不到
- `--story-ids` 里的编号在经历清单里找不到
- `--exp-ids` 里的编号在经验总表 JSON 里找不到

**结构找不到 → 同样退出 1。**包括：

- `--angle` 指定的角度小节不存在（`## 角度 X ·` 这行没有）
- 事实链缺第二 / 第四 / 第五节
- 风格说明书缺 `## 十八、` 那一节
- 用户校准词表缺文件、条目缺字段、类型或录入值不认识、标了"用户点名"却没有用户原话
- 真人语料包缺 `openings` / `sayings` / `voices` 数组、条目没 id、id 重复

**文件问题 → 退出 1。**文件不存在、读不出来、JSON 不合法、JSON 顶层不是数组。

**`--topic-type` 不是 `虚拟` / `实物` → 退出 1。** `--scenes` 里有 A–J 之外的字母、`--n-openings` / `--n-sayings` / `--n-voices` 不是非负整数 → 退出 1。

**认不出的参数 → 退出 1。**打印可用参数表。

**缺参数 → 不报错。**跳过那一节，写进第十二节缺项，退出码 0。

**切入大类 / 切入方式匹配不到 / 候选不够 → 不报错。**能抽几条抽几条，差额写进缺项（并列出总表现有的大类名），标准错误里提醒一句，退出码 0。这跟"编号找不到"不一样：大类名是分类，不是编号。

## 六、体量参考

2026-09-07 的角度 C 那一份：**11135 汉字 / 17817 字符**。其中风格说明书占 5900 汉字（一半多），剩下是事实、故事、经验和各种红线。这个量写手一口气能读完。2026-09-08 加上用户校准词表（58 条）后同一份重生成为 **13740 汉字 / 24327 字符**，词表占约 2600 汉字。

2026-09-08 晚加上真人语料三节（开头五条 / 说法三十条 / 原声五条）后同一份重生成为 **18152 汉字 / 33450 字符**：真人开头结构约 970 汉字、真人说法约 1300 汉字、原声约 360 汉字、文末编号列表约 300 汉字，另外这一版词表已长到 87 条（约 3900 汉字）。

要是配料包超过两万汉字，多半是 `--facts` 或 `--exp-ids` 给多了——一篇稿正常是十条上下事实、五到六条经验、两三个故事。真人说法三十条是上限，再多写手记不住。

## 七、注意

- `build-brief.mjs` **只读不写源文件**，只往 `--out` 写一个 markdown。会写源文件的只有 `mark-used.mjs`，而且只动 `总表.json` 里的"用过的期"和顶层"写回顺序"两个地方。
- 嵌进去的风格说明书带着它自己的 `#` 一级标题，所以配料包里会有两个一级标题层。这是"原样嵌入"的代价，没改。
- 挑编号是主线程的活，不是脚本的活。脚本不会替你判断哪条事实该配哪一环——它只负责把你点的名一条不落地端出来，或者告诉你哪条点错了。
- **同一条经验一轮里只给一篇**（2026-09-08 定）。四篇并行时主线程把 X-上架-054、X-售后-005 同时配给了三篇，三篇里出现一字不差的句子。以后一轮多篇派工，`--exp-ids` 互不相交；确实要在两篇里讲同一个道理的，写手必须用本期选题自己的名词说，不许照抄经验表原句。
- **经验在稿里直接当事实说**（2026-09-08 用户点名）。不许"有人是这么干的 / 做闲鱼的都知道 / 做闲鱼的还有一个说法"这类固定开头，见校准词表 U123/U140/U141、写稿规则 R049。
- 用户校准词表的维护规矩见 `docs/用户校准词表.md`：用户亲口纠正的标"用户点名"，主线程推出来的标"主线程预防性"，后者不许冒充前者。加条目改 JSON，`check-words.mjs` 和 `build-brief.mjs` 都读它，别在别处再抄一份词表。

## 八、交稿前检查脚本 `check-words.mjs`

> 2026-09-08 起交稿用第二节那一条 `check-all.mjs`，它把这个脚本当模块调（词表只跑一遍，命中按规则表的类型归行）。单独跑它还是可以的，输出不变。

```
node engine/brief/check-words.mjs <稿件.txt> [--table docs/用户校准词表.json] [--topic-type 虚拟|实物]
```

- 逐行扫描，每处命中打印：行号、命中词、换成什么、类型、用户哪天说的、用户点名还是预防性，外加前后文。
- `--topic-type 虚拟` 时才查"实物专用"那一类（退货、运费、快递、物流、品控、面单、囤货、包邮、运费险、七天无理由退货、签收、破损、发货慢、补发；"退款"不在内）。实物词前面带否定（"不需要囤货"）只算提醒，不计命中。
- 内置三条结构检查：第一句是不是"今天给大家分享一个"；有没有连续三行都以"我"开头；有没有阿拉伯数字、英文字母、百分号。
- 末尾一行汇总：`词表 N 条（用户点名 a / 预防性 b），命中 M 处（用户点名 x / 预防性 y），结构检查命中 z 处`。有命中退出 1，报告里贴这段输出。

## 九、真人语料三节：过滤、抽样、写回、连抄

三节都从 `docs/真人语料包/总表.json` 来（`--pack`），共用 `engine/brief/corpus-pack.mjs`。总表本身怎么来的、字段什么意思，见 `docs/真人语料包/总表.md` 开头的"使用须知"和 `docs/真人语料包-抽取口径.md`。

### 过滤规则（硬，三层通用，按这个顺序判）

| 条件 | 处理 |
|---|---|
| `--topic-type 虚拟` 且 品类 = 实物专用 | 剔 |
| `--topic-type 虚拟` 且 立场 = 反虚拟 | 剔 |
| `--topic-type 实物` 且 品类 = 虚拟专用 | 剔 |
| 口播 = 图文腔 | 剔（开头层、原声层没这个字段，等于不剔） |
| 含收入数字 = true | 说法层剔；原声层**留**，配料包里加注"含收入数字，只学引原话的形" |
| "用过的期"里含本 `--episode`，或含最近写回的两期 | 剔。"最近两期"按总表顶层"写回顺序"（`mark-used.mjs` 维护，按写回先后）取最后两个不等于本期的；总表没这个键时按各条"用过的期"在文件里出现的先后推 |
| `--authors` 给了且作者不在里面 | 只对说法层生效，剔 |

没给 `--topic-type` 就前三条都不判（照列，记缺项）；没给 `--episode` 就不判轮换。

过滤掉多少、按什么原因，`build-brief.mjs` 跑完在标准输出里逐层打印（`语料包 openings 过滤：品类=实物专用 7` 这种），报告里贴。

### 排序和抽样（要可复现）

不用随机数。每条算一个 `hash(episode | 层 | 分池名 | id)`（FNV-1a），在同一优先级档里按这个数排，再按 id 兜底。所以同样参数同样结果；换一个 `--episode` 就换一批。

- 开头层优先级：步数 ≤ 5 且没标"口播要压缩"的在前。分池 = 每个大类（或退路匹配到的切入方式）一池，按请求顺序轮转各取一条，取满 `--n-openings` 为止；同一条命中多个池只取一次。

### 切入大类（`--opening-types` 用这些名字）

开头层 150 条原来的"切入方式"是五个抽取人各自起的名字，去重后 144 种，按名字选根本对不上。2026-09-08 起按"第一句干什么"归成十九个大类 + 待定，写在 `engine/corpus-pack/opening-types.json`（名 / 判据 / ids），`merge-pack.mjs` 合表时给每条 opening 贴 `切入大类`，原"切入方式"保留。改归类只改这个 JSON 再重跑合表。

| 大类 | 判据（第一句干什么） | 条数 |
|---|---|---|
| 数据冷开 | 报同行链接 / 店铺（或自家后台）的标价、想要数、浏览、总销量，先不算账 | 10 |
| 算账冷开 | 报价格和想要数，第二句立刻按转化率或单利润算出单量、总收入 | 13 |
| 报数+反转 | 报一个看着不值钱或不对劲的数（免费、几毛、退了几单），第二句反转：正因为这样才赚 | 6 |
| 热点借势 | 引一个正在刷屏的东西（传言视频、朋友圈业务、收益截图、新火的工具），接着给判断或提前布局 | 4 |
| 澄清传言 | 引一条新规或大家传得慌的说法（常带传言原话），接着从头捋清楚 | 7 |
| 开门见山预告 | 直接说这期讲什么（拆解 X、只做揭秘、几个误区、把结论整理成一篇），两三句就进编号 | 11 |
| 命令你现在做一个动作 | 先别往下划、打开你的店或详情页看一眼、先问自己一句 | 4 |
| 反常识揭晓 | 先说"以前以为 / 大家以为"的原因，逐个否掉，再揭晓真正的原因或改口 | 6 |
| 反直觉总结 | "做了几年"起手，第二句给一个跟直觉相反的总感悟，再分类展开 | 4 |
| 断言+推演 | 一句反常识断言或狠话，接着一步步推演后果、画出人群或打比喻 | 10 |
| 提问→极简回答→展开 | 抛一个问题或困境，马上给一个极短的答案，剩下全篇展开 | 7 |
| 一条消息引出道理 | 引刚收到的一条消息、私信、学员 / 朋友 / 很多人问的同一个问题（常带原话），顺着讲道理 | 14 |
| 亲历见闻引出 | 讲自己刚遇到、刚做、刚看见的一件事（测了个东西、买了一次、翻到一个品），由它引出正题 | 11 |
| 续篇承接 | 回链上篇或回应上篇的反响（书接上文、后台炸了、读者追问），直接进编号 | 10 |
| 一个画面+反转 | 一个具体画面、一件旧物或一句原话，第二三句反转或由它带出全程 | 7 |
| 转变宣言 | 一句话交代自己的转变、决定或低谷（从 A 到 B、不想一辈子 X、我也有过瓶颈） | 12 |
| 自画像 | 描述自己的性格或身份（内向、带娃妈妈、工地出身），由此说明为什么做这个 | 5 |
| 小事归因 | 引"你是怎么做到的"，否定有转折点，把原因归到一件很小的事 | 3 |
| 反面场景+编号 | "你是不是也……"替读者描述一个失败场景或痛点，点名后果，再进编号 | 5 |
| 待定 | 归不进的（目前只有圣矾的投流广告片一条） | 1 |
- 说法层优先级：口播 ✅ 先于 ？，纯措辞先于含亲历（四档）。分池 = 每个场景（含子场景）一池，`--n-sayings` 按池数均分、余数给前面的；某池不够，剩下名额轮给还有货的池。
- 原声层优先级：不含收入数字在前。单池。

### 写回"用过的期"

```
node engine/brief/mark-used.mjs --pack docs/真人语料包/总表.json --episode <期标识> --ids K-开头-xxx,K-说-xxx,K-声-xxx [--dry-run] [--indent auto|2]
```

- 编号从配料包第十三节复制；没用上的删掉再跑也行。三层编号混着给。
- 任一编号找不到 → 一条不写，退出 1。已含本期的跳过，不重复追加。
- 只改"用过的期"和顶层"写回顺序"，其它字段原样；原声层原本没有"用过的期"字段，写回时补上。
- 缩进默认跟原文件一致（合表脚本 `merge-pack.mjs` 写的是 1 格），这样 git diff 只有改动的那几行；要 2 格就 `--indent 2`。
- `总表.md` 里的"用过的期"列**不会**跟着更新，那份是 `merge-pack.mjs` 生成的展示件；机器只读 `.json`。下次重跑合表脚本前要先把 `.json` 里的"用过的期"和"写回顺序"合并回去，不然会被清空——这是目前的一个坑。

### 交稿时的连抄对照

```
node engine/leakage/check-source-leakage.mjs --corpus docs/真人语料包/总表.md --drafts <稿件.txt>
```

十二个字连着和总表一样就算命中，命中即打回。对照库是整个总表（开头结构、说法、原声、作者档案都在里面），不只是配料包里抽出来的那几十条——写手看了配料包之外的语料也一样查得到。`leakage-rules.json` 里的受保护短语（品牌清单、签名句）先剔掉再比，不算命中。脚本本身没改。
