# 用户校准词表

> 用途：用户对口播稿的每一次字句纠正，变成一条机器规则；同样的错不再第二次到用户眼前。
> 真身是 `docs/用户校准词表.json`，这份 markdown 是从它生成的（`node engine/brief/check-words.mjs` 读 JSON，不读这份）。改词表改 JSON，改完重新生成这一页。
> 建立于 2026-09-08。现在 **58 条：用户点名 28 / 主线程预防性 30**。

---

## 一、怎么用

交稿前跑一遍，命中即改，报告里贴输出：

```
node engine/brief/check-words.mjs <稿件.txt> --topic-type 虚拟
node engine/brief/check-words.mjs <稿件.txt> --topic-type 实物
```

- `--topic-type 虚拟` 才查「实物专用」那一类；实物选题不查。不给就不查那一类并提醒一句。
- 有命中退出 1；没命中退出 0；参数或文件出错退出 2。
- 除了词表，脚本还内置三条结构检查：第一句是不是「今天给大家分享一个」；有没有连续三行都以「我」开头；有没有阿拉伯数字、英文字母、百分号。
- 实物专用词前面带否定（「不需要囤货」「不用发快递」）只算「提醒」，不计命中，人自己判断——虚拟品说「不用寄东西」是它的卖点，不该被机器一刀切。
- 配料包生成器 `build-brief.mjs` 加了 `--topic-type`，会把这张表按选题类型过滤后整表贴进配料包第八节。

## 二、两种录入，不许混

| 录入 | 意思 | 谁能加 |
|---|---|---|
| **用户点名** | 用户亲口说过这个词不对（原话记在「用户原话」列，日期是他说的那天） | 只有用户说了才能标 |
| **主线程预防性** | 主线程从同一病根推出来的同类词，用户没点过名 | 主线程；「用户原话」列必须空着，不许冒充用户点名 |

一条预防性的词后来被用户点了名，就把录入改成用户点名、补上原话和日期。

## 三、每条的字段

```
{"id":"U001","禁":"挂红条","换":"被平台挂了退款多的提示 / 店铺页顶上有平台的提示",
 "类型":"内部术语","日期":"2026-09-07","用户原话":"挂红条是啥意思？",
 "来源稿":"京东家政 C v2","录入":"用户点名"}
```

- `类型` 只能是：内部术语｜压缩词｜自造对仗｜书面词｜整齐收口｜经验表用词｜套用错｜空包袱｜开头固定句｜旧系列引用｜实物专用
- 可选字段：`正则`（给了就按正则匹配，否则按「禁」做字面匹配）、`位置`（`第一行` 表示只查稿件第一句）、`说明`
- 「实物专用」只对虚拟选题生效；**「退款」不在内**，虚拟品也有退款。
