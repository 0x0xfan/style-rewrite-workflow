# 学结构，不学用词

**适用范围：所有 IP 的 DNA 拆解、风格卡沉淀、改写生成。**

这条规则解释一件事：为什么我们此前的"抽象公式"其实只是一句话标签，导致生成时只能替换名词，看起来"像"但实际上只是穿了同一件外套的另一个名词。

## 出过的问题

- **兰州拉面 → 海底捞**：钱十七原稿里"从一天一顿兰州拉面，变成一天一顿海底捞"是一次生活消费阶梯——公式是"[频率][低档] → [同频率][同类高档]，收入变化由读者推断"。此前拆解把它记成"用生活场景写收益"这一句话标签，生成时的直接后果就是把参照物换成"沙县 → 海底捞"或"泡面 → 海底捞"——结构没懂，名词照搬。
- **鸡蛋卷在床上打滚**：半佛旧档案把这句话本身当模板存起来，配文"用魔幻画面表达尴尬"。结果生成稿里出现"鸡蛋卷在床上打滚"的近变体，触发 lifted-phrase 拦截；抽掉之后又只剩下一个空洞的一句话标签，写不出新画面。
- **共同症状**：所有这些"公式"都长得像"用 X 写 Y"——一句话读起来抽象，但落到笔上只有一件事可做：把原句里的名词替换成另一个名词。生成稿因此和原稿共享几乎所有具体名词，靠改一两个词逃过字面复用检查。

## 标准：什么才算"学到了结构"

一条风格控制要沉淀进 DNA 或风格卡，必须同时具备以下五项。缺任一项都只算标签，不算结构。

| # | 要素 | 判定 |
| --- | --- | --- |
| 1 | **槽位定义** | 明确写出这条句式有几个槽位，每个槽位装什么类别的内容（时间频率？消费档位？动作对象？情绪词？） |
| 2 | **槽位之间的关系约束** | 槽位之间是什么关系：同类、倍数、顺序、重复、对立、递进？读者是靠哪个关系推出结论的？ |
| 3 | **功能** | 这句话在读者身上起什么作用：建立价值、留住注意、驱动行动、触发情绪、代入身份？回答"为什么用它"。 |
| 4 | **负面样例** | 至少列两种失效情形：结构写对了但功能不成立，或者结构走样成了另一种东西（触发平台规则、变成收益推算、退化为形容词堆砌）。 |
| 5 | **≥ 3 个结构一致但用词全新的实例** | 三条实例必须槽位关系完全对齐，但所有具体名词换掉；且不出现来源原稿里的任何具体参照物（人名、店名、金额、地名、道具）。 |

**范例规格**：`ips/钱十七/dna/钱十七-DNA-重构版.md` 的 P8 生活消费阶梯正在按这个标准补写（公式 + 适用位置 + 边界 + 证据齐备，实例正在补三条全新场景）。它是本规则的示范位置；后续所有辅助模式（P1–P8、A1–A7）都要向这个规格看齐。

**槽位怎么写才够具体**：

- 差的写法："用生活场景写收益。"（读者不知道有几个槽位、槽位装什么。）
- 中的写法："[频率] + [消费档位]。"（有槽位但没关系约束，也没功能。）
- 好的写法："槽位 A = 时间频率（"一天一次"、"每周一次"）；槽位 B = 一档具体消费（"某种主食"、"某种交通"）；关系：前后两句的 A 完全相同、B 属同一类目但档位跨越明显（快餐 → 火锅，公交 → 网约车）；功能：让读者用自己的物价常识推出收入变化，不出现任何金额；实例：见 P8 补写的三条。"

## 自检方法

改写稿或新加的风格控制卡，在提交前用两步自查：

1. **拆回槽位**：把生成的每一句关键句拆回声明的槽位定义。填不进去，或者要额外解释才能填进去——结构没落到句子上，回炉。
2. **共享名词扫描**：把生成的关键句和来源原稿的对应句放一起，列出两句共享的所有具体名词（人名、店名、菜名、金额、频率数字、地名、品牌）。**只要共享任何一个具体名词，就视为改名词而不是套结构，回炉重写。** 允许共享的只有槽位的类别标签（"某种主食"、"某档消费"），不允许共享槽位的具体填充值。

自检失败必须回到 DNA 层面追问：是原公式写得太笼统（只是标签），还是生成时没按公式走？两种原因的修法不同——前者改 DNA，后者改生成 prompt。

## 现有拦截层的分工

| 层 | 拦什么 | 拦不住什么 |
| --- | --- | --- |
| `engine/tests/platform-compliance.test.mjs` 的 lifted-phrase 测试 | 生成稿逐字或近似复用来源原句（比如"鸡蛋卷在床上打滚"、"月入过万"） | 换一个名词的近亲复制（"沙县 → 海底捞"这类只改一个词的复用） |
| `engine/compliance/check-copy.mjs` | 平台高风险表达（收益数字、承诺、导流） | 结构错位（消费阶梯写对了但紧挨一个收益数字，规则会命中数字这一层，但不会告诉你结构本身失效） |
| **本规则 + 人工审** | 名词换过、字面测试过、平台检查过，但槽位关系没对上或和来源共享具体参照物的情况 | —（这一层就是兜底，没有更下游的自动拦截） |

## 与其他文档的关系

- `docs/platform-compliance.md`：短视频合规是这条规则的一个下游后果——消费阶梯这种"用结构过合规"的手法，只有结构真的被拆到位、生成时真的按结构走，才顶得住数字紧邻检查和 lifted-phrase 拦截。
- `docs/style-dna-spec.md`：JSON 契约里的 `replication.rules` 字段应当承载本规则的五要素；只写一句话标签的 rule 视为不完整，评分器不应据此打分。
- `AGENTS.md` Project-Specific Rules 中"抽象公式 + 适用条件 + 证据锚点 + 风险边界"这条已追加一句：抽象公式必须达到本规则的五项标准。

## 一条铁律

**"抽象公式"不是给公式起个抽象名字，而是把公式写到能填空的程度。**

写完一条控制，先自己填三个和来源无关的例子。填不出三个不同场景，就是这条公式还停留在标签层，别沉淀进 DNA，也别用它生成。审稿时看到"用 X 写 Y"型的一句话公式，直接打回；看到实例里出现来源原稿的具体名词（人名、店名、菜名、金额、地名、品牌），也直接打回。
