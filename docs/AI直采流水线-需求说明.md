## 流水线（八步）

1. **用户提交选题单**：

   ```
   选题词：xxx（闲鱼搜索词，1–3 组）
   产品从哪来：一句话线索（如"GitHub 有开源工具"）
   渠道资源：一句话，可空
   拿货价线索：大概成本或去哪查，可空（缺了利润推算出不了数）
   可选叮嘱：受众档位、长/短视频、其他
   ```

2. **AI 采集闲鱼数据**（用户已登录的 Chrome，固定时段批量采）：
   - 搜索结果列表：标题、价格、想要人数、地区、卖家标签、商品链接
   - Top 3–5 详情页：价格、想要人数、浏览量、店铺已售、好评率、店龄、链接
   - 汇总统计：商品总数、有想要的商品数、Top 想要分布、价格带、标题共同词、扩展词
   - 截图留档：搜索结果页全貌 + 各 Top 详情页（数据区域清晰），入素材包目录
   - **数据口径红线**（继承 goofish-research）：单品数据（想要/浏览）与店铺数据（已售/好评率/店龄）严格分开；禁止把店铺已售写成单品销量
3. **AI 资源溯源**：按线索搜 GitHub/网盘/官方渠道，验证来源、交付方式、可否合规复制；产出供应路径说明；经验沉淀进知识库"渠道字典"。**硬规则（2026-08-28 补）：溯源随采集默认执行，不得推迟到写稿前**——用户没给线索也要至少跑一轮公开检索（GitHub/闲鱼知识库/网页）再交审；素材审核包的"供应路径"栏只许两种状态：有初查结论，或"检索过确实查不到"（附检索词）。空标"缺口"不算完成。理由：做不做的拍板依赖货源可得性（mac微信多开一役的执行偏差教训）
3.5 **素材完整性硬规则（2026-08-28 用户令）**：
   - **需求分析是素材包必备层**——百度搜索下拉/相关搜索/结果页等第二信源佐证，每个选题都要有，**不论选题来自新采还是用户原版视频**；缺需求分析不算素材整理完成。
   - **原版视频抽帧必须去边框**——视频画面里内嵌截图四周的边框/留白/黑边要裁掉，只保留内容主体，处理后才算合格素材图。
   - **原版视频抽帧不得带烧录字幕条（2026-08-31 用户令）**——优先在口播句间隙抽无字幕帧；确无干净帧时优先"裁掉底部字幕带"保高数据（关键数字在裁剪线上方时），再退选字幕最短且不压关键信息的帧，并在清单注明。
   - **抽帧四边不得残留桌面/壁纸底（2026-08-31 视频方验收反馈）**——裁边后用程序化边缘检测复核（四边逐像素查壁纸色），零残留才交付。
4. **素材关（硬门，2026-08-28 用户令）**：素材整理完成后必须依次做两件事，然后停下：
   ① **立即交视频项目入池并新建一期**（单写者原则：上游只交付+通知，入池与立期由视频方执行）；
   ② **素材包 + 题材判断五信号（需求密度/标题一致性/价格分层/供应路径/录制可视化）交用户审核**。
   **用户未明确确认"素材合格/可以写"之前，禁止进入事实卡终版与写稿环节**——素材审核是写稿的前置硬门，不得并行抢跑
5. **AI 组装事实卡（= 事实 contract）**：受众档位、核心结论、事实清单（来源+核实状态）、同行数据、利润推算（口径见下）、供应路径、风险与规避、亲测/案例素材（从 52 期字幕库与用户口述取，缺则标缺口，不编造）
6. **生成**：事实卡 + 知识包 + N 风格档案 → N 篇稿；过六道门禁 + 信任配方保留清单（真实数据先行、推算透明、风险直说、保守口径、不夸大收益）
7. **交付**：文案成稿（带画面提示的分段格式：画面/口播/目的）+ 截图素材包 → 视频生成项目。**硬规则（2026-08-27 补，两次教训）：凡把成稿交给用户终审，必须同时产出并首先发送"纯口播稿"（只含要念的字的 .txt），终审以口播稿为主件，分段稿只作分镜参考附件**——用户读的、视频管线吃的，都是口播稿
8. **数据回流**：发布 7 天后回填播放/完播/评论风向/粉丝净增，双周复盘

## 二创入口（用户给文案的工作流，2026-08-28 用户令）

用户提交一篇现成文案（贴文字/文件路径/链接）+ 指定风格后，不得直接改写，必须走带两道确认关的流程：

1. **提炼核心产品（产品关）**：从文案中识别"这篇讲的产品/玩法是什么"，给出一句话概括 + 建议的闲鱼搜索词候选 → **停，交用户确认**（理解错产品会白采一场，此关不可跳）
2. **搜集数据（素材关）**：用户确认产品后，走标准素材流水线——闲鱼采集（含详情/店铺层）+ 货源溯源 + 需求分析（三层缺一不可，见 3.5 节）+ 原文案事实抽取入事实卡（原文数字标"来源文案宣称，未核实"）→ 素材入视频项目池并立期 → **停，交用户审素材**（同第 4 节硬门）
3. **生成**：用户确认素材合格后，按指定风格成稿 → 六道门禁 + 信任配方 → 终审

## 利润推算口径（用户拍板，2026-08-26）

- **估算单量 = 想要人数 × 30%–50%**（闲鱼"想要 → 成交"经验转化率，用户口径）
- 文案中只写区间，不写点估计；拿不准取下限
- 收益推算 = 估算单量区间 × 单利；单利来自真实同行定价与拿货价，缺拿货价时标注"未核实"
- 推算永远标注为"推算"，与"实测"分层表述，不得混淆

## 对 goofish-research 的处置

- **继承**：采集字段、单品/店铺口径红线、题材判断五信号、供应路径不明时的稳妥表达（禁写"零成本、直接拿货"）、"每个关键判断可回到数据或链接"的证据底线
- **拆掉**：其文案生成部分（推荐结构、钩子写法、互动/CTA 规范）——写稿职责归风格仿写引擎，风格由各 IP 档案控制
- **保留其"画面驱动格式"**（画面/口播/目的）作为成稿输出格式，服务视频生成
- **新增**：截图规范化留档、资源溯源与渠道字典、事实 contract 标准接口、批量选题、数据回流

## AI 的边界

1. 登录、验证码、滑块：用用户已登录的 Chrome，不新建登录态；遇人机验证停下叫用户
2. 买同行的货（采购式调研）：涉及支付，每单需用户确认后才下
3. 亲测素材只来自用户（字幕库+口述），AI 不编造
4. 核心事实未核实的选题不进生成；核实以用户抽检为准
5. 门禁只保证不违规/不重复/不像 AI；"好不好"由用户按信任配方八条抽检终审

## 首次技术验证结论（2026-08-26，选题「ai拼车」）

- **主链路跑通**：两级健康检查 → 登录态搜索采集（第 1 页 30 条）→ Top3 详情（单品/店铺口径分开）→ 对照词补采 → capture.json / 汇总统计 / 事实卡草稿三份产物落盘。产物见 `research-runs/2026-08-26_ai拼车_验证/`。
- **耗时基准**：全程 14.5 分钟（含 3 分钟截图试错）；稳定后预估 **10–12 分钟/选题**（主词 30 条 + 对照词 + Top3 详情 + 三份产物）。
- **固化进流程的经验**：
  1. 采集前两级健康检查：扩展连接 + 闲鱼登录态（检测登录框/"猜你喜欢"填充/右上角用户名），任一不过即停；"登录门"与验证码并列为硬停点。
  2. **选题词策略**：泛词只用于发现题材，实采与选品按具体产品词展开（实证：「ai拼车」Top1 仅 17 想要，对照词「gpt拼车」Top 达 299/258/217）。
  3. 选题单增加"拿货价线索"栏——拿货价缺口会导致利润推算无法出数。
- **已知能力缺口**：受控标签页截图无法落盘为文件（三种方案均失败，其一曾误将用户另一 Chrome 窗口置前并截图，已立即删除）。暂不把截图留档作为验收硬门，数据以 DOM 文本采集为准；待补"扩展侧 CDP 截图落盘"通路后恢复截图要求。
