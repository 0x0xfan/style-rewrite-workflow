- 权威规范（唯一合同）：`D:\项目仓库\remotion视频制作\docs\handoff\film-input-spec.md`

## 一个影片输入包的构成

```
films/<film-id>/
├─ script.txt          # 必需 · 纯口播稿（TTS 直接吃）
├─ storyboard.md       # 分镜参考件（成稿原格式，口播与 script.txt 逐字一致）
├─ assets-src/         # 该稿实际引用的整页截图 PNG（已改名）
└─ assets.md           # 素材清单 + 头部元信息
```

- `film-id`：小写 kebab-case，内容可辨，定了不改（全链路稳定键）。

## 从成稿到 script.txt 的转换规则

`script.txt` = 逐段抽出成稿的**口播**字段拼成的纯口播稿。硬要求：

1. **只含要念的字**：零标题、零段名、零画面提示、零注释、零 markdown 记号、零文件名。
2. **中文标点，句号为分句锚点**：单句 ≤50 字（最长 60）。超长句把**逗号/分号升级为句号**做最小拆分——不改词序、不改内容、不增删字。
   - 拆分避坑：不要把句子拆成以裸「的」收尾（会触发 ai-flavor 的悬空「的」门禁），改在邻近逗号处拆或让该句含系动词「是」。
3. **数字写成 TTS 能念的样子**：区间「130–1200」写「130到1200」、「30%–50%」写「30%到50%」、「¥20.21」写「20.21元」或成稿原有口语写法；破折号一律消灭。（本轮两稿口播本就全用中文数字，无需改写。）
4. 编码 UTF-8；口播分段之间空行分隔，段内换行随意。

## storyboard.md

成稿原格式照搬，两个硬要求：

- 每段**口播**字段与 script.txt 对应片段**逐字一致**（步骤 1 的标点微调要同步进来）。
- **画面**提示（及文件内一切素材引用）改写成 assets-src 的新文件名。

- 按权威合同文末自查清单逐项过：script 通读全是能念的字；storyboard 口播与 script 逐字一致（**脚本比对，不目测**）；每图有清单行、命名合规。
- film-id 的「发车」信号由主线程在用户终审后发出，**转换会话不通知 remotion 会话**。

## 素材入池规则（2026-08-27 与视频方议定，替代上文"待办改进"条）

- 背景：2026-08-27 双写竞态实录（上游回滚与视频方入库同时发生）。另注：manifest 的 path 为 public 相对路径，物理文件在 public/<path> 下——即便未来恢复上游直写也须遵守。
- 面板显示：素材库读 manifest 实时数据，刷新即见，无额外步骤。
