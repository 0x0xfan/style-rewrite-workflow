## 需要你拍板的

### 1. 四篇样稿，你更认哪一套方法

- **是什么**：同一个题目（闲鱼餐饮券），我们用两套不同的“拆解方法”各写了长、短视频共四篇稿子：
  - `ips/钱十七/outputs/闲鱼餐饮券-长视频版.md`
  - `ips/钱十七/outputs/闲鱼餐饮券-短视频版.md`
  - `ips/半佛/outputs/闲鱼餐饮券-长视频版.md`
  - `ips/半佛/outputs/闲鱼餐饮券-短视频版.md`
- **为什么得你定**：机器只能查“结构对不对、有没有抄”，查不了“读起来像不像、能不能用”。这一步只有你能判断。而且钱十七那套“严谨方法”之前连过三次机器检查、你还是三次都觉得不像——所以不能靠机器,只能靠你看。
- **这决定什么**：你选的这套方法，就是以后接新博主时走的路子。选错了，后面几十个博主都会跟着走弯路。
- **选项**：(A) 更认钱十七那套“慢工出细活、每句都有出处”的方法；(B) 更认半佛那套“看几篇就上手、直接写”的方法；(C) 两套各有用，分场合用。
- **我的建议**：先各挑长、短两篇通读一遍，凭直觉记下“哪篇最像那个博主本人在说话”，别先看报告。看完再翻报告 `docs/F011-双路线对照-闲鱼餐饮券.md` 对照。我个人观察：半佛那套在“学到结构、没抄用词”上表现更干净（它的比喻、画面都是新造的，没照搬原文），可作参考，但最终以你的耳朵为准。

### 2. 稿子里的数字，发之前用不用、用哪些

- **是什么**：四篇稿子共用了一组数字——新号 3 天出单、一周日均几百单、月入过万、一张券 30 拿货 38 挂出赚 8 块、一天 100 单约 800 元。
- **为什么得你定**：这组数字是从 8-16 那篇半佛稿子里抄过来当“对照实验的固定条件”用的，**没有任何独立来源、没核实过**。真发出去,数字对不对、会不会惹麻烦,只有你清楚。
- **选项**：(A) 都不用,发之前全部换成你自己核实过的真实数字;(B) 只留你能背书的几个;(C) 先按你的真实经营数据重写这组数字再谈发布。
- **我的建议**：发布前这组数字一律当“待核实”,你亲自确认过哪个才留哪个。这是项目的硬规矩(不能把别人稿子里的事实直接搬进自己的稿子)。

### 3. 以后写稿走“严格流程”还是“快速流程”

- **是什么**：写一篇稿子有两种干法。
  - **严格流程**：先把事实一条条核实 → 再去资料库里找相关素材凑进去 → 写之前先做一遍“开工检查” → 才动笔。
  - **快速流程**：直接按博主风格写 → 写完用机器查（合规、重复、有没有抄）。
- **为什么得你定**：这一个月我们实际一直在走“快速流程”,但项目最早的设计文档要求的是“严格流程”。两套对不上,得你定哪套算数。
- **选项**：(A) 强制走严格流程(慢但稳);(B) 认可快速流程,把老文档里严格流程的要求删掉;(C) 平时快速、正式发布前补严格流程的关键几步。
- **我的建议**：选 (C)。日常出稿用快速流程保效率,真要对外发的稿子补上“事实核实”这一步就够,不必每篇都走全套。

### 4. 钱十七的“机器版档案”要不要解锁更新

- **是什么**：钱十七有两份档案——一份是**人读的**（给人看的风格说明），一份是**机器读的**（让程序自动照着写）。昨天想把人读档案的新内容（比如“互动指令”“消费阶梯”这些新总结）同步进机器版,结果卡住了。
- **卡在哪**：负责校验的外部工具其实**通过了**、没报错。真正拦住的是仓库里一条**写死的自检**——它规定机器版档案“只能有 7 条规则”,多一条就报红。我们不能在没你同意的情况下去改这条自检,所以把机器版恢复了原样。
- **为什么得你定**：放宽这条自检等于改动项目的“安全锁”,该由你拍板。
- **选项**：(A) 放宽这条自检,让机器版跟上人读版;(B) 先不动,维持现状。
- **我的建议**：**建议放宽并同步**。因为人读档案已经更新了、机器版还锁在旧状态,两份档案会越差越远,以后自动写出来的东西会越来越不像。（细节见 `ips/钱十七/audits/contract-sync-blocked-20260822.md`）

### 5. 两个残留文件删不删

- **是什么**：
  - `workbench_rewrites/`：老工作台 6 月留下的一次改写残留,现在没用了。
  - `ips/半佛/outputs/闲鱼餐饮券-图文版.md`：一篇“图文版”稿子,和这次对照的四篇（长/短视频）不是一类,单独躺在那。
- **为什么得你定**：删东西不可逆,得你确认没用了再删。
- **选项**：(A) `workbench_rewrites/` 直接删;(B) 先留着;图文版那篇——归类保留 / 删掉 / 不管。
- **我的建议**：`workbench_rewrites/` 可以删（老工作台早停用了）;图文版那篇先留着,它不参与这次判定,不碍事,等你 F011 判定完再决定它的去留。

### 6. 要不要推送到 GitHub

- **是什么**：昨天一整天(含昨晚)一共有 **二十多次改动**都只在本地,没传到 GitHub。
- **为什么得你定**：推送等于把这批改动正式对外记录,该你决定时机。
- **选项**：(A) 现在推送;(B) 等 F011 判定完、可能还要改稿,判定后一起推。
- **我的建议**：选 (B)。反正只有你一个人在做,晚点推没风险;等判定完、该改的都改了再一次推干净。

- **两份档案都做了“结构化升级”**：按新规矩“学结构不学词”,把风格说明从“一句话标签”改写成“能照着填空的公式”(几个槽、每个槽装什么、槽之间什么关系、写坏了什么样、再给三个全新例子)。
