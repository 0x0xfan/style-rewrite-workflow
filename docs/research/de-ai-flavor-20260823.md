# 去 AI 味调研（面向中文口播稿）

- 日期：2026-08-23
- 目的：研究 GitHub / 社区的"去 AI 味"方法，提炼一份**面向中文口语/口播稿**的 AI 味特征清单，对本项目两篇稿子抽查验证，给出可落地的分档建议。
- 范围提醒：多数"去 AI 味"项目以 SKILL / prompt 形式改写为主，几乎没有现成的**量化检测器**；量化阈值需本项目自建（见第 5 节）。
- 用法：本文只做调研与抽查，不改任何稿子；抽查中的"改法"仅为示例。

| S4 humanize-zh | 结构均匀/语气平滑/无不完美；分文体 | prompt/Skill，改写模式 + 策略模式 | 否 | 中文原生 |

| S7 ai-flavor-remover | 刻板句式/机械过渡/AI 高频短语/情感平淡 | 多步 prompt，变句式+注入视角+制造互动 | 否（以检测器分数为效果指标） | 中文原生 |
| S10 yage.ai | 翻译腔（英文句法骨架 + 中文皮） | 归化：盖上原文用中文重说 | 否 | 中文原生，机理解释最深 |

**共识要点**：
1. 去 AI 味不是"加随机噪声/堆口语词"，而是模拟真人写作的**不完美与具体性**（S4）。
2. 目标不是骗过检测器，而是真正提升可读性（S3）；检测器（GPTZero/朱雀）有非平凡错误率，不能单靠（S1/S7）。
3. **个人/口语文要保留作者风格，说明文才求中性**（S2）——这条对本项目做 IP 仿写至关重要，直接关系"去 AI 味 vs 保 IP 风格"的边界。
4. 多为"编辑线索而非禁词"：单次出现无罪，**重复/空洞才触发**（S6）。

## 3. 合成清单：面向中文口语/口播稿的 AI 味特征（22 条）

例句均为自造，非引本项目稿件。"可否程序检测"：✅正则/统计可测｜🟡统计可近似、需人工复核｜❌须 LLM/人判断。

| # | 特征 | AI 味例句（自造） | 人话改法（示例） | 可否程序检测 |
|---|------|------------------|------------------|----------|
| 1 | 电报体过度省略（省主语/宾语/助词，为求"高级"而删到不像口语） | "券虚拟，拍下自动发，最省事。" | "券是虚拟的，你拍下它自动就发了，最省事。" | 🟡（可查无主语短句连发比例） |
| 2 | 悬空"的"字结尾结构（"只收说得清的""挑对的"，宾语被吞） | "只做能落地的。" | "只做那些真能落地的项目。" | ✅（句尾"的。/的？"占比） |
| 3 | 排比三连 / rule-of-three（凑三点，机械对齐） | "省时间、省成本、省心力。" | "最省时间；成本嘛也就几块；至于心力，看你自己。" | 🟡（顿号/逗号三项等长列举计数） |
| 4 | 反问句堆叠（每段一反问，甚至连续多句反问轰炸） | "货哪来？渠道稳吗？出事算谁的？平台信谁？" | "货从哪来，是第一个要想的。渠道下个月还在不在，也得盯着。" | ✅（连续以"？"结尾句计数） |
| 5 | 金句收尾壳（每节必甩一句对仗警句作总结） | "它挣的是辛苦钱，不是聪明钱。" | "说到底就是个辛苦活，别指望它多聪明。" | 🟡（段尾对仗/短断句模式） |
| 6 | 冒号金句壳（"短语：短语"充当结论） | "第一条规矩：不图便宜，只图放心。" | "所以第一条，别图便宜，图个放心。" | ✅（"…：…"结论式冒号计数） |
| 7 | 破折号滥用（——当停顿/戏剧效果，口播读不出） | "有样东西不占地方——餐饮券。" | "有样东西不占地方，就是餐饮券。" | ✅（——每篇计数） |
| 8 | 引号滥用（吓人引号/给普通词强行加引号） | "别只盯着'最低价'这个'坑'。" | "别只盯着最低价，那多半是个坑。" | ✅（引号密度统计） |
| 9 | "不是 X 而是 Y" / "不是 X，是 Y"（否定式对照壳） | "这不是倒券，是拿时间换差价。" | "说穿了就是花时间赚点差价，谈不上倒券。" | ✅（正则匹配"不是…(而)?是…"） |
| 10 | "不仅 X 更 Y" 虚假递进（同一点说两遍充递进） | "不仅省钱，更省心。" | "省钱，顺带也省心。" | ✅（正则"不仅…更/还…"） |
| 11 | 总结壳口头禅（说白了/这就是/核心是/本质是/说穿了，硬贴帽子） | "说白了，核心就是信息差。" | "其实赚的就是别人懒得查的那点信息差。" | ✅（词表匹配，看是否高频/每段一顶） |
| 12 | 句长方差过小（句子长度太整齐，节奏机械） | 全篇每句 8–12 字，无长短起伏 | 穿插一句长解释 + 一句三字短句 | ✅（句长标准差/变异系数） |
| 13 | 缺口语赘词与插入语（其实、就是、然后、我跟你讲、怎么说呢） | "渠道很重要。选错就白费。" | "其实吧，渠道最重要，你要是选错了，后面基本白干。" | 🟡（口语标记词命中密度，下限） |
| 14 | 缺具体可感细节（抽象泛化，无数字/场景/人物） | "很多人都栽在这上面。" | "上周就有个卖了三个月的号，一批券作废直接封了。" | ❌（须判断是否具体） |
| 15 | 四字格/对仗过密（成语与对句连用，书面腔） | "来路不明、后患无穷、得不偿失。" | "券来路不清，出了事你兜不住，不值当。" | 🟡（相邻四字格连用计数） |
| 16 | 过度压缩（信息密度高到人嘴说不出，一句塞多层因果） | "券到期门店不认叠加受限售后全砸手里。" | "券要是到期了、门店又不认，售后就全压你身上。" | 🟡（单句字数 + 从句/因果层数） |
| 17 | AI 高频词（赋能/助力/打造/闭环/值得注意的是/不难发现/至关重要/深入） | "这套打法能助力你打造副业闭环。" | "这么干，副业慢慢就能转起来。" | ✅（黑名单词表命中=0 目标） |
| 18 | 机械连接词（首先/其次/最后、然而/此外/因此 段段照用） | "首先找货，其次定价，最后售后。" | "货先解决，价格随手定，真正费劲的是售后。" | ✅（连接词句首命中率） |
| 19 | 悬念标题党 setup（"不是你以为的那关""其实真相是"） | "卡住你的，从来不是你以为的那个。" | "很多人卡在选品，其实真正难的是售后。" | 🟡（"不是你以为/其实真相/真正的X是"正则） |
| 20 | 模板化互动结尾（收藏/关注下期/打在评论区，且跨稿雷同） | "先收藏，关注我下期讲。评论区扣个1。" | 依据具体动作给一句自然引导，且各稿不撞同一骨架 | ✅（结尾 CTA 模板指纹比对） |
| 21 | 翻译腔（被字句、代词冗余、定语从句前置堆叠） | "被平台判定为违规的账号是无法被恢复的。" | "平台一旦判你违规，号基本救不回来。" | 🟡（被字句密度 + 长定语前置） |
| 22 | 空强调壳（"真正 X 的""值得一提的是""不可否认"，强调却无信息） | "真正决定成败的，是你的执行力。" | "能不能成，就看你肯不肯天天盯着做。" | 🟡（"真正…的(是)""值得一提"正则 + 人工看是否空洞） |

### 4.3 关键交叉发现（最强 AI 味铁证）

两篇稿子在核心规矩句上用了**同一个模板**：
- 钱十七 L19："…只收说得清出处的。"
- 半佛 L31："…讲不清打哪来的，给再便宜也不碰。"

两个本应差异明显的 IP，产出撞上"来路讲不清 = 不收/不碰"这同一句骨架，且互动结尾（打开闲鱼→搜→打在评论区）几乎逐句同构。**跨 IP 的模板复用，比任何单条句式都更能暴露"这是同一个 AI 生成的"**——这正是本项目"AI 味"的根源，也应是检测器的头号指标（见 5.1 第 20 项）。

## 5. 落地建议（三档）

### ① 可立刻做成程序检查器的指标（给阈值 + 计算方法）

以"句"为单位（按 。！？ 分句），建议先在语料上校准，下列为口播稿初始阈值：

| 指标 | 计算方法 | 建议阈值 | 命中动作 |
|------|----------|----------|----------|
| 句长标准差下限 | 全篇各句字符数的标准差 σ | σ < 8 字 → 过整齐 | 警告：节奏机械 |
| 平均句长上限 | 总字符/句数 | > 40 字/句 → 过密 | 警告：过度压缩(#16) |
| "的"字结尾句占比 | 以"的。/的？/的！"结尾句数 / 总句数 | > 15% | 警告：悬空"的"(#2) |
| 反问句占比 | 以"？"结尾句数 / 总句数 | > 20% 或**连续 ≥3 句反问** | 警告(#4) |
| 冒号金句壳 | "短语：短语"结论式冒号数 | 每篇 > 2 | 警告(#6) |
| 破折号 | "——"计数 | 每篇 > 2 | 警告(#7) |
| 否定对照 | 正则 `不是.{0,20}(而)?是` / `不仅.{0,20}(更\|还)` | 每篇 > 1 | 警告(#9/#10) |
| 总结壳词 | 词表 {说白了,说穿了,本质是,核心是,这就是,归根结底} | 命中 > 1 / 每段命中 | 警告(#11) |
| AI 高频词 | 黑名单（赋能/助力/打造/闭环/值得注意的是/不难发现/至关重要/深入探讨…，取 S3 词表） | 命中 > 0 | 硬拦(#17) |
| 机械连接词 | 句首 {首先,其次,最后,然而,此外,因此} 命中率 | > 15% 句 | 警告(#18) |
| 四字格连用 | 相邻四字短语连用 | ≥3 连 | 警告(#15) |
| 段落句数均齐度 | 各段句数的方差 | 方差≈0（段段等长） | 警告(#12 篇章版) |
| **跨稿模板指纹** | 对同批/跨 IP 稿做结尾 CTA 与"规矩句"骨架的 n-gram/编辑距离比对 | 相似度 > 阈值 | **高优先警告（最强 AI 味信号）** |

实现提示：本项目已有 `validate-generated-copy.mjs` / `validate-generation-inputs.mjs` 与 S5 的 `style_audit.js` 思路，可把上表并入现有校验脚本；多数为正则/统计，成本低。

### ② 应写进生成规则 / DNA 负面清单的条目

- 禁 AI 高频词表（#17）与总结壳口头禅硬贴帽子（#11）。
- 禁"不是 X 而是 Y / 不仅 X 更 Y"作为默认造句模具（#9/#10），每篇至多 1 次。
- 悬念标题党 setup 每篇限 1 次，禁一稿内重复（#19）。
- **互动结尾与"核心规矩句"必须每个 IP 一套、禁跨稿复用同一骨架**（对应 4.3 铁证）。
- 强制注入具体细节：每篇至少 2 处可感数字/场景/人物（#14），把"很多人"换成具体一例。
- 口语赘词按 IP 人格档位注入（#13），而非一律加"其实/然后"。
- 冒号金句、连续反问设"预算上限"，写进 DNA 的"标点预算/句式节奏"（借鉴 S5）。

### ③ 只能靠人 / LLM 评审的

- 终极判据（S4）："改完能不能感到是一个具体的人在说话？" 能，才过。
- 金句是否**空洞**（对仗工整但无新信息）——#5/#22 须人判。
- 抽象 vs 具体（#14）：例子是否真具体、可核。
- 语气是否贴合该 IP 人格、有无"端着"。
- 逻辑跳跃 / 因果强弱 / 事实是否被压缩到失真（#16）。
- 翻译腔的"英文骨架感"（#21）——需读感判断，正则只能近似。

## 6. "去 AI 味"与"保留 IP 风格"的冲突（不能一刀切之处）

核心原则（来自 S2/S6）：**个人/口语 IP 文要保留作者风格，说明文才求中性；单次出现无罪，重复/空洞/跨稿雷同才是 AI 味。** 据此：

| 特征 | 一刀切风险 | 建议做法 |
|------|-----------|----------|
| 短句 + 句长方差（#12） | 钱十七本就爱短句、半佛爱短句成行，硬拉高 σ 会毁掉两者节奏 | σ 下限**按 IP DNA 分别标定**；对短句型 IP 放宽，但仍查"是否每句都等长"的机械感 |
| 编号/列举（#3 rule-of-three） | 钱十七"第一条规矩""下一条只讲…"是其人格标志 | 豁免其编号体；只拦**为凑三点而机械对齐**的空列举 |
| 反问句（#4） | 半佛本就靠反问推进 | 允许反问，但拦"连续 ≥3 句机械轰炸"（如半佛稿 6 连问）；改成陈述+反问交替 |
| 金句收尾（#5） | 半佛的"辛苦钱不是聪明钱"式收尾是其识别度来源 | 允许金句，但用③人工查**是否空洞**；禁每节都甩、禁对仗过密到读不出口 |
| 口语赘词注入（#13） vs 口播求精炼 | 无脑加"其实/然后"会让稿子啰嗦，反伤口播 | 按人格档位控量：钱十七偏干脆、少赘词；半佛可略多插入语。不是越啰嗦越自然 |

**结论**：本项目的 AI 味主要不在"用了短句/反问/金句"（那是 IP 风格），而在**模板化与跨 IP 撞骨架**（见 4.3）。检测与规则的重心应放在"是否复用同一句式模具、是否空洞对仗、是否两个 IP 产出同构"，而非机械封杀短句、反问、编号这些本就属于 IP 人格的手法。
