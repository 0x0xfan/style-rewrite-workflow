# 钱十七口播风格 DNA（重构版）

> 当前用途：用户已确认合格的钱十七仿写基准，也是项目唯一内容主版本。机器审计仍由同目录 `style-dna.draft.json` 承担；JSON 的 `draft/review_only` 表示正式证据审批尚未完成，不否定本文件已被用户选为实际写作基准。
>
> 重构目标：去除过拟合控制，恢复项目拆解主干的优先级。

## 核心模型（一句话）

快速摆出具体项目或结果，把学会后的生活、能力、执行效率或收益画面提前给观众看，再用数据和编号路径把方法讲清楚。

## 适用边界

- 适合副业、闲鱼、电商、轻资产项目、工具清单、实操教程和资料承接型口播。
- 目标内容必须提供自己的项目、步骤、数据、案例、证据、风险和 CTA；风格文件只决定怎么说。
- 医疗、金融、法律、资质教育等高风险主题，或没有证据却要求强收益承诺的内容，不直接套用。

## 一、必须稳定的主干（A层）

### A1. 具体项目或结果直接开场

**执行标准：**
- 第1-2句就让观众知道在讲什么项目、产品、问题或结果
- 有可靠数字时使用一组最强数据，不把所有数据堆在开头
- 不用"我拆了一遍、我先发现、我继续往下看"拖慢主题

**样本证据：**
- "闲鱼上有个手机数据恢复的产品，标价只有0.2元，却有2万人想要、6万浏览"
- "小红书上有个做线下探店的博主，3个月涨了8万粉"

**反例：**
- "我最近研究了一个项目，发现了一些有意思的东西..."
- "今天给大家拆解一个案例..."

---

### A2. 用场景化结果预演包装内容价值

**执行标准：**
- 开头和主要章节前，先展示学会后的一个具体变化，再进入方法
- 变化维度可以是生活消费升级、新手能力升级、当天可完成的动作、节省时间、减少重复劳动，或证据支持的收益变化
- 长稿通常覆盖开头和3-5个主要章节，每次换一种维度；小步骤直接讲
- 时间、出单、收入、百分比和倍数必须来自目标内容证据；缺证据时改成可执行动作或定性场景
- 学习表达关系，不复制来源里的饭店、金额、学员结果和具体数字

**抽象公式：**
- 普通结果 → 熟悉的生活场景升级 → 进入方法
- 新手当前状态 → 学会后的可执行状态 → 给成功路径
- 普通步骤 → 省下的时间或重复动作 → 进入方法
- 已有结果证据 → 观众能感知的变化画面 → 进入动作

**与段落承接的区别：**
- 场景型价值预演回答“学会以后会发生什么”，负责包装和留存
- 段落承接回答“当前做到哪里，下一环节还解决什么”，只负责必要过渡

---

### A3. 先报路径，再编号拆解

**执行标准：**
- 用一句话告诉观众本期会拆哪几个环节
- 随后按项目真实路径推进，不为了形式硬凑步骤
- 编号推进时，保持"第一/第二/第三"或"先/再/接着/最后"的清晰节奏

**样本证据：**
- "顺着这条线，咱们从头拆一遍"
- "具体分三步：选品、上架、交付"

---

### A4. 每段只讲一个环节

**基本结构：**
点名当前环节 → 一个关键判断或理由 → 具体动作 → 必要时补数据或结果

**执行标准：**
- 不用“很多人错了—真正关键—新标准”反复替观众下结论
- 全篇最多保留1-2次真正有价值的纠偏
- 一个环节讲完再进入下一个，不在同一段里混讲选品方法论+账号设置+内容准备

**样本证据：**
选品段落应该是：
- 为什么这个产品有人买
- 场景或数据支撑
- （可选）选品判断标准

而不是：
- 为什么有人买 + 选品三标准 + 合规提醒 + 账号准备

---

### A5. 数据贴着它要证明的内容出现

**执行标准：**
- 开头数据证明项目值得看
- 店铺或过程数据放在对应步骤
- 单笔账和累计结果放在收益段
- 口播直接讲事实，不念"截图显示、计算器显示、更新时间"

**样本证据：**
- "这个店铺一天曝光89673、浏览6897、出了269单"（放在店铺经营成果段）
- "我光网盘拉新的累计收入就做到了6143.54元"（放在收益机制段）

---

### A6. 收益关系直接算清

**执行标准：**
- 先解释交付或收益为什么成立，再把单笔账、条件项和累计结果讲清
- 不把案例结果变成人人都能做到的保证
- 不强制把结尾升维成商业模型

**样本证据：**
- "这个产品一单是19.9元。客户把资料保存到自己的网盘，7块钱的拉新收益就到账了，这一单实际到手26.9元"

---

### A7. 用目标内容自己的资源和身份收尾

**执行标准：**
- CTA、口令、渠道、资源和签名全部读取目标输入
- CTA前只需一句自然项目总结，不强制"你真正要学的是背后的方法"

**样本证据：**
- "我把这套流程用到的6份资源整理好了：...需要的话，评论666"
- "我是研究虚拟资料的圣矾"

---

## 二、按需使用的辅助层（B层）

### B1. 项目依赖承接（辅助规则）

**使用条件：**
只有上一环节与下一环节存在真实依赖时才使用，长稿通常1-2次，不覆盖每个小步骤

**结构：**
上一环节或当前状态 → 下一环节还缺什么、为什么重要或不做会怎样 → 进入方法

**执行标准：**
- 每次承接使用不同的真实关系，例如信任、重复交付、效率或收益
- 不能只写"接下来、第二、第三"
- 也不能反复写"最关键、一定要看"
- 不能新增平台机制、确定收益、用户心理或虚构后果

**样本证据：**
- "产品有人要了，账号和店铺解决的就是这一层：用户点进主页以后，能不能一眼看懂你卖什么、怎么交付"
- "商品能卖、资料也能发了。但这条网盘链接的价值还没算完"

**注意：**
它只负责连接项目步骤，不能替代A2的场景价值预演。V9测试稿把承接当成包装，结果每段都像课程过渡。

---

### B2. 局部认知差（低权重）

**使用条件：**
当目标内容确实有"表面一层"和"第二层机制"时，可以使用一次

**结构：**
常见理解 → 被忽略的一层 → 具体证据或方法

**执行标准：**
- 不能把它变成全文主结构
- 全篇最多1次

---

### B3. 人群代入（可选）

**使用条件：**
目标内容明确受众和门槛时，可以用一句说明谁适合继续听

**执行标准：**
没有明确受众时删除

---

### B4. 局部事实边界（可选）

**使用条件：**
只有数据或执行条件容易被误读时才使用

**结构：**
用一句短事实边界直接收口，例如“想要不等于订单”；随后进入具体动作或证据

**执行标准：**
- 默认不用修辞式“不是X，而是Y”
- 不接“本质上、真正关键、核心逻辑”等工整结论
- 全篇最多1-2次必要边界

---

### B5. 数据价值翻译

**执行标准：**
每组数据最多解释一层直接意义，不能从相关性推成因果或结果保证

---

### B6. 必要风险（压缩进对应步骤）

**执行标准：**
版权、隐私、违法、资金损失或会让步骤失效的红线，压进对应动作的一句话里

**执行标准：**
详细审计留在稿外，口播只保留会改变项目能否执行的红线

---

## 三、明确删除的过拟合控制（C层）

### C1. 删除"研究者/拆解者必须先讲自己的过程"

**删除原因：**
它让开头变成"我做了什么"，反而晚于项目和结果；"我把项目拆了一遍，先发现……"已经被用户明确否定

---

### C2. 删除"完整认知旅程贯穿全文"

**删除原因：**
原样本只支持局部纠偏，不足以证明每篇都按"旧理解—新标准—升维"推进；强行使用会让每段同壳

---

### C3. 删除"表面值—疑问—真实值"作为钱十七稳定DNA

**删除原因：**
0.2→19.9是本篇目标内容的有效揭晓关系，应保留在本篇content contract，而不是上升成钱十七所有稿件的固定风格

---

### C4. 删除"每段错误关注点—真正关键—新标准—动作"

**删除原因：**
同一测试稿连续使用后AI味加重，压过项目解释

同时删除修辞式“不是X，而是Y”作为常用推进句。必要的数据边界直接短说，让场景和动作承担对比。

---

### C5. 删除"没有人物位置就是说明书"

**删除原因：**
钱十七可以直接讲项目；说明书感来自缺少判断、收益和口语推进，不等于必须增加第一人称研究过程

---

## 四、重构后的生成权重配置

### 主干优先级（A层）：95%
- A1-A7是钱十七风格的根基；A2的场景化结果预演负责持续包装，不能只在开头出现一次

### 辅助层使用频次限制（B层）：
- A2场景化结果预演：长稿开头+3-5个主要章节，短稿开头+1-2个主要章节；每次换一种结果维度
- B1项目依赖承接：长稿1-2次，短稿0-1次
- B2认知差：全篇最多1次
- B3人群代入：有明确受众时1次
- B4局部事实边界：全篇最多1-2次，不使用“不是X，而是Y”句壳
- B5数据翻译：每组数据1层
- B6风险提醒：压缩进对应步骤，不单独成段

### 删除层（C层）：权重0%
- 遇到C层控制时，主动跳过或替换为A层控制

## 五、典型段落结构示例

### 开头段（A1+A2）
```
闲鱼上有个手机数据恢复的产品，标价只有0.2元，却有2万人想要、6万浏览。

实际问下来是19.9元。成交以后，客户把资料保存到自己的网盘，你还能多拿一份拉新收益，一单再叠7块钱。

顺着这条线，咱们从头拆一遍。
```

### 路径拆解段（A3+A4）
```
先看为什么这个产品有人买。

手机数据恢复平时不一定有人找，可一旦误删资料、换了手机，或者重要记录找不到了，用户就会马上想办法解决。几十块钱能买到一套方法，决策成本也不高。
```

### 场景价值预演段（A2，主要章节前使用）
```
同样一天处理五个客户，有人每次重新解释一遍，有人把咨询、检查和交付做成固定清单，照着走就能省下大量重复沟通。

接下来把这套交付清单怎么搭讲清楚。
```

### 项目依赖承接段（B1，确有依赖时使用）
```
产品有人要了，账号和店铺解决的就是这一层：用户点进主页以后，能不能一眼看懂你卖什么、怎么交付。

下载闲鱼、完成注册，再把昵称、头像、简介和其他资料补完整。
```

### 收益段（A6）
```
这个产品一单是19.9元。客户把资料保存到自己的网盘，7块钱的拉新收益就到账了，这一单实际到手26.9元。

如果客户再通过这条链接开通会员，还有30%的会员分成。我光网盘拉新的累计收入就做到了6143.54元。
```

## 六、生成检查清单

生成完成后，按以下标准自查：

### 主干检查
- [ ] 开头2句内出现具体项目/产品/结果
- [ ] 开头有最强数据或市场信号
- [ ] 开头和主要章节前有不同维度的场景价值预演
- [ ] 场景只使用目标内容能够支持的生活、能力、动作、效率或收益变化
- [ ] 有明确的路径预告句
- [ ] 每段只讲一个环节
- [ ] 数据出现在它要证明的内容旁边
- [ ] 收益关系直接计算，有条件说明
- [ ] 用目标内容自己的CTA和签名收尾

### 辅助层频次检查
- [ ] 项目依赖承接：≤2次
- [ ] 认知差结构：≤1次
- [ ] 必要事实边界：≤2次
- [ ] 没有修辞式“不是X，而是Y”
- [ ] 没有"我拆了一遍、我发现"开头
- [ ] 没有每段都用"很多人以为...其实...真正关键"
- [ ] 没有“本质上、核心逻辑、你会发现、这说明了一件事”等工整总结壳

### 说教感自查
- [ ] 是否有过多"接下来还有一个问题"
- [ ] 是否有"最容易掉进去的坑"
- [ ] 是否有"你就盯住三个标准"
- [ ] 是否有"一定要、必须、千万"

如果以上任何一项超标，优先删减B层控制，保留A层主干。

## 七、与V9版本的核心差异

| 维度 | V9版本 | 重构版 |
|---|---|---|
| 核心定位 | 研究者/认知升级型IP | 项目拆解型内容 |
| 开头 | 可能先讲研究过程 | 直接讲项目和数据 |
| 内容包装 | 依赖问题型承接 | 主要章节前做生活/能力/动作/效率/收益场景预演 |
| 项目承接 | 几乎每段都承接 | 只在真实依赖边界1-2次 |
| 纠偏结构 | 多段使用 | 全篇最多1-2次 |
| 转折句式 | 反复“不是X，而是Y” | 具体人物、动作和结果自己形成对比 |
| 说教感来源 | B层控制权重过高 | A层主干优先，B层严格限频 |
| 生成效果 | "你应该怎么做" | "这个案例是怎么做的" |

## 八、来源事实、证据与 CTA 边界

### 不能从钱十七样本迁移的内容

- 收入、利润、订单、销量、出单速度、学员结果和累计收益。
- 具体项目教程、平台操作、货源渠道、资源包数量和交付工具。
- 公众号、关键词、身份、签名、案例主体和截图归属。
- 平台安全、合规、账号权重或收益确定性判断。

### 生成时必须保持的关系

- 数字、单位、主体、时间范围、条件和证据归属原样保持。
- 数据贴着它要证明的内容出现；想要数、浏览量、店铺数据和订单不能混成同一主体。
- 素材只证明目标内容已经锁定的事实，受众口播不念“截图显示、计算器显示、根据你提供的”等后台审计过程。
- CTA、领取渠道、关键词、资源名称和作者身份全部读取目标输入；没有就留占位，不从样本补。

### 风险处理

- 收益、当天出单、百分比、倍数、时间节省和生活消费参照都需要目标内容证据。
- 版权、隐私、违法、资金损失或会让步骤失效的红线，压进对应动作的一句话；详细审计放在稿外。
